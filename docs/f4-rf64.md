# F4：WAV RF64 / BW64

日期：2026-10-18。任务卡：[tasks/F4.md](../tasks/F4.md)。本卡的结果来自自有解码器测试、模拟宿主、fuzz、Kani 与 QEMU，**不是实机结果**。

## 1. 做了什么

`qy-codec-wav` 读取 RF64（EBU Tech 3306）与 BW64（ITU-R BS.2088）文件：结构与 RIFF/WAVE 相同，长度由紧接 `WAVE` 的 `ds64` 块给出，data 可以超过 4 GiB。fmt、样本编码（整数、8 位、EXTENSIBLE、浮点）、声道布局与 W1 容错规则都与普通 WAV 相同，严格路径不改变样本。

| 情形 | 处理 |
| --- | --- |
| 文件头 `RF64` / `BW64` | 32 位 RIFF 长度字段按规范为 0xFFFFFFFF（不使用），不读取 |
| 第一个块不是 `ds64`、`ds64` 不足 28 字节、表越出 `ds64`、重复的 `ds64`、`ds64` 的 RIFF 长度容纳不下 `ds64` 本身 | 不合规，明细 `WavDetail::Ds64(…)` 写明 |
| data 的 32 位长度为 0xFFFFFFFF | 用 `ds64.dataSize`（64 位） |
| data 的 32 位长度不是 0xFFFFFFFF | 必须等于 `ds64.dataSize`，否则两处声明矛盾，不合规 |
| 其他块的长度为 0xFFFFFFFF | 按块标识取 `ds64` 表中第一个未用过的同名表项；没有时不合规 |
| `ds64` 表超过 8 项且后面需要查第 9 项以后 | `CapacityExceeded`，明细写明表项数与容量（真实写入程序的表为空） |
| 浮点文件的 `fact` 为 0xFFFFFFFF | 帧数取 `ds64.sampleCount`，再按 F3 与 data 核对 |
| `ds64` 全零、data 为 0xFFFFFFFF（ffmpeg 输出到管道） | 同 W1 R1 + R2：读到源末尾，报告两条修正（`RF64` 与 `data` 的占位值 0） |
| `ds64` 的 RIFF 长度与文件不符而 data 完整 | 同 W1 R3，以 data 为准并报告 |
| 不足一帧的尾部 / 源比声明短 | 同 W1 R4 / R5；R5 的明细如实给出 64 位声明长度 |
| BW64 的 `axml`、`chna`（ADM 元数据）、`JUNK` | 与未知块一样跳过；声道布局只按 fmt（F1） |
| 普通 RIFF 中的 `ds64` 块 | 按未知块跳过 |

接口变化：

- `qy_core::engine::Repair` 的 `declared` 由 `u32` 改为 `u64`（64 位声明长度也能如实报告）；`WavDetail::DataShort` 与 `WavDetail::Fact` 的 `declared` 同样改为 `u64`；
- 新增 `WavDetail::Ds64(Ds64Problem)` 与常量 `qy_codec_wav::DS64_TABLE`（8）；
- 文件筛选（Windows 与 Linux 图形界面、`qy-ui` 文件信息读取）增加 `rf64`、`bw64` 扩展名（多数文件仍为 `.wav`）。

## 2. 规范出处与核对

- EBU Tech 3306 v1.1 与 ITU-R BS.2088-1 的原文在本环境中无法下载（`tech.ebu.ch`、`itu.int` 被网络策略拒绝），**尚未逐条核对**，需要用户提供 PDF。
- 在此之前，结构按两份开源实现交叉核对（只读，不复制代码；校验值见 [specs.md](specs.md)）：
  - FFmpeg n7.1 `wavdec.c`：`ds64` 固定部分依次为 riffSize、dataSize、sampleCount（各 64 位）；RF64 / BW64 的 data 长度取 `ds64`；
  - libsndfile 1.2.2 `rf64.c`：之后为 32 位表长度与表项（块标识 + 64 位长度）；RIFF 长度字段应为 0xFFFFFFFF。
- 真实写入程序：ffmpeg 6.1 `-rf64 always` 的输出（2026-10-18 核对）：
  - 写到文件：`ds64` 28 字节、表为空，三个长度已回填（sampleCount 为帧数），data 为 0xFFFFFFFF，data 之前有 `LIST`；浮点文件的 `fact` 为 0xFFFFFFFF；
  - 写到管道：`ds64` 的三个长度都是 0，RIFF 与 data 为 0xFFFFFFFF。
  两种输出都作为夹具（`rf64_ffmpeg_seekable`、`rf64_ffmpeg_pipe`）。

## 4. 已知限制

- 规范原文未逐条核对（见 §2）。
- `ds64` 表最多存 8 项；真实写入程序的表为空，只有超过 4 GiB 的非 data 块才需要表项。
- 嵌入式宿主经 FAT 读文件：FAT32 单个文件不超过 4 GiB，嵌入式上的 RF64 只能是小于 4 GiB 的文件（结构照常解析）。
- ADM 元数据（`axml`、`chna`）不解释；对象音频不渲染。多于 2 声道而没有 EXTENSIBLE 声道掩码的 BW64 按“布局未定义”拒绝（F1）。
- 只读，不写 RF64。
- 真实设备上未运行。
