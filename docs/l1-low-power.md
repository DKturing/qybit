# L1 低功耗宿主：完成记录

任务卡：[tasks/L1.md](../tasks/L1.md)。提交：`a48bd72`（L1-A 桌面生产端）、`007f846`（L1-B 界面）、`ec65ad3`（L1-C MCU），以及本文所在的 L1-D 提交。

**结论**：宿主只在有事可做时醒来。核心接口没有改动（`Wait::QueueFull`、`Wait::Device`、`Step::Idle` 原本就有），改的是宿主怎样等待。

- 桌面生产端：
  - 暂停时每秒醒来约 1 次（安全网），原先约 500 次；
  - 空闲时生产端不运行；
  - 播放时醒来次数由状态快照间隔与队列半满决定；
- 命令响应在毫秒以下到几毫秒；
- 按真实时间消费的假设备上无欠载。

数值见 §5，只对测量的机器成立。

## 1. 桌面生产端（L1-A）

| 等待 | 原先 | 现在 |
| --- | --- | --- |
| 队列满 | 每 2 ms `sleep` 后再看 | 登记 `space_wanted` 后 `park`；渲染线程取数使队列降到阈值以下时 `unpark`，每次等待至多一次 |
| 排空（等渲染线程播完） | 每 2 ms `sleep` | `park`；渲染循环结束时（含 panic 展开，`EndGuard`）先置 `ended` 再 `unpark` |
| 控制命令 | 每轮 `try_recv` | `command_channel()`：`CommandSender::send` 发出后 `unpark` 已登记的生产端；`qy-ui` 与测试改用它 |
| 状态快照 | 每轮检查 | 播放中（未暂停）且有回调时按快照间隔（100 ms）醒来 |
| 暂停 | 同队列满，约每 2 ms | 只等命令；安全网 1 s |
| 停止标志（CLI 的 Ctrl+C） | 每轮检查 | 每 100 ms 查看：标志由信号处理置位，不能安全地从那里唤醒 |
| 空闲（无会话） | `qy-ui` 播放线程阻塞在请求通道 | 不变 |

- **唤醒阈值**（§6 决定 1）：取队列容量的一半，填满后再等。
  - 桌面队列是整块 3 072 000 字节：44.1 kHz / 16 位双声道约 17 s，192 kHz / 32 位双声道约 2 s。所以半满唤醒在 CD 采样率下约 8.7 s 一次；
  - 实测（§5）没有欠载、最低水位远高于预填，因此不再调低。
- **无丢失唤醒**：
  - `unpark` 先于 `park` 时，下一次 `park` 立即返回（标准库语义）；
  - 生产端先登记再休眠，渲染线程在两者之间取数时，它的 `unpark` 让这次休眠立即返回；
  - 渲染线程在生产端检查之前已结束时，`ended` 已置位，生产端不再等待；
  - `park` 本身可能虚假返回，循环照常处理。
- **实时路径**：渲染线程只多两次原子读（未登记等待时），唤醒时多一次 `unpark`。它不阻塞、不分配，每次等待至多一次。

## 2. 界面（L1-B）

- **通知合并**：GUI T2 起已有。后台线程投递 `WM_QY_NOTIFY` 前查“未处理”标志，窗口处理时清除并一次取完全部事件。本卡核对后不改；任务卡 §1 的描述有误。
- **最小化时不重绘**：
  - `qy_ui::Deferred` 在窗口不可见时暂存显示变化，恢复时一次重绘；模型、日志与结束报告照常更新；
  - `qybit-gui` 每次处理输入时按 `IsIconic` 同步可见性。即使漏掉 `WM_SIZE`，也不会停在不可见状态；
  - 被其他窗口遮挡没有检测（需要 DWM 遮挡通知），只处理最小化。

## 3. MCU（L1-C）

- **串口接收**：
  - 板级示例改为 RXNE 中断：中断里只把字节放入有界的 `RxQueue<64>`，满时丢弃并计数；
  - 主循环在临界区内一次取出，再在临界区外解析。
- **休眠**：`Step::Idle` 且接收队列为空时执行 WFI。
  - 判断与 WFI 在同一临界区：屏蔽中断时，挂起的中断仍会唤醒 WFI，所以不会漏掉判断之后到达的中断；
  - 唤醒源是 DMA 传输完成中断与串口接收中断。
- **统计**：用 DWT 周期计数器。
  - `stats` 回应活跃比例、`step` 次数与单次最长耗时、休眠次数、DMA 截止余量（复用 R1 水位：中断取数前队列中的最少帧数）与欠载次数；
  - 板级另报接收丢弃与错误次数；
  - 活跃比例只统计播放与暂停期间：此时 DMA 每个缓冲都会唤醒，单次休眠远短于计数器回绕周期（96 MHz 下约 44 s）。停止时的休眠只计次数。
- **`unsafe`**：新增 USART2 中断的 `NVIC::unmask`，与 DMA 中断放在同一处，审计说明见板级模块文档。

## 4. 正确性

| 测试 | 证明 |
| --- | --- |
| `qy-player` `commands_wake_parked_producer` | 暂停 1 s 内生产端只醒来 ≤ 3 次；恢复与暂停中停止都在 300 ms 内生效（只靠安全网时约 1 s，测试会失败） |
| `qy-player` `render_end_wakes_parked_producer` | 排空完成与设备出错（生产端正在等空间）后立即返回；0.5 s 队列（768 kHz / 32 位）下 2 s 播放无欠载，醒来 < 40 次 |
| `qy-player` `command_sender_wakes_registered_producer`、`render::tests::producer_is_woken_once_per_wait_and_at_end` | 不计时：生产端用不带超时的 `park`，漏掉唤醒即永久阻塞；后者含渲染循环 panic 展开时的唤醒 |
| `qy-ui` `hidden_window_defers_redraw_without_losing_events` | 最小化期间整个会话不重绘，恢复时状态、日志与会话一次重绘 |
| `qy-host-embedded` `idle_main_loop_sleeps_until_interrupt` | 按板级模型的主循环（休眠到下一个中断）：两次播放逐字节一致、无欠载；暂停中每次 DMA 中断只唤醒一次；停止后到下一条串口命令之间不调用 `step` |

另外核对过：分别去掉三条唤醒路径（命令、渲染结束、队列降到阈值）时，前两个测试中至少一个失败。

现有播放器、界面、嵌入式（含 500 个模型种子）与 QEMU 演示测试全部通过。
