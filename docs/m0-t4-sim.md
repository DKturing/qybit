# M0 T4：真实路径模拟记录

实现：`crates/qy-core/src/lib.rs`（播放状态机）、`crates/qy-host-sim/src/sim.rs`（模拟宿主）、`crates/qy-host-sim/tests/sim_seeds.rs`（1000 种子）。

## 冻结接口

T4 验收后，`qy_core::Action`、`qy_core::Event`、`qy_core::Decoder`（连同其返回的 `Status` / `Progress` / `DecodeError`）为稳定接口，破坏性变更须先征得用户同意。

| Action | 宿主应做的事 | 回报 Event |
| --- | --- | --- |
| `Open { generation, track }` | 打开音源 | `Opened` / `OpenFailed` |
| `Read { generation, request, max }` | 读取 ≤ max 字节，写入 `read_target(generation, request)` | `ReadDone { len }`（len 可为 0，不表示 EOF）/ `ReadEof` / `ReadFailed` |
| `Configure { generation, format }` | 按源格式配置输出；若当前是其他格式，先排空旧格式 | `Configured` / `ConfigureFailed` |
| `Output { generation, frames }` | 用 `pcm()` 取 `Pcm<Exact>`，pack 入队至多 frames 帧 | `Output { frames: 实际取走 }`（队列满时为 0） |
| `Close { generation }` | 关闭音源 | — |
| `Finished { generation }` | 排空队列与设备中剩余音频 | — |
| `Failed { generation, track, fault }` | 播放列表停止；已入队的有效音频可以排空 | — |

- 每首曲目打开时、以及 `stop()` 时，代次递增。读请求 ID 全局递增。
- 旧代次或非当前请求的回报返回 `CoreError::Stale`，不改变状态；对这类请求 `read_target` 返回 `None`，宿主不会写入。
- 回报与当前状态不符（读取长度超出请求、取走帧数超出可用、状态错位）返回 `CoreError::Protocol`。
- 相邻两首曲目的源格式相同时不再发 `Configure`，PCM 无缝衔接。`stop()` 后已配置的输出视为失效。
- `Fault` 共五种：`Open`、`Read`、`Decode(DecodeError)`、`Configure`、`InputWindow`。

## 模拟宿主规则

数据路径全部是真实组件：`Core<WavDecoder>`、8192 字节输入窗口、4096×2 PCM 工作区、`FrameProducer::pack_push`、rtrb 队列（768000 字节）。这些缓冲在 `SimHost::new` 中分配一次，1000 个场景复用同一套。

只模拟三样东西：

- **文件**：内存字节。读取长度随机：5% 返回 0 字节，10% 返回 1–16 字节，其余在 1–max 之间均匀取值。慢读延迟 1–2 tick。读错误、打开失败由场景决定。
- **时间**：1 tick = 1 ms。生产端可被注入停顿窗口；不停顿时，每 tick 一直 poll，直到核心等待回报或队列满。
- **设备**：每 10 ms 一个周期，`packet = rate / 100` 帧。
  - **WASAPI 整包**：每周期请求并消费一整包；不足的部分补静音。若该格式已确认不再有数据（播放完成、换格式、失败），补的静音计为尾部填充；否则计为欠载，记录 tick、设备帧位置和缺失帧数。启动时立即处理第一包，模拟初始端点缓冲。
  - **短写**：每周期消费 0–2 包之间随机的帧数，允许部分消费，不补零；数据不足时只记录欠载。

宿主策略：

- **预填**：设备启动前至少预填当前采样率下 500 ms（`prefill_frames`）。播放列表已结束或失败时直接启动设备，把已有数据播完。
- **换格式**：排空旧格式，等设备播完最后一包有效音频，然后用新代次重配置队列，开一个新段，重新预填。
- **失败**：把已入队的有效音频排空后停止。
- **设备断开**：立即 `stop()` 核心。
- **重启**：`stop()`，停设备并清空队列，然后 `play(from, n)`。重启注入会等到当前代次有在途读取时才触发，最多顺延 1000 tick。
- **格式选择**：在设备支持列表中取 V ≥ N 的最小 V，同 V 时按设备偏好顺序；采样率和声道照搬源格式，不改样本。

## 场景与通过标准（种子 0–999，类型 = 种子 % 10）

曲目由测试内独立的 WAV 写入器生成，样本已知：

- 曲目内容：前导静音 0–50 ms；最后一帧满幅；随机插入 JUNK chunk 和奇数长度的 LIST chunk；约 5% 是空曲目。
- 格式：采样率 44.1/48/88.2/96/176.4/192 kHz，单/双声道；位深 PCM 16/24/32 或 EXTENSIBLE 20/24、12/16、24/32。
- 每个场景 1–4 首曲目，偏向同格式相邻，以覆盖无缝衔接。

期望设备字节由独立公式 `s << (C − N)`（小端）计算，按设备格式把相邻曲目分段，并与实际播放的有效字节逐字节比较。

| 类型 | 场景 | 通过标准 |
| --- | --- | --- |
| 0–5 正常 | 短读、零长度读、3% 慢读（≤ 2 tick）；生产端停顿最多 3 次，每次 ≤ 300 ms，间隔 ≥ 1000 ms；预填 500 ms；75% 用 WASAPI，25% 用短写 | 逐字节匹配全部曲目；无欠载；完成；标记完整保真；WASAPI 每段尾部填充 < 1 包；短写后端尾部填充为 0 |
| 6 超预算停顿 | 192 kHz C32 双声道（队列恰为 500 ms），2 首各 ≥ 0.5 s；设备启动后（20–100 ms）停顿 1000 ms | 必须报告欠载，每次缺失帧 > 0；不得标记完整保真；有效音频仍逐字节完整（无丢帧、无重复）；播放恢复并完成 |
| 7 输入故障 | 按种子轮换：打开失败、读取错误（随机偏移）、截断（若干完整帧加半帧）、非法 blockAlign | 故障曲目与类型正确；之前的曲目完整排空；截断时输出全部完整帧；读取错误时输出是期望的前缀 |
| 8 输出故障 | 轮换：设备不支持 32 位有效位（`Configure` 失败）、播放中设备断开 | 配置失败时之前曲目逐字节完整；断开时输出是期望的前缀，不得标记完整保真 |
| 9 停止重启 | 全部读取为慢读，在前 1/3 时长内重启，从随机曲目重播（≤ 96 kHz） | 重启前输出是前缀；重启后从该曲目起逐字节完整；在途旧读取全部被拒绝；无欠载；完成 |

另外，所有场景都要求：不超时（上限 = 3 × 时长 + 停顿 + 5 s），协议错误为 0，pack/队列错误为 0。

## 结果（Linux debug，约 27 s）

```
模拟种子 1000：各类型 [100 × 10]，欠载事件 5016，拒绝旧回报 62，实际重启 62，
设备断开 45，故障 {Configure: 50, Decode(Malformed): 25, Decode(Truncated): 25, Open: 25, Read: 25}，
读错误前已有输出 22
```

- 1000 个种子全部通过。wine 下的 Windows GNU 目标也全部通过（这是补充验证，不是原生 Windows）。
- 100 个重启场景中有 62 个实际发生重启。其余 38 个在重启点之前已读完全部数据，不再有在途读取，所以等价于正常场景并按正常标准验证。
- 100 个断开场景（类型 8）中有 45 个实际断开。其余在断开点之前已播放完成，同样按正常标准验证。
- 复现单个种子：`QY_SIM_SEED=<n> cargo test -p qy-host-sim --test sim_seeds -- --nocapture`。失败时会打印种子。

## 变异检查

每项都是临时改动，跑完立即恢复：

| 改动 | 结果 |
| --- | --- |
| 核心同时不检查代次与请求 ID | 23 个种子失败（重启后旧数据污染） |
| 换格式不排空，直接重配置 | 357 个失败 |
| 设备不记录欠载 | 100 个失败（类型 6） |
| 欠载补零计为尾部填充 | 100 个失败 |
| 跳过 500 ms 预填 | 103 个失败（预算内欠载） |
| 排空时丢弃不足一包的尾帧 | 846 个失败 |
| 丢弃段首全零包（前导静音） | 608 个失败 |
| 解码器在最后一帧处出错 | 2 个失败 |

只去掉代次检查时没有失败：请求 ID 是全局唯一的，加上 `read_target` 的检查，旧回报仍会被拒绝。这是有意保留的双重防护。

## 边界

- 这是软件逻辑模拟。设备模型是对 WASAPI 整包契约和短写后端的抽象，不代表真实驱动的时序。
- 不证明 WASAPI 实际行为或 DAC 输入逐位一致；真机验证在 T5/T6。
