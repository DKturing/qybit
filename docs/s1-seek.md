# S1 曲目内定位（seek）

日期：2026-10-15。任务卡：[tasks/S1.md](../tasks/S1.md)（用户 2026-10-15 确认冻结接口变更、样本级精确、FLAC 二分上限 1 秒 / 32 次跳转）。

提交：3bdcd1f（S1-A 核心、引擎、WAV/AIFF 与各宿主）、e5fc17e（S1-B FLAC）、85de53b（S1-C 播放器、界面与嵌入式）、a49c585（S1-D 随机场景、QEMU 与嵌入式待定定位）。

## 1. 行为

- **定位就是从目标帧重新开始这首曲目**：停止设备、丢弃队列（代次加一，旧代次的读取回报、定位回报与 PCM 一律拒绝），重新打开音源、解析文件头，再按解码器给出的字节位置让宿主移动读取位置。之后照常预填、打开或续用设备。
- **样本级精确**：定位后送到设备的第一帧就是目标帧，之后与从头播放到该处逐字节相同。不改变样本，不做淡入淡出。
- **暂停中定位**：保持暂停，恢复后从目标帧播放。
- **目标等于或超过曲目长度**：按播完该曲处理，进入下一首（与自动换曲规则相同）。
- **不可定位的音源**（宿主回报 `SeekFailed`，如管道）：关闭后重新打开，按顺序解码并丢弃到目标帧。结果同样精确，只是更慢。报告写明“曲目 N 的音源不支持定位，已按顺序解码到目标位置（结果相同，只是更慢）”。
- **报告**：“按操作定位 N 次（定位过的曲目没有完整播放）”。与切歌一样，定位过的播放不计为软件路径完整；欠载与错误照常统计。

## 2. 接口（M0 T4 冻结接口的变更，用户已同意）

- `Action::Seek { generation, request, offset }`：宿主把音源读取位置移到距文件开头 `offset` 字节处。
- `Event::SeekDone { generation, request }`、`Event::SeekFailed { generation, request }`。
- `Decoder` 只新增带默认实现的方法，已有实现不受影响：
  - `seek(&mut self, frame) -> Result<u64, SeekError>`：文件头解析后调用，返回字节位置。默认 `Unsupported`，此时核心就地顺序解码并丢弃。`PastEnd` 表示目标等于或超过长度。
  - `seek_request(&mut self) -> Option<u64>`：FLAC 查找时需要再跳一次就给出下一个位置，核心据此再发 `Seek`。任务卡原写 `&self`；取出请求同时清除它，所以改为 `&mut self`。
- 核心：`Core::play_at(first, count, frame)`。目标之前的样本由解码器丢弃（FLAC 在帧内裁剪）或由核心顺序丢弃（不支持定位、或音源不可定位），`pcm()` 交给 pack 的只有目标帧及之后的样本。顺序丢弃有进展的步骤不占 `poll()` 的 8 步上限（否则连续丢弃 8 帧后会返回“无动作”）。
- 引擎（`qy_core::engine`）：`Engine::seek(frame)` = 停止后从目标帧重新开始当前曲目，保留暂停状态。`HostAction::Seek` / `SeekSequential { track }`，`HostEvent::SeekDone` / `SeekFailed`。播放位置从目标帧算起（刚定位、尚无输出时也报告目标帧，不显示 0:00）。
- 播放器：`Command::Seek(frame)`；`TrackSource::Reader` 要求 `Read + Seek`，`seek` 返回错误即视为不可定位。
- 嵌入式：存储接口 `Storage::seek(offset) -> bool`（默认 `false`）；FAT 存储用 `embedded-sdmmc` 的 `file_seek_from_start`，无文件系统的闪存按曲目起点加偏移。

## 3. 各格式

| 格式 | 定位方式 | 出处 |
| --- | --- | --- |
| WAV | data 块起点 + `frame × block_align`，一次精确，不需要丢弃；W1 修正过的结构按修正后的边界计算 | RIFF WAVE（M0 T2） |
| AIFF / AIFF-C | SSND 数据起点（含 `offset` 字段）+ `frame × 每帧字节数`；FORM 剩余字节数的记账同步调整 | AIFF 1.3 / AIFF-C（F2） |
| FLAC | 见下 | RFC 9639 |
| ID3v2 前缀 | `AutoDecoder` 把标签长度加回各解码器给出的偏移 | ID3v2.4.0 §3.1 |

**FLAC**（`qy-codec-flac`，no_std、无 alloc，查找状态只有标量：源偏移、第一帧位置、SEEKTABLE 的位置、第一帧长度与块大小、查找上下界、跳转次数与阶段）：

1. **能否定位**：总样本数已知（RFC 9639 §8.2）或有 SEEKTABLE（§8.5）；并且是可变块策略（帧头即样本号），或固定块且最小块 = 最大块（帧号 × 块大小为样本号，§9.1.5）。固定块、块大小不一的码流不能从帧号换算样本号，返回 `Unsupported`，核心顺序解码。总样本数为 0 且无表时同样顺序解码。
2. **有 SEEKTABLE**：定位时重新读表（不缓存，不占 RAM），取样本号不晚于目标的最大有效点（跳过占位点），跳到“第一帧起点 + 偏移”。表内容不可信：跳过去的帧同样要通过下面的整帧校验，样本号对不上就转为查找。
3. **无表或表不可用、总样本数已知**：按样本号插值估计位置（向前偏两个首帧长度），跳过去后找同步码 `FF F8` / `FF F9`（阻塞位须与 STREAMINFO 一致）。
4. **误同步防护**：同步命中后整帧解码——帧头 CRC-8（§9.1.8）、采样率 / 声道 / 位深与 STREAMINFO 一致、帧尾 CRC-16（§9.3）。任一不过就是音频数据里的同步码样式，继续向后找，不报错。
5. **收敛**：试探到的帧含目标时，直接从帧内目标样本输出；否则更新上下界继续插值。离目标 1 秒以内、范围已窄（不超过 4 个首帧长度）、或跳转满 32 次时，跳回已确认的、目标之前最近的帧顺序解码并丢弃目标之前的样本（任务卡原写“超过上限时退回第一帧”，实现退到已确认的最近帧，结果相同、更快）。试探落在源末尾之后（读不到任何数据）时改取上下界中点。

## 4. 界面

- **GUI**（Windows）：工具栏下方的进度条（trackbar，0–1000）。拖动时只在状态栏预览时间，松开时定位；播放列表中 ←/→ 定位 ±5 秒（不早于曲目开头）。总时长未知（FLAC 总样本数为 0）时进度条不可用。截图见 [gui-t3/12-seek-half.png](gui-t3/12-seek-half.png)（CI 第 103 次运行：10 秒的曲目播放中把进度条设到一半，日志“按操作定位：丢弃已入队的音频，曲目 1 从 0:05，第 220500 帧开始”，2 秒后状态栏 0:07 / 0:10、欠载 0）。
- **真机发现的问题（已修正）**：用户在 Windows 真机上点击进度条后滑块立即回到原位置，没有定位。原因：点击滑轨时 trackbar 先把滑块移动一页，鼠标松开才发 `TB_ENDTRACK`；按住期间播放线程的状态快照照常到达，界面按播放位置重设滑块，松开时读到的是被拉回的当前位置，于是“定位”到原处。CI 截图步骤用 `TBM_SETPOS` 加合成的 `TB_ENDTRACK` 消息，中间没有状态快照，所以没有发现。修正：
  1. 点击、按住与拖动期间（到 `TB_ENDTRACK` 为止）都不按播放状态移动滑块；
  2. 点击滑轨时滑块直接移到点击处（`TBM_GETCHANNELRECT` / `TBM_GETTHUMBRECT` 换算），不再每次只移动一页；
  3. 定位命令发出后、播放线程执行之前的旧状态快照不把进度条与时间拉回：`Status` 新增 `user_seeks`（已执行的定位次数），界面在它赶上已发出的次数之前按目标帧显示位置（连续按 ←/→ 也从上一次的目标累加）。
  CI 新增“13-点击滑轨定位”：用真实鼠标输入点击滑轨约 3/4 处并按住 400 ms，要求日志中定位 1 次、目标在 65%–85% 之间；runner 桌面不接受模拟输入时写明未运行。修正后的真机点击仍需用户运行确认。
- **CLI**：不提供交互定位（M0 规则不变）。
- **嵌入式串口**：`seek <毫秒>`，回应 `OK seek track=N frame=M`；空闲时 `ERR seek idle`。刚开始播放、曲目格式还不知道时（毫秒数无法换算成帧）回应 `OK seek track=N pending ms=M`，格式确定后、音频入队之前换算并定位；play / stop / next / prev 清除待定定位。音源不可定位时通知 `EVENT seek-sequential track=N decoded-to-target`。

## 6. 未运行与限制

- **真实设备上的定位**：WASAPI 独占真机、ALSA 真机与 MCU 实物均未运行定位（用户 2026-10-15 表示细微项暂不实测）。
- **嵌入式模型随机测试**（`model_random`）不含定位：它的模型假定每段输出是曲目从头起的前缀；定位由上面的嵌入式与 QEMU 测试覆盖。
- **FLAC 跳转上限**：实测最多 14 次，32 次上限未被触发；1 秒与 32 次是任务卡建议值，以后可按实测再调。
- **不支持定位的情形**（结果仍精确，只是顺序解码更慢）：FLAC 总样本数为 0 且无 SEEKTABLE；固定块策略但块大小不一的 FLAC；不可定位的音源。
