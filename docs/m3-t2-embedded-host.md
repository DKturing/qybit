## 1. 结构

板级适配只做两件事：外设初始化，以及实现下面三个接口。播放规则（预填、续用、换格式排空、暂停、切歌、出错跳过、能力检查）全部在 `qy_core::engine`。

| 接口 | 作用 | 板级实现 |
| --- | --- | --- |
| `storage::Storage` | 播放列表、打开、分段读取、关闭、重新扫描 | 通用实现 `FatStorage`（基于 `embedded-sdmmc`），板子只提供 `BlockDevice`（SPI 或 SDIO） |
| `output::AudioOutput` + `OutputCaps` | 按设备格式配置 I²S/SAI、启动/停止循环 DMA；声明能精确产生的采样率、槽位格式、声道、缓冲帧数与在途缓冲数 | 时钟分频、DMA 双缓冲 |
| `feeder::FeederAccess` | 主循环与 DMA 中断共享 `Feeder` | 临界区（`cortex_m::interrupt::Mutex<RefCell<…>>`） |

**中断与主循环的分工**：

- DMA 每完成一个缓冲，中断调用 `Feeder::fill`。它只做三件事，不解码、不 pack、不分配、不阻塞：
  - 有界拷贝（至多两次读授权）；
  - 缺数据时补静音；
  - 计数。
- 计数分开记录：
  - 欠载：运行中、未暂停、未排空时队列不足；
  - 暂停静音；
  - 排空尾部静音。
- **排空完成**的判定：队列已空，并且最后一个含有效数据的缓冲之后又填了 `in_flight` 次（乒乓双缓冲为 2）。这样保证在途缓冲里的有效数据都已播出，才回报 `DeviceDrained`。
- **主循环 `Player::step`** 每次至多执行一个引擎动作，读取每次至多 `read_chunk` 字节，所以串口命令的响应延迟有界。读卡阻塞期间 DMA 中断照常触发。

**串口命令**（按行，ASCII）：`ls`、`play [n]`、`pause`、`resume`、`stop`、`next`、`prev`、`status`、`scan`。

- 回应为 `OK …`、`ERR …`、`TRACK i 名称`、`STATUS key=value …`，异步通知为 `EVENT …`。
- `status` 报告以下计数：
  - 欠载次数与缺失帧数；
  - 暂停静音缓冲数；
  - 打开错误、读取错误、解码错误；
  - 能力或设备不支持、跳过曲目数；
  - 输出错误、喂数错误、协议错误、旧代次回报。
- 超长的行整行丢弃并回 `ERR too-long`。

**存储**：

- 读 MBR 第 1 个分区（FAT16/FAT32）的根目录，扩展名为 `WAV` 或 `FLA`（`.flac` 的 8.3 短名）的文件按短文件名排序，构成播放列表。格式由解码器按文件头识别。
- 拔卡或读错时返回错误，由引擎按出错策略跳过或停止。
- `scan` 会重建卷管理器（丢弃 `embedded-sdmmc` 的块缓存，避免读到旧卡内容）。

## 2. 预填与读卡时序的推导（写入任务卡）

记号：

| 记号 | 含义 |
| --- | --- |
| `W` | 最大输入单元字节数。FLAC 为最大块的不压缩帧上界（输入窗口）；WAV 为板级选定的统计窗口，例如 16 KiB |
| `F` | 一个最大输入单元至少包含的音频帧数 |
| `U` | 读取文件中**任意连续 `W` 字节**的最长耗时，含命令开销、偶发停顿与 FAT 簇链查找。板级实测：反复读取测试文件，取所有长度为 `W` 的窗口中的最大值 |
| `D` | 解码并 pack 一个最大输入单元的最长耗时，板级实测 |
| `T` | 最长 DMA 缓冲周期，即最低采样率下一个缓冲的时长 |
| `R` | 源的最大字节率。WAV 为 `fs × 声道 × 4`；FLAC 按最小块（16 帧）的不压缩帧上界计算，块越小每帧开销越大 |
| `fs` | 最高采样率 |
| `P` | 配置档的预填时长 |

按启用的每种格式分别核对，两个条件都满足才启动。同一时刻只播放一种格式，所以各格式用自己的 `W`、`U`、`D`。

1. **持续负载**：`R · U / W + D · fs / F ≤ 10⁶`（时间单位 µs）。
   - 读取是阻塞的，读取时间与解码时间相加。
   - 每秒要读 `R / W` 个单元，每个单元至多耗时 `U`。
2. **预填**：`P ≥ U + D + T`。
   - 最坏情况：开始读取一个最大输入单元时，队列只剩预填量。
   - 接下来要读取这个单元（至多 `U`）、解码（至多 `D`）；入队后还要等到下一个缓冲边界（至多 `T`）才会被取走。
   - 这段时间内设备持续取数，队列不得取空。
   - 条件 1 保证此后队列不会越来越空。

不满足时，`Player::new` 直接返回 `BudgetError`，不启动。报告给出具体组成，例如“预填 250000 µs 不足：最坏情况需要 255334 µs（读取最大输入单元 230000 + 解码 20000 + DMA 周期 5334）”，或“读卡与解码的持续负载为 134.1%，超过 100%”。

`U` 与 `D` 只能在实物上实测。本模块只核对，不估算：

- QEMU 演示中的值是名义值；
- 示例板级适配中的值是未实测的占位值，启动时打印警告。

## 3. 选型与审阅

**`embedded-sdmmc =0.10.0`**：

- 基本信息：2026-07-24 发布，rust-embedded-community，MIT/Apache-2.0，`no_std`、无 alloc。2026-10-13 在 crates.io 核对版本，下载源码审阅。
- 依赖：`embedded-sdmmc-types` 0.1、`heapless` 0.9.1、`embedded-hal` 1.0、`embedded-io` 0.7、`byteorder`、`bitflags`、`thiserror` 等。关闭默认的 `log` 特性。
- 只需要 MBR 分区表。支持的分区类型为 0x04、0x06、0x0E（FAT16）与 0x0B、0x0C（FAT32）。
- 卷管理器内部用 `RefCell`，带一个 512 字节块缓存；没有块缓存失效接口，因此换卡后由 `FatStorage::rescan` 重建。
- `unsafe` 位置：
  - `unsafe` 块 6 处，都用于从磁盘字节构造短文件名或卷标（不再校验字符）：`volume_mgr.rs` 4 处、`filesystem/filename.rs` 1 处（`from_utf8_unchecked`）、`fat/mod.rs` 1 处；
  - `unsafe fn` 3 个：`ShortFileName::to_volume_label`、`VolumeName::to_short_filename`，以及 SPI 驱动的 `SdCard::mark_card_as_init`（本项目未用 SPI 驱动）。
- **panic 风险**：读取路径中有 `assert!` 与 `unwrap`，例如：
  - `volume_mgr.rs`：`read` 中 `assert!(to_copy != 0)`、`find_data_on_disk` 中 `assert!(offset_from_cluster < bytes_per_cluster)`；
  - `fat/volume.rs`：`next_cluster` 对超范围簇号 `panic!`。
  
  损坏的文件系统（例如目录项中的起始簇号越界）有可能触发这些 panic。这是不可信输入，按 AGENTS §4 不应 panic。本卡未处理，列为未完成项：T3 故障注入前对 `FatStorage` 做损坏镜像 fuzz，再决定上游修复，还是在 `BlockDevice` / 目录扫描层加防护。

**`fatfs =0.3.6`**：

- 只用于测试与构建脚本，生成 FAT16 镜像（`tools/qy-fat-image`），与被测读取路径相互独立。
- 关闭默认的 `chrono` 特性，镜像中没有时间戳，内容确定。

**`stm32f4xx-hal =0.23.0`**（2025-09-22 发布）、**`stm32f4 =0.16.0`**（PAC，只为打开 `rt`）：

- 只用于板级适配示例。
- I²S 驱动来自其依赖 `stm32_i2s_v12x` 0.5.1。DMA 双缓冲使用安全接口 `Transfer::next_transfer`，不使用 `unsafe` 的 `next_transfer_with`。

## 4. 新的槽位表示：`Endian::HalfWordSwapped`

STM32F4 的 SPI/I²S 数据寄存器是 16 位。经 16 位 DMA 发送 32 位槽位时先发高半字，因此内存中每个样本是“高半字在前、半字内小端”。例如 `0x1234_5678` 的内存字节为 `34 12 78 56`。

- 这是设备表示的一部分，由 pack（唯一的表示转换边界）直接排好；中断里只按小端把字节对解释为半字，不改变数值。
- 规则：
  - 16 位容器与小端相同；
  - 24 位容器没有此表示，构造即拒绝（`FormatError::Layout`）；
  - WASAPI 与 ALSA 的格式描述只接受小端，遇到此表示按非小端拒绝。
- 测试：
  - 独立参考字节：32/32、32/24 左对齐、16/16；
  - 往返测试：覆盖 16/32 容器 × 两种放置 × 1–V 位。

## 5. 宿主侧仿真（不是实机）

`qy-host-embedded/tests/embedded_sim.rs` 运行真实的 `qy-host-embedded`、引擎、自有解码器、pack、静态队列与 `embedded-sdmmc`，只把 SD 卡与 I²S DMA 换成虚拟时间下的假设备：

- **SD 卡**：内存中的 FAT16 镜像，簇 4 KiB。每读一个块推进虚拟时钟。可注入：
  - 固定延迟；
  - 周期性停顿；
  - 第 k 次块读取失败；
  - 拔卡。
- **I²S DMA**：启动时连续填两个缓冲。此后每个缓冲周期到点时，最早的在途缓冲才算“播出”并计入输出，再填一个。停止时在途缓冲丢弃，所以过早停止会少输出数据。
- **期望字节**：由独立参考（libFLAC `.s32le`、ffmpeg `.ffmpeg.s32le`，或测试自己写入的样本）按 `s << (C − N)` 放置。设备分段规则也在测试内独立实现。

| 场景 | 结果 |
| --- | --- |
| 夹具播放列表：WAV 16、FLAC 16、CRC 错误 FLAC、6 声道 WAV、192 kHz FLAC、96 kHz/24 位 FLAC、48 kHz/20 位 FLAC、长文件名 WAV、8 kHz WAV；时序声明 WAV `U` 9 ms / `D` 1 ms，FLAC `U` 17 ms / `D` 15 ms | 4 个设备段与参考逐字节一致；跳过原因依次为解码错误、6 声道能力不足、192 kHz 能力不足；无欠载；时序核对负载 740‰、需要预填 64 ms（配置档 250 ms） |
| 慢卡：每块 150 µs、每 40 次块读取停顿 8 ms；声明 FLAC `U` 26 ms、WAV `U` 14 ms | 48 kHz 16 位 3 s、48 kHz 24 位 1.5 s、44.1 kHz 16 位 2 s 无欠载，逐字节一致；负载 965‰；虚拟时长 6.63 s，块读取 2996 次 |
| 实际读卡慢于声明：每 300 次块读取停顿 400 ms（超过 250 ms 预填） | 欠载 11 次、缺 2568 帧，经 `status` 报告；有效数据不丢、不重复（逐字节一致） |
| 时序不足 | `Player::new` 拒绝：“读卡与解码的持续负载为 134.1%，超过 100%”；预填不足的报告文字另有核对 |
| 读错误、拔卡、重新插卡 | 第 2 首读取中块读取失败：该曲按读取错误跳过（`read_errors=1`），只输出出错前的前缀，其余曲目完整。播放中拔卡：其余曲目打开失败，最后一首出错时停止并报告失败，不 panic。重新插卡后 `scan`、`play`：完整且逐字节一致 |
| 串口命令脚本 | `ls`、错误命令、越界 `play` 的回应正确；播放中 `pause`（`status` 显示 paused）、`resume`、`next`、`prev`、`stop` 都生效；暂停与切歌不算欠载；三段输出各为对应参考的前缀 |
| 板级能力不足：时钟不能产生 44.1 kHz、只支持双声道 | 44.1 kHz 与单声道曲目分别以 `Rate(44100)`、`Channels(1)` 拒绝，其余曲目逐字节一致 |

变异检查（逐一改坏、确认被测试发现、再还原），四处都被发现：

| 改坏的地方 | 失败的场景数 |
| --- | --- |
| 排空不等在途缓冲 | 5 |
| 排空期间也计欠载 | 3 |
| 暂停不输出静音 | 1 |
| `in_flight` 少算 1 | 5 |

## 6. QEMU 演示（指令集仿真，不是实机）

`qy-mcu-demo` 现在就是一个“外设由软件模拟的板级适配”：

- **SD 卡**：`build.rs` 用 `qy-fat-image` 生成 FAT16 镜像（簇 512 字节，约 2.1 MB），编进闪存，经 `embedded-sdmmc` 扫描读取；
- **DMA**：主循环空闲时推进一个 DMA 周期，在临界区里调用 `Feeder::fill`；
- **串口**：命令脚本（`ls`、`play`、`pause`、`resume`）经行缓冲解析，回应经半主机输出。

| | Embedded Full | Embedded Lite |
| --- | --- | --- |
| 设备段 | 44.1k/2/16、96k/1/32-24、48k/1/32-24，帧数与 FNV-1a **与 M3 T1 完全相同** | 44.1k/2/16、8k/1/16，同样与 T1 相同 |
| 跳过 | 解码错误、6 声道 WAV、6 声道 FLAC（解码器容量）、192 kHz | 未链接 FLAC、6 声道、24 位、96 kHz |
| 暂停静音缓冲 / 欠载 | 50 / 0 | 2 / 0 |
| `.text` / `.rodata`（含 2 223 104 字节镜像）/ `.data` / `.bss` | 72 144 / 2 230 772 / 600 / 365 736 字节 | 59 468 / 2 229 304 / 600 / 91 068 字节 |
| 栈高水位 | 9 656 字节（T1 为 3 072） | 4 692 字节（T1 为 2 672） |

`.bss` 不变，大缓冲仍全部静态分配。栈增加，是因为宿主（含 `embedded-sdmmc` 卷管理器的 512 字节块缓存）放在 `main` 的栈帧里，远小于栈区。`.data` 的 600 字节是共享状态的静态初值。

## 7. 板级适配示例（STM32F411，只编译）

`crates/qy-board-stm32f411`：只说明一块板的适配有多薄，不代表推荐型号；**未在实物上运行**。

| 外设 | 实现 |
| --- | --- |
| SD 卡 | SDIO 4 位，HAL 低速初始化后切到 24 MHz；读错后下次访问重新初始化 |
| I²S | SPI2/I²S2 主发送，飞利浦标准；DMA1 Stream4 双缓冲，三块 2 KiB 缓冲；传输完成中断里填空闲缓冲后用 `next_transfer` 换入 |
| 串口 | USART2 115200；空闲时轮询（接收没有用中断或 DMA，WFI 期间会丢字符） |

**槽位**：

- 16 位源用 16 位帧；
- 17–24 位源用 32 位帧中的 24 位数据，即 32/24 左对齐、`HalfWordSwapped`；
- 只能立体声，SPI/I²S 外设没有单声道模式。

**采样率**：

- 计算公式：Fs = I2SCLK / (帧位数 × (2 × I2SDIV + ODD))（RM0383 §20.4.4，不输出 MCK 时）。
- I2SCLK 为 61.44 MHz 时，8、16、32、48 kHz 都能整除；44.1 kHz 系列不能，因此不列出。
- `configure` 按实际 I2SCLK 重新核对，除不尽即报错，不近似。

**配置档**：

- 本芯片只有 128 KiB RAM，放不下 Embedded Full（约 360 KiB）。
- 在板级 crate 里声明了一个配置档：只链接 WAV，≤ 48 kHz、≤ 24 位、预填 150 ms。
- `.bss` 为 104 772 字节，`.text` 为 68 932 字节。
- FLAC 需要更大 RAM 的板（例如 STM32F7/H7 级别）。

**`unsafe`**：唯一一处是开启 DMA 中断的 `NVIC::unmask`。理由：中断处理所需的共享状态都已就绪后才解除屏蔽，处理函数只经临界区访问状态。
