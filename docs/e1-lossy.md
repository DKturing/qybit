# E1：有损标记

日期：2026-10-18。任务卡：[tasks/E1.md](../tasks/E1.md)。本卡的结果来自单元测试、契约测试与示例 crate 的桌面 / 嵌入式虚拟时间场景，**不是实机结果**。

## 1. 接口

- `qy_core::SourceFormat`（定义在 `qy-pcm-format`）增加有损标记：
  - `SourceFormat::lossy(self) -> Self`：解码器构造格式时调用，标记为有损编码的解码输出；
  - `SourceFormat::is_lossy(&self) -> bool`；
  - 默认无损；官方解码器（WAV、FLAC、AIFF）不调用，输出与报告不变；
  - `relayout`、`with_encoding`（单声道复制、浮点转整数时由引擎调用）保持标记。
- 含义：有损时 `bits()` 是解码输出的精度，不是音源位深（AGENTS §3）。
- 标记只影响报告：设备是否接受（`DeviceFormat::accepts`）与续用设备的判断不看它，送出的数据不变。同参数的有损曲目与无损曲目共用一个设备流。
- `qy_core::Core::track_format()` 与 `qy_core::engine::Engine::track_format()`：最近一次产出样本的曲目序号与解码器给出的源格式。宿主据此按曲目记录源格式（同格式的相邻曲目不重新配置，但每首都会更新）。

## 2. 显示

| 位置 | 有损曲目的写法 |
| --- | --- |
| 播放报告、命令行实时输出（`qy-player`） | 协商记录“源格式：44100 Hz / 2 声道 / 有损编码，解码输出 24 位”；实时输出“曲目 N 是有损编码：播放的是解码重建的信号，24 位是解码输出的精度，不是音源位深”；报告逐曲目列出，并在结论后写明“软件路径没有改动解码输出，但解码输出本身不是音源的无损数据”；`PlaybackReport::lossy_tracks` |
| `qybit decode` | 源格式行同上 |
| 图形界面（`qy-ui`，Windows 与 Linux 共用） | 格式列与格式行“44.1 kHz 解码 24 位 2 声道 有损”；保真行“软件路径：未改动解码输出、无欠载；当前曲目是有损编码，播放的是解码重建的信号” |
| 嵌入式串口（`qy-host-embedded`） | 播放计划行 `EVENT plan rate=… ch=… bits=… lossy=1 …`（无损时没有 `lossy` 字段，原有解析不受影响） |

## 3. 顺带修正

`qy-player` 原先按“引擎当前曲目序号 + 解码器当前格式”记录各曲目的源格式。曲目结束后、下一首打开前，序号已指向下一首而解码器的格式仍是上一首的（短曲目可能在一次引擎 `poll` 内解码完），于是可能把上一首的格式记在下一首名下。这条记录原来只用于定位时显示的时间，E1 的测试暴露了它。现在改为按 `Engine::track_format()` 记录：核心产出样本时的序号就是该曲目。

## 4. 验证

| 测试 | 内容 | 结果 |
| --- | --- | --- |
| `qy-pcm-format` 单元测试 | 默认无损；`relayout` / `with_encoding`（整数与浮点）保持标记；设备是否接受与标记无关 | 通过 |
| `qy-ui` 单元测试 | 无损与有损（整数、浮点）的格式文字 | 通过 |
| 契约测试（`examples/qy-ext-demo/tests/contract.rs`） | 有损变体 QYL1（与 QYT1 布局相同，格式标为有损）满足全部契约（格式在同一个源内不变由 `qy-testkit` 检查）、样本与生成值相同、可定位 | 通过 |
| 桌面场景（`tests/desktop.rs`） | QYT1、QYL1、WAV 混排（44.1 kHz / 16 位 / 双声道）：一个设备流，设备字节逐字节等于三份参考依次相接；报告与实时输出只把第 2 首写成有损 | 通过 |
| 嵌入式场景（`tests/embedded.rs`，虚拟时间） | QYL1、QYT1：计划行只在有损曲目上有 `lossy=1`；一个设备流，字节等于参考 | 通过 |
| 全部既有测试 | 官方解码器的输出与报告不变 | 通过 |
| QEMU 演示（Embedded Full / Lite） | 照常通过；`.text` 分别增加 288 / 992 字节（相对 F5），`.bss` 不变 | 通过 |
