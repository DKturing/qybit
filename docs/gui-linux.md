# Linux 图形界面（自绘，X11）

日期：2026-10-18。

**来源**：原型与测量见 [gui-linux-prototype.md](gui-linux-prototype.md)。用户在真机上经 MobaXterm 的 X11 转发运行原型后决定：

- 采用自绘方案（x11rb 纯 Rust X11，musl 静态）；
- 界面尽量与 Windows 版保持一致，包括各个选项；
- 不另写任务卡，记录在本文与 [tasks/GUI.md](../tasks/GUI.md)。

## 1. 与 Windows 版相同的部分

两个前端共用同一份界面逻辑 `crates/qybit-gui/src/app.rs`：

- 菜单命令、排序与调整顺序、设备列表（选定设备消失时标明“未连接”，不自动换设备）；
- 媒体键、记住设置；
- 进度条预览文字、播放标记与单元格文字。

播放走 `qy-ui` 的同一套后台线程：真实核心、自有解码、pack 与渲染循环，不经软件音量，严格路径不改样本。

| 项目 | Linux 前端 |
|---|---|
| 菜单 | 文件 / 播放 / 列表 / 查看 / 帮助，条目、快捷键与勾选状态同 Windows；Alt+字母、F10、方向键、回车、Esc、助记字母 |
| 按钮行 | 播放（播放中显示“暂停”/“继续”）、停止、上一首、下一首、添加文件…；设备下拉框（滚轮、方向键） |
| 选项 | 单声道复制到左右两路（会改变声道）、浮点转整数（会改变样本）；每次启动默认关闭，不保存 |
| 格式行 | 源格式 → 设备格式（独占）；右侧为设备硬件音量（§2） |
| 进度条 | 拖动时状态栏显示“松开后定位到 …”，松开后定位；←/→ 前后 5 秒 |
| 播放列表 | 播放标记、序号、文件、时长、格式。点击列标题排序（再点反向，标题显示箭头），拖动列分隔线调整列宽。单击、Ctrl、Shift 多选，Ctrl+A 全选；双击或回车播放，Del 移除。拖动选中的行调整顺序：落点高亮，状态栏写“松开后移到第 N 行之前 / 列表末尾”，靠近边缘时滚动，Esc 或失去焦点时取消。Ctrl+↑/↓ 上移下移 |
| 日志 | 与列表之间的分隔条可拖动；查看菜单可显示/隐藏、清除；自动换行，新内容出现时滚到末尾 |
| 状态栏 | 播放状态、保真状态、采样率指示灯（灰 / 琥珀 / 绿 / 红，文字同 Windows） |
| 加入曲目 | 添加文件、添加文件夹（文件夹在读取线程中扫描）、从文件管理器拖放（XDND）、命令行参数 |
| 记住播放列表与设置 | 文件菜单，默认关闭；保存到 `$XDG_CONFIG_HOME/qybit/qybit-gui.cfg`（缺省 `~/.config/qybit/`），格式同 Windows。内容：播放列表顺序、选定设备、窗口位置与大小（含最大化）、日志区显示与高度、排序箭头、全局媒体键 |
| 媒体键 | XF86AudioPlay / Pause / Stop / Next / Prev。“全局媒体键”开启时在根窗口上抓取（`GrabKey`），窗口不在前台时也响应；被其他程序占用的键写入日志 |
| 关于 | 版本、输出方式（ALSA hw 独占，内核接口）、许可 |

## 2. 与 Windows 版不同的部分（及原因）

- **输出设备**：内核直连 ALSA（A1）没有系统默认设备。
  - 下拉框第 0 项为“（请选择输出设备）”；未选择时播放会报告原因。
  - 只有一个播放设备且没有保存的选择时，自动选中它。
  - 内核接口没有设备变化通知：每 2 秒、以及打开下拉框时重新读取设备列表。
  - 没有找到设备时，日志说明可能的原因（没有声卡，或用户不在 `audio` 组）。
  - 每次会话开始时日志写明“输出设备：hw:…”。同一张卡常有模拟输出与 HDMI 等多个 PCM，名称中含 HDMI 的是显示器音频；日志里“声道映射：可变”通常也表示 HDMI（模拟输出与 USB 声卡一般是固定映射）。
  - 播放（或暂停）中在下拉框换设备：停止原设备上的会话（恢复其硬件音量），在新设备上从同一曲目、同一位置重新开始，暂停状态保持，日志写明“输出设备已更换为 …”。这是两个前端共用的逻辑（`qy_ui::Ui::set_device`），Windows 版同样适用；此前换设备只对下一次开始播放生效，当前会话仍在原设备上。
- **设备硬件音量**：遵循 A4 的决定（AGENTS §3：qybit 不在播放之外改动设备混音器），与命令行 `--volume` 相同。
  - 滑块是“播放时的设备硬件音量”百分比，缺省 40%，百分比的算法与 alsamixer 相同。
  - 开始播放时设置这组控制并打开静音开关，播放结束（停止、出错、换设备、退出）时恢复原值。
  - 播放中拖动滑块只改这组控制，结束时仍恢复为播放前的值。
  - “播放”菜单的“播放时调整设备硬件音量”可关闭；关闭时正在播放的会话立即恢复。
  - 设置、读数与恢复写入日志。设备没有可用的硬件音量时照常播放并说明原因，不以软件缩放代替。
  - 与 Windows 不同：Windows GUI T5 的滑块直接调端点音量，不在结束时恢复。
- **文件对话框**：自绘界面没有系统文件对话框；精简系统上也没有 xdg-desktop-portal。
  - 自绘的文件面板：路径栏可输入后回车；上一级、主目录、根目录。
  - 目录在前；默认只列 WAV、FLAC、AIFF，可切换“显示所有文件”。
  - 多选；双击目录进入、双击文件加入；Backspace 上一级；首字母跳转。
- **复制日志**：查看菜单“复制日志”或在日志区按 Ctrl+C，整段复制到剪贴板（`CLIPBOARD` 选择）；经 SSH X11 转发时，MobaXterm 等会同步到本机剪贴板。日志区不能逐字选择。
- **字体**：直接读系统字体（fontdb 解析 fontconfig 配置文件，不链接 libfontconfig）。没有中文字体时日志提示安装（如 `fonts-noto-cjk`）；系统中一个字体也没有时（精简系统、容器）启动即报错退出并说明安装方法或放到 `~/.local/share/fonts/`。
- **经 SSH 的 X11 转发**：每次重绘的像素都经网络送出。播放中进度条只重绘滑块两侧的一小段，状态栏每秒重绘一次；1.5 倍缩放时稳态约 0.2 MiB/s（此前进度条整行重绘约 3 MiB/s，网络慢时表现为读秒滞后）。换曲、日志新增时重绘列表或日志区。
  - **遗留（2026-10-18 用户决定暂时略过）**：经 MobaXterm 转发的真机上，降低数据量后读秒仍略慢于实际时间，用户认为影响不大。尚未查明是数据量还是事件延迟所致；以后可测量从进度变化到画面送出的延迟，并把状态栏也改为只重绘变化的文字段。
- **诊断输出**：环境变量 `QYBIT_GUI_TRACE=1` 时把新增的日志行（`日志：…`）、状态栏与指示灯的变化以及每 10 秒的界面数据量（`界面更新：N KiB/s`）写到标准错误，如 `QYBIT_GUI_TRACE=1 ./qybit-gui 2>&1 | tee gui.txt`。模拟设备模式下总是写出（CI 据此核对）。
- **缩放**：读 `Xft.dpi`；环境变量 `QYBIT_SCALE`（如 `1.5`）可覆盖。
- **未实现**：
  - 中文输入法（XIM）：只有文件面板的路径栏需要输入文字，可输入 ASCII 与 Latin-1 字符；
  - 读屏软件（无障碍）。

## 3. 结构

| 文件 | 内容 |
|---|---|
| `src/app.rs` | 两个前端共用的界面逻辑（原 `win/app.rs`；端点类型换成平台无关的 `Device`，下拉框第 0 项的含义由前端指定） |
| `src/sim.rs` | 两个前端共用的模拟设备模式（`sim` 特性，只用于界面核对） |
| `src/linux/x11.rs` | X11 边界：x11rb `RustConnection`（不链接 libX11 / libxcb，不启用 `allow-unsafe-code`）。连接与窗口；`PutImage` 按最大请求长度分条提交（支持两种字节序）；键码表；XDND 接收；`CLIPBOARD` 所有者；媒体键抓取；核心光标字体；窗口位置的读取与恢复（`_NET_WM_STATE` 最大化）；`Xft.dpi` |
| `src/linux/paint.rs` | 画布：tiny-skia 形状、cosmic-text 文字；单行排版按字符串缓存，超长截断加“…” |
| `src/linux/view.rs` | 主窗口控件的布局、绘制、命中测试与输入。按 9 个区域只重绘变化的部分；弹出菜单、下拉框与对话框画在主窗口内 |
| `src/linux/files.rs` | 文件面板 |
| `src/linux/audio.rs` | ALSA 设备列表；会话期间持有音量守卫的后端包装（`GuiBackend`，释放时恢复） |
| `src/linux/mod.rs` | 界面线程：X 事件（读取线程转来）、后台通知（合并）、设备检查定时器；执行显示操作；保存设置 |

`qy-host-alsa` 的 `PlaybackVolume` 增加两个方法：

- `set_percent`：播放中改变百分比，原值仍为播放前的值；
- `describe`：当前读数。

本前端不含 `unsafe`：

- X11 协议由 x11rb 的安全代码实现；
- ALSA 系统调用在 `qy-host-alsa` 已审计的边界内。

## 5. 用户步骤

1. 从 CI 的 `qybit-linux-<架构>` 构件取 `qybit-gui`（与 `qybit` 在同一构件中），放到 Linux 机器上，`chmod +x qybit-gui`。
2. 在桌面的终端里运行 `./qybit-gui`；经 SSH 时用 MobaXterm（或 `ssh -X`）登录后运行，`echo $DISPLAY` 应有输出。
3. 在下拉框中选择设备（名称形如“卡名 — PCM 名（hw:CARD=…,DEV=…）”，耳机选 PCM 名含 Analog 的或 USB 声卡，不要选含 HDMI 的），用“添加文件…”或拖放加入曲目，双击播放。日志中会写明“输出设备：…”和设置的设备硬件音量；停止后写明“已恢复”。
4. 请核对：
   - 3.5 mm 耳机和 USB 耳机都能出声；
   - 音量滑块在播放中拖动生效，停止后 `./qybit mixer --device hw:CARD=<卡名>` 显示这组控制回到原值；
   - 媒体键、记住设置、窗口位置恢复；
   - 播放中换设备后声音转到新设备，从原位置继续；
   - 经 SSH 转发时读秒与实际时间一致；
   - 如有问题，请用查看菜单“复制日志”把日志发来，或用 `QYBIT_GUI_TRACE=1 ./qybit-gui 2>&1 | tee gui.txt` 记录。
