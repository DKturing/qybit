# E5：定位预滚

日期：2026-10-19。任务卡：[tasks/E5.md](../tasks/E5.md)。本卡的结果来自契约测试与示例的桌面 / 嵌入式虚拟时间场景，**不是实机结果**。

## 1. 问题与做法

S1 要求解码器定位后第一帧就是目标帧，做不到时核心从头顺序解码。有损格式（MP3 的比特储备、AAC 的重叠相加）定位到某一包之后要先解码若干帧并丢弃，才能得到正确的样本；从头顺序解码在长曲目上太慢（按 2026-10-18 测得的约 20 倍实时，1 小时的曲目跳到 50 分钟约需 2.5 分钟）。

现在 `Decoder` 增加一个带默认实现的方法：

```rust
fn take_preroll(&mut self) -> u64 { 0 }
```

`seek`（及之后 `seek_request` 的跳转）落在目标之前时，解码器返回目标帧之前还会输出的帧数 k，核心解码并丢弃这 k 帧（与顺序定位共用同一个丢弃计数），定位后送出的第一帧仍是目标帧，精确性不变。约定：

- 核心在每次 `decode` 之后取一次，取走即清零；解码器最迟在落点之后第一次产出样本的那次 `decode` 中给出，可以分几次给出，合计为 k；
- k 不得超过目标帧号；未定位时为 0；
- 默认 0：解码器自己只输出目标帧及之后的样本（S1 的约定）。官方解码器（WAV、AIFF 按字节直接定位，FLAC 按帧精确定位并自行丢弃帧内的前段）不需要预滚，行为不变。

报告：引擎给出 `HostAction::SeekPreroll { track, frames }`；桌面播放器的实时输出与报告写“曲目 N 定位时解码并丢弃了目标之前的 k 帧（预滚；送出的第一帧仍是目标帧）”（`PlaybackReport::seek_prerolls`），嵌入式串口 `EVENT seek-preroll track=N frames=k discarded`，模拟宿主记入 `seek_prerolls`。预滚不算顺序解码。

`Decoder` 是 M0 冻结的接口；本卡只增加带默认实现的方法（与 S1 相同的扩展方式），已有实现不需要修改。`HostAction` 增加了一个变体，宿主对它的 `match` 要加一个分支（本仓库的三个宿主已加）。

## 2. 验证

| 测试 | 内容 | 结果 |
| --- | --- | --- |
| `qy-testkit`（`check_seek`） | 定位检查按核心的做法丢弃预滚帧；预滚超过目标帧号、未定位时给出预滚为违约。契约测试本身：正确的预滚解码器（落在目标之前至多 10 帧）通过；少报 1 帧、超过目标、未定位时给出三种违约变体都被发现 | 通过 |
| 示例 `tests/contract.rs` | QYT1 包模式（每 64 帧一包，落在目标所在包的前一包开头）与组合解码器：51 个目标（包边界两侧、第一包内、最后一帧、越界与 40 个固定种子的伪随机目标），一次性与随机分块输入，定位后的样本与从头解码的对应部分逐个相同 | 通过 |
| 示例 `tests/desktop.rs` | 真实引擎、pack、帧队列与整包渲染循环（无硬件后端）：每包 1152 帧，目标 13000、600、1152、2303、40000：定位后的新流从目标帧起与参考逐字节一致；报告的预滚帧数等于目标与落点之差（目标恰在落点时没有预滚）；不算顺序解码 | 通过 |
| 示例 `tests/embedded.rs` | `qy_host_embedded::Player` 虚拟时间：串口 `seek 300`，串口报告 `seek-preroll`，无欠载，定位后播出的字节从目标帧起逐字节一致 | 通过 |
| 全部既有测试 | 官方解码器的定位与报告不变 | 通过 |
| QEMU 演示（Embedded Full / Lite） | 照常通过；`.text` 分别增加 164 / 136 字节（相对 E3），`.bss` 不变 | 通过 |
| `qy-codec-flac/tests/buffers.rs` 的结构大小上限 | `Core<WavDecoder>` 因 E3 的识别模式标志与本卡的预滚计数（都是标量）由 608 增至 648 字节，上限由 640 调为 704（该测试证明没有内嵌块大小的存储，最小的块缓冲为 73 728 字节） | 通过 |

## 3. 未做

- 本仓库没有需要预滚的格式；真实的有损解码器（插件仓库的 MP3、AAC 等）按本约定实现时，要以独立参考核对定位后的样本。
