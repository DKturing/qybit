# QyFi M0：Windows WAV 严格输出

遵循根目录 AGENTS.md。目标：核心、自有推送式 WAV 解码、pack 与模拟验证可在无音频设备环境自动测试；Windows CLI 使用 WASAPI 独占播放，真机测试独立执行并记录。

范围仅 WAV、顺序多文件与 CLI。设备由命令行 ID 指定；不做交互设备选择、GUI、拖放、随机、seek 或配置。M1 做 FLAC，M2 做 ALSA/snd-aloop。

## T1：工程骨架

- 建立 qy-core、qy-codec-wav、qy-pcm-format、qy-host-sim、qy-host-wasapi、qyfi；Cargo 包/目录名使用这些名称，qyfi 的二进制命名为 qybit。
- qy-core、qy-codec-wav、qy-pcm-format 为 no_std/无 alloc；Windows 绑定仅在 Windows 目标编译。
- qy-pcm-format 中定义与 Windows SDK 无关的格式字段结构与纯构造函数；不能为测试纯逻辑而要求 Windows。
- 输入窗口和 PCM 工作区由宿主启动时堆分配为切片，Box::leak 后传入核心；模拟宿主遵守同一契约，停止/换曲复用，不逐曲分配。M0 默认输入窗口 8192 字节、PCM 工作区 4096 帧×最多 2 声道；WAV 流式读取，不要求整文件装入窗口。
- 生产端完成 pack，SPSC 队列存完整设备帧字节，容量至少容纳最高支持采样率下 500 ms：192 kHz 为 96000 帧，双声道 C32 为 768000 字节，可向上取整。每次设备重配置核对帧宽、容量与代次，不逐曲泄漏新队列。
- 启动前预填至少当前采样率下 500 ms，并准备 API 规定的初始端点缓冲；短曲目则预填全部有效帧并明确 EOF。500 ms 是本阶段缓冲预算，不保证任意长 I/O 停顿都不会欠载。
- CI 分开执行通用模块测试、no_std 目标编译、Windows 构建与测试。所有命令仅引用已存在的 crate。

验收：通用模块在 Linux/Windows 可测试；上述三个精简 crate 可编译到 thumbv7em-none-eabihf；Windows 宿主可构建。

## T2：流式 WAV

- 实现明确的输入消耗/输出帧数、NeedInput、NeedOutput、End 与错误契约，头部未解析时格式未知。
- 支持 RIFF/WAVE 格式码 1，以及 0xFFFE 且子格式为 PCM；16/24/32 位容器、单/双声道。8 位与浮点本阶段明确不支持。
- EXTENSIBLE 正确处理有效位、左对齐、声道掩码；支持范围和非法/不支持的区别写入测试。
- 跳过未知 chunk，处理奇数长度填充；检查 RIFF/chunk 边界、blockAlign、帧完整性与算术溢出。

验收：确定性样本逐样本匹配；独立参考夹具覆盖有效位小于容器位宽、奇数 chunk、截断。逐字节和随机分块输入与一次性输入结果一致；fuzz 至少 10 分钟，记录语料/时长，失败不得 panic。

## T3：pack 与 Windows 纯格式构造

- pack 保持相对幅度，正确处理符号、源精度、容器布局和溢出；N > V 拒绝。
- 实现 pure WAVEFORMATEXTENSIBLE 字段构造：tag、cbSize、rate、channels、container_bits、valid_bits、block_align、avg_bytes_per_sec、channel_mask、PCM subformat GUID。
- 构造逻辑不调用 COM，不依赖实际设备。Windows 层只做字段到 SDK 结构的转换，并验证布局/字段映射。
- pack 在生产端将 i32 PCM 转成设备字节再入队；只按完整帧入队/消费，环形回绕最多分段拷贝，渲染线程不做位移、字节序或样本格式转换。
- 为 16/16 单/双声道添加纯 WAVEFORMATEX 描述：PCM tag=1、cbSize=0，其采样率、声道、位深、blockAlign 和 avgBytesPerSec 与 EXTENSIBLE 相同；两种描述分别测预期字段。
- 格式例：44.1k/双声道/C16/V16 → blockAlign=4、avgBytesPerSec=176400；96k/双声道/C32/V24 → blockAlign=8、avgBytesPerSec=768000。PCM EXTENSIBLE 的 tag=0xFFFE、cbSize=22。
- 单声道布局定义为 FrontCenter，双声道为 FrontLeft/FrontRight；音源的其他布局不能偷偷重映射。

验收：在所有测试平台用独立预期字段检查完整描述，包括 GUID 和 mask；覆盖 16/16、24/24、32/24、32/32，拒绝零采样率、非法声道、V=0、V>C 和溢出。pack 测试同时有往返性质与独立预期字节，不能只验证自洽。

## T4：真实路径模拟

- qy-host-sim 执行真实 qy-core、qy-codec-wav、pack；只模拟文件、时间与设备。
- 注入短读、慢读、读取错误、格式不符、打开失败、设备断开、部分消费与欠载。
- 请求 ID/代次防止旧结果污染；检查 EOF 与输出队列 drain，保留起始静音和曲目尾帧。

验收：1000 个固定可复现种子；正常场景在明确的预填和生产停顿预算下逐样本、逐帧匹配曲目拼接且无欠载；超预算停顿作为故障场景，按报告与恢复规则验证。模拟 WASAPI 整包消费，跟踪有效样本与填充；其他后端不套用统一补零假设。失败输出种子，场景设定终止/超时条件。

T4 验收通过后，`Event`、`Action`、`Decoder` 视为已稳定接口；此前可按任务调整，通过后破坏性变更须先征得用户同意。其他接口仅在后续任务卡明确冻结时视为稳定。

## T5：WASAPI 宿主

- 使用独占模式和事件驱动输出，按原格式调用 IsFormatSupported，再 Initialize；不加自动转换，不共享回退。
- pure 描述到 SDK 结构的映射不改变字段；正确处理 COM 生命周期、缓冲对齐、事件等待与设备失效。
- 渲染线程自行调用 AvSetMmThreadCharacteristicsW 注册 MMCSS 的 “Pro Audio” 任务；注册失败记录 Win32 错误，退出/错误清理时在该线程调用 AvRevertMmThreadCharacteristics。记录注册结果并验证清理，不以 MMCSS 成功代替欠载测试。
- 每个格式尝试使用新的 AudioClient；初始化失败重试遵循 API 要求，不重复使用已失效的实例。
- 提交严格遵循 GetBuffer/ReleaseBuffer 文档：WASAPI 独占事件驱动每包请求和释放的帧数均等于成功初始化后 GetBufferSize 返回的端点缓冲帧数，不按队列可用量缩小，不预设允许部分提交；对应调用在同一渲染线程内配对。
- 每包从已 pack 队列拷贝有效帧；播放中且未 EOF 时不足的部分补设备格式静音，记录欠载事件、缺失帧数及时间位置。部分补零不能设置整包 SILENT 标志，否则有效音频也会被静音。
- 已确认 EOF 且没有下一首同格式曲目数据时，末包剩余静音是设备整包填充，不算播放中欠载；分别记录有效音源帧与尾部填充，并按后端 drain 规则等待末尾有效音频播放完成。启动/停止/错误语义另行区分。
- 音频线程不解码/pack/读文件/等 UI；报告实际协商依据，GetMixFormat 不作为独占实际格式证据。

验收：Windows 自动测试覆盖字段映射、完整包请求/释放、跨环形回绕拷贝、队列不足补零、部分有效包不标整包 SILENT、EOF 尾包与欠载区分；以注入的假 API 检查调用帧数和配对，codec/pack 仍跑真实实现。真实设备测试均标记 #[ignore]，普通 cargo test 不要求 DAC。

## T6：真机集成与 CLI

- CLI：qybit --device <endpoint-id> file1.wav file2.wav；另提供只列举设备 ID 的命令。
- 明确显示音源格式、独占协商结果、错误及欠载计数，不显示未经证实的“设备端 bit-perfect”。
- 真机测试要求显式设备 ID，未指定设备或设备不存在时明确失败，不偷偷跳过。
- 手动执行 cargo test -p qy-host-wasapi --test device -- --ignored --test-threads=1；测试文件命名可按实际工程调整，并同步 README。
- 格式矩阵至少覆盖 44.1/48/88.2/96/176.4/192 kHz 与 16/16、24/24、32/24、32/32，单/双声道；设备不支持是需要记录的正常能力结果。
- 16/16 单/双声道在每个采样率分别测试 WAVEFORMATEX 与 WAVEFORMATEXTENSIBLE；默认输出仍用 EXTENSIBLE，本阶段不预先加入运行时回退。按实测结果决定是否添加同 PCM 参数的描述回退；不得改样本、采样率、位深、声道或独占模式。
- 每项记录设备 ID/名称、系统和驱动信息、后端版本、描述类型与请求字段、IsFormatSupported HRESULT、Initialize HRESULT、MMCSS 结果、播放结果/输出错误/欠载。只对支持并成功打开的组合做播放验证。
- 对至少两个支持的不同采样率执行顺序换曲，检查正确重开设备、无旧 PCM、尾帧不截断。

验收：自动测试与 Windows 构建通过；生成可复现的 JSON/CSV 设备能力与播放报告。无硬件时交付手动步骤，并明确真机未验证。接口成功与人工听音只能证明兼容性/播放运行，不能证明 DAC 输入样本逐位一致。

## M0 证据边界

纯函数/真实解码模拟验证软件逻辑；真机 ignored 测试验证独占协商和运行；真实数字链路仍需独立捕获比较。M2 的 snd-aloop 增加 ALSA 路径自动回环，不追溯证明 WASAPI 或真实 DAC 保真。
