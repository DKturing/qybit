# QyBit P1：性能优化（按实测数据决定）

遵循根目录 AGENTS.md。前置：M3 T3 完成，即在至少一块实物板上有实测记录，包括：

- 各格式的读取耗时 `U`、解码耗时 `D`；
- 解码余量分布；
- 中断占用；
- RAM 余量。

顺序：用户确定放在 M3 T3 实测之后（2026-10-14）。

**原则**：

- **先测量，后优化**。每一项都有启动条件，只有实测数据表明它是瓶颈时才做；数据不支持的项写明“不做”及理由；
- **不改变样本**。每一项都必须通过逐样本一致性测试（libFLAC / ffmpeg 参考、模拟回归摘要、A 层回环），并通过 fuzz；
- **同板对比**。优化前后在同一块板、同一配置下测量，记录芯片型号、时钟、编译选项与测试文件；结论只对记录中的板成立；
- **接口不变**。冻结的 `Action` / `Event` / `Decoder` 不变；如需破坏，先征得用户同意；
- **保留基准实现**。新增的专用实现（特定指令集或特定板）与标量基准实现并存，可以切换对比。

## 1. 有界解码与分层 FLAC 解码

**启动条件**（满足任一）：

- 实测 FLAC 的 `D`（解码一个最大帧的最长耗时）使预填条件 `P ≥ U + D + T` 的余量不足；
- 单次解码调用的最长耗时，使串口命令或其他主循环任务的响应延迟超出可接受范围（数值在启动时写入本卡）。

**内容**：

- 在不改 `Decoder` 公共接口的前提下，把 FLAC 解码内部分成帧头、子帧、残差几层；
- 每次调用的工作量有上界，例如至多处理一个子帧或一定数量的样本；未完成时保存可恢复的中间状态；
- 现有的整帧重试保留为对照实现；
- 工作量上界不等于时间上界：时间上界仍须在目标板上按限定的码流复杂度实测。

**验收**：

- 逐样本一致；
- 任意分块输入一致；
- fuzz 10 分钟；
- 同板对比单次调用最长耗时与总解码耗时：前者应下降，后者不得明显上升，阈值在启动时写定。

## 2. 零拷贝与缓冲所有权传递

**启动条件**（满足任一）：

- 实测 DMA 中断里的拷贝耗时（例如每周期约 2 KiB）占输出周期的比例过高；
- RAM 余量不足以容纳独立的 DMA 缓冲。

数值阈值在启动时写定。

**内容**（候选，按数据选择）：

- DMA 直接读取静态帧队列的连续读授权（`consume_contiguous`），省去中断里的拷贝；需要处理缓冲长度变化与回绕；
- 板级示例（STM32F4）中“字节 → 16 位半字”的转换拷贝，改为让 DMA 直接读取队列存储；
- 固定数量缓冲块的所有权传递（空闲 → 填充 → 就绪 → 消费 → 归还），每块只有一个可写所有者；
- 桌面后端不强求：WASAPI 必须写入 API 提供的缓冲，零拷贝只作为后端能力优化，不是 Core 的强制要求。

**约束**：

- 不自行编写无锁缓冲（AGENTS §2），只用成熟库的接口；
- 生产端不得覆盖 DMA 正在读取的数据；
- 欠载、暂停、排空的计数语义不变。

**验收**：

- 逐字节回环与 QEMU 校验和不变；
- 同板对比中断耗时与 RAM 占用；
- 模型随机命令测试（R1）全部通过。

## 3. 解码内核优化

**启动条件**：

- 实测解码耗时是负载 `R · U / W + D · fs / F` 中的主要部分；
- 或者目标格式（例如 96 kHz / 24 位 FLAC）在该板上不满足负载条件。

**内容**（按 profiling 结果排序，逐项做）：

- 位读取器：批量读取、减少边界检查的分支，前提是仍然对所有输入不 panic；
- Rice / Rice2 残差解码：查表或计算前导零的快速路径；
- 固定预测与 LPC 重建：循环展开、按阶数特化；累加位宽仍须满足 RFC 9639 的范围，不得溢出；
- SIMD 或特定指令集（如 Cortex-M 的 DSP 扩展、桌面的向量指令）：只在基准测试证明对该目标有效时加入；与标量实现并存，按目标选择。

**验收**：

- 逐样本一致（全部 FLAC 夹具、模拟 1200 种子、libFLAC 参考）；
- fuzz 10 分钟；
- 同板对比 `D` 与代码体积；体积增加须在记录中说明。

## 4. 记录

每一项都要在 `docs/` 中记录：

- 启动条件的实测数据（做或不做的依据）；
- 方案与理由；
