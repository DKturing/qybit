# QyBit F5：AIFF-C 未压缩变体 `twos`、`sowt`、`fl32` / `fl64`

遵循根目录 AGENTS.md。顺序见 [tasks/FORMATS.md](FORMATS.md)：基础格式，F4 之后。

状态：进行中（2026-10-18 立卡）。用户 2026-10-18 决定把这四种类型纳入基础格式（取代 2026-10-15 “不进 Core”的决定，见 [F2](F2.md) §4、[F3](F3.md) §8）。

**目标**：`qy-codec-aiff` 解码 AIFF-C 的 `twos`、`sowt`、`fl32`、`fl64`（以及大写写法 `FL32`、`FL64`）。它们都是未压缩 PCM，只在字节序或样本编码上与 `NONE` 不同；严格路径不改变样本，浮点按位输出、接入 F3 的浮点路径。

## 1. 规则

- **`twos`**：与 `NONE` 相同（大端补码，`sampleSize` 1–32 位，1–8 位占 1 字节……25–32 位占 4 字节，有效位左对齐、低位填充丢弃）。QTFF 的表述只提到 8 位与 16 位；更宽的位数是写入程序（libsndfile）的实际用法，含义没有歧义（字节序与编码都确定），按同一规则接受。
- **`sowt`**：小端补码，其余与 `NONE` 相同（`sampleSize` 1–32 位，容器字节数与左对齐规则相同，只是容器内字节顺序相反）。QTFF 只定义 16 位；8/24/32 位是 libsndfile 等写入程序的实际用法，含义没有歧义，按同一规则接受。ffmpeg 只把 `sowt` 当作 16 位，因此 16 位以外的 `sowt` 只用本项目生成器的独立参考核对（并用 libsndfile 写出的文件做回归样例，若环境中有 libsndfile 工具）。
- **`fl32` / `FL32`**：IEEE 754 binary32，大端；`sampleSize` 必须为 32，否则按不合规拒绝并写明（libsndfile 会把这种损坏文件“修正”为 32；本项目先严格，以后有真实样例再按 W1 的方式逐条加入修正）。
- **`fl64` / `FL64`**：IEEE 754 binary64，大端；`sampleSize` 必须为 64。
- **浮点输出**（F3 约定）：binary32 每样本一个 `i32`（位模式原样），binary64 每样本两个 `i32`（先低 32 位、后高 32 位）；不做数值运算。NaN、无穷原样传递，只在明确开启的浮点转整数选项中处理（F3）。
- **COMM 的 `sampleSize` 上限**：整数类型 1–32；浮点只允许 32 / 64（不再按“1–32 位”统一检查）。
- **其他规范之外的类型**照旧按“规范之外的扩展”拒绝并写明类型码：`raw `、`in24`、`in32`、`42ni`、`23ni`、`ulaw`、`alaw`、`ima4` 等（以后若需要再逐项立卡）。
- **报告**：格式行与报告中写明类型码（如“AIFF-C sowt（小端）”），让用户知道读的是哪一种。

## 2. 夹具与参考

- **生成器**（`tools/qy-gen-fixtures`，aiff 模块）独立构造夹具与期望样本：
  - `twos` 与 `sowt`：1、8、12、16、20、24、32 位；单声道、双声道、3 声道；极值样本；低位填充非零；
  - `fl32` / `FL32` / `fl64` / `FL64`：有限值、±0、次正规数、±∞、NaN（含载荷）；期望值为写入的位模式本身；
  - SSND `offset` ≠ 0、可选块与未知块，与 `NONE` 夹具相同的结构变化；
  - 拒绝：`fl32` 的 `sampleSize` ≠ 32、`fl64` 的 ≠ 64、`raw ` / `in24` 等仍为扩展。
- **第二参考**：ffmpeg 对 `twos`（全部位数）、`sowt` 16 位、`fl32`、`fl64` 逐样本（浮点逐位）比较。
- ffmpeg 写出的真实文件（`-c:a pcm_s16le -f aiff` 得 `sowt`，`pcm_f32be`、`pcm_f64be` 得 `fl32`、`fl64`）作为回归样例。

## 3. 验收

1. 全部夹具与独立参考逐样本（浮点逐位）一致；ffmpeg 能读的与第二参考一致；拒绝情形的类别与明细与期望相同；
2. 任意分块结果相同；`qy-testkit` 契约测试覆盖新类型；
3. 浮点：严格路径在接受同一浮点格式的设备上按位输出；不接受时严格路径拒绝，开启浮点转整数后与独立参考一致（沿用 F3 的测试方法，模拟宿主与 A 层回环）；
4. fuzz：`aiff_decode` 与 `auto_decode` 语料加入新类型，冒烟运行并记录次数；Kani 证明更新；
5. 模拟宿主：新类型与 WAV、FLAC、AIFF `NONE` 混排，设备字节逐字节等于独立参考；
6. no_std（thumbv7em）构建与 Clippy；三个配置档预算不变（或记录增量）；QEMU 演示照常通过；
7. 文档 [docs/f5-aifc-variants.md](../docs/f5-aifc-variants.md) 记录出处、规则与已知限制；F2、F3 文档中“规范之外的扩展”的说明同步更新。
