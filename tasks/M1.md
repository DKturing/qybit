# QyFi M1：自有推送式 FLAC 与宿主切片

前置：M0 通用验证和 Windows WAV 链路完成。遵循 AGENTS.md，自行实现 qy-codec-flac。以 RFC 9639 为规范，桌面支持单/双声道、4–32 位整数 PCM、块大小最大 65535，编码帧还受下述输入窗口容量限制；MCU 使用明确的较小容量，超限报错。

## T1：统一缓冲接口

- 核心和 qy-codec-flac 保持 no_std/无 alloc，仅保存切片及小状态，不嵌入大定长数组；所有大型缓冲由宿主提供，不能漏掉输入窗口。
- 统一采用 `&'static mut [u8]`、`&'static mut [i32]`、`&'static mut [i64]`。输入窗口交给核心管理，解码工作区交给解码器管理，不共享重叠的可变借用；类型不带生命周期泛型。
- 桌面宿主启动时使用 `vec![0u8; n]` / `vec![0i32; n]` / `vec![0i64; n]` 转 boxed slice，再 Box::leak；整程序生命期复用，停止、换曲和重置不能重新分配或再次 leak。
- MCU 用 `static_cell::ConstStaticCell::new([0; N])` 定义静态零缓冲，使用 try_take 获取一次性可变引用并转切片；获取失败返回初始化错误。禁止运行时构造大数组再传给 StaticCell::init。
- 当前 ConstStaticCell 文档保证 const 初始化的大缓冲不占运行时栈；全零对象应放在 .bss，实际 MCU 的链接 map 仍需核验。固定依赖版本，核对 API 与目标平台要求。
- 构造时按声明容量检查切片长度，不足返回 CapacityExceeded。容量只依据宿主配置，不依据不可信头部动态分配；缓冲初始化全部 safe，不使用原地未初始化内存 API。

桌面初始容量：
| 缓冲 | 类型与长度 | 字节 |
| --- | --- | ---: |
| 帧输入窗口 | u8 × 1048576 | 1048576 |
| 解码/预测/解相关工作区 | i64 × (2×65535) | 1048560 |
| 最终交错 PCM | i32 × (2×65535) | 524280 |

另列 SPSC 和其他小状态开销；工作区可复用，但不得用 unsafe 重解释切片。约 512 KiB 只描述最终 PCM/verbatim 帧的量级，不是全部合法编码帧的上界；本配置承诺支持编码帧 ≤1 MiB，超过返回容量错误。

验收：debug 构建，在显式 256 KiB 栈的桌面测试线程内完成上述 safe 堆分配、核心/解码器构造、最大块解码与多次重置/换曲；测试夹具也从文件/堆读取，不在栈上生成大数组。验证 core/decoder 结构体不包含随块大小增长的内嵌存储、复用无新增分配、容量不足返回错误；“不崩溃”不等于精确测得最大栈。MCU 小容量配置 no_std 编译通过，实机 RAM/性能另验。

## T2：整帧解析与有界重试

- 本阶段保留整帧输入窗口；每次实际尝试都从帧头重新解析，不保存 Rice/子帧的比特级暂停状态。只有 CRC 验证通过才发布该帧 PCM，失败尝试写入的工作区不对外可见。
- 缺输入时记录下一次尝试阈值 retry_at；按本次尝试时已缓冲长度 n 几何增长，至少为 2n（检查溢出，且大于 n），并封顶到窗口容量。输入未达阈值且未 EOF 时直接返回 NeedInput，不重新解析；retry_at 是重试门槛，不冒充精确帧长度。
- 达到窗口容量后仍缺输入，返回 CapacityExceeded；源 EOF 时绕过阈值执行至多一次最终解析，完整短尾帧成功、截断帧明确报错。成功后按实际帧长度消费，保留后续帧字节并重置重试门槛；已解码等待输出空间时不重解该帧。
- STREAMINFO 的最大帧字节数非零时先做容量检查；为 0 表示未知，继续有界累积并检查实际帧长度。元数据不能直接信任，实际块/声道/位深/帧长度仍需检查。无需使用的元数据分块跳过，不整块缓存封面。
- 实现元数据、帧/子帧、常量/verbatim、固定预测、LPC、Rice 残差、wasted bits、声道解相关和 CRC 检查；记录对应 RFC 章节。
- 区分 NeedInput、NeedOutput、End、输入错误与容量超限；输入耗尽不能伪装 EOF，未完整帧不能发布部分音频。
- 32 位音源的 side 子帧可需要 33 位；以 i64 工作区处理预测/残差/还原并做范围检查，最终样本验证后输出 i32，不能截断。
- 超出支持范围明确报错，不降精度、改声道或绕过容量检查。

验收：覆盖最大块 verbatim、32 位 side 极值、各编码分支、随机分块、截断/CRC 错误、最大帧长度未知、谎报容量、窗口刚好够/不足；超出窗口的有效编码帧返回容量错误。另覆盖 EOF 前未达 retry_at 的完整短帧、截断尾帧、连续两帧的门槛重置和 NeedOutput 无重复解码。

对逐字节喂入一个 F 字节完整帧，记录实际解析调用次数、累计输入重扫描字节/位数及样本运算量；调用次数应为 O(log F)，累计输入扫描量为 O(F)，不能只测墙钟时间。样本重建另按样本数量记录，避免把高度压缩帧的输出成本算成输入扫描；最大块约 500 KiB 夹具必须满足明确的重试次数/扫描常数界。所有支持样本与独立参考逐样本一致。

统计字段、更新代码与查询接口放在 `#[cfg(any(test, feature = "test-metrics"))]` 后；test-metrics 默认关闭，正式发布不得启用，正式构建不含计数器。跨 crate 的集成测试显式启用 qy-codec-flac/test-metrics，不能假设依赖库自动获得 cfg(test)。统计只使用 core 整数/类型，不引入 std 或 alloc；该 feature 开/关都要通过 no_std 目标检查。

## T3：参考工具与接入

- 32 位夹具使用 Xiph flac ≥1.4.0 生成；固定工具版本，记录生成命令、种子、夹具摘要，并检查实际 block size/bit depth/编码分支，不假设命令选项必然产生目标分支。
- 32 位解码参考使用支持该格式的 libFLAC/flac -d，输出明确有符号、位深、字节序的原始 PCM，与已知原始 PCM 和自有解码结果比较；不用 claxon 作为 32 位唯一参考。
- claxon 只用于已验证支持的夹具；其错误或缺少特性不得被当作待测解码器通过的依据。特殊位深/分支无法用命令行工具生成时，采用独立规范夹具并注明来源。
- 将真实 FLAC 解码器接入 qy-host-sim 与桌面播放，复用 M0 代次、背压、drain 和 pack；最大块、随机分块、故障模拟与 fuzz 记录种子和时长。
- 固定一套泄漏一次的工作区反复重置，禁止模拟测试每首曲目泄漏一套。多个实例的并发测试各有独立非重叠工作区。

验收：qy-codec-flac 与核心 no_std 编译、自动测试通过；Windows 支持格式的 ignored 真机测试运行并记录，未运行明确标记。M2 再加入 ALSA/snd-aloop。

参考：RFC 9639 §8.2、附录 A.2；static_cell 当前 ConstStaticCell 文档；Xiph FLAC 1.4.0 发布说明。实现时核对所锁定版本。
