# QyBit W1：真实世界 WAV 的容错与 8 位 PCM

遵循根目录 AGENTS.md。顺序：用户确定与 FORMATS 路线一起排（2026-10-14），具体位置见 [tasks/FORMATS.md](FORMATS.md)。

**目标**：真实世界的 WAV 文件头经常不规范，例如流式录音留下的占位长度、写错的 RIFF 长度、不完整的尾帧。这类文件在意图明确时应能正确播放，且报告写明做了哪项修正。同时补上无损的 8 位 PCM。

**原则**：

- **只在意图没有歧义时容错**。每条规则都有真实来源（常见写入程序的已知行为），并写明依据；
- **只修正结构，不改样本、不编造样本**。修正只影响“读到哪里为止”和“丢弃不完整的尾部”，样本值来自文件原样；
- **每次修正都报告**。解码器给出修正明细（如 `WavFix::RiffSizeMismatch { declared, actual }`），播放报告写明“按规则 X 修正：…”。报告只写“软件路径无损”，不宣称文件本身完好；
- **有歧义的情况照旧拒绝**。例如 blockAlign 与位宽、声道数矛盾，fmt 字段互相冲突，多个 data chunk；
- 现有 `Malformed` / `Truncated` 的分类保持不变，只把下列明确情形改为可播放并报告修正。现有夹具的期望如有变化，逐项写明依据。

## 1. 容错规则（候选，实现前逐条核对真实样例）

| 编号 | 情形 | 常见来源 | 处理 |
| --- | --- | --- | --- |
| R1 | RIFF 长度为 0 或 0xFFFFFFFF | 流式写入程序（输出到管道、录音时先写占位），未回填 | RIFF 视为延伸到文件末尾 |
| R2 | data 长度为 0 或 0xFFFFFFFF，且 data 是最后一个 chunk | 同上 | data 视为延伸到文件末尾，按整帧读取，丢弃不足一帧的尾部 |
| R3 | RIFF 长度与文件实际长度不符，但 data 的声明长度在文件内完整 | 写入程序长度计算错误（例如差 8 字节） | 以 data 的声明长度为准；不再因“chunk 越出 RIFF”整首拒绝 |
| R4 | data 长度不是 blockAlign 的整数倍 | 录音中断、写入程序错误 | 播放全部完整帧，丢弃不完整的尾帧并报告丢弃的字节数 |
| R5 | data 声明长度超过文件实际长度 | 录音中断（文件被截断） | 现状已播放完整帧后报 `Truncated`；保持，但报告注明“文件比声明短 N 字节” |

**不纳入**（仍拒绝，理由写入记录）：

- fmt 中 blockAlign、位宽、声道互相矛盾：无法确定哪个字段正确；
- data 出现在 fmt 之前、重复的 fmt/data：意图不明；
- 无法确定 data 边界、又不是最后一个 chunk 的占位长度：后续 chunk 会被当作样本。

## 2. 8 位 PCM

- WAVE 规范的 8 位 PCM 为无符号，偏移 128。解码时减去 128，得到有符号 8 位（N = 8），是精确的整数表示变换，不改变样本的值域与相对幅度；
- 设备格式不变：N = 8 ≤ V 的设备格式按 pack 规则放置；
- 8 位 EXTENSIBLE（V < 8 的情形）同样处理有效位；
- 夹具含 0、128、255 等极值，独立参考由生成器直接构造，ffmpeg 第二参考核对。

## 3. 夹具与参考

- **生成器**（`tools/qy-gen-fixtures`）：为每条规则构造夹具，并给出期望的样本与修正明细；ffmpeg 作为第二参考，对 ffmpeg 同样能读取的情形逐样本比较；
- **真实来源样例**：收集各写入程序的实际输出头部（例如 ffmpeg 输出到管道、arecord 中断录音、常见录音软件），只取头部结构，样本由生成器重新构造，不把第三方音频放进仓库；
- **边界**：
  - 每条规则的“刚好成立”与“刚好不成立”；
  - 任意分块；
  - 修正与已有拒绝情形的组合。

## 4. 验收

1. 各规则夹具与独立参考逐样本一致，修正明细与期望相同；
2. 不纳入的情形仍按原分类拒绝；
3. WAV 1000 种子模拟摘要：现有夹具池不变（新夹具另建场景）；
4. fuzz 10 分钟（扩展语料含新夹具），记录种子；
5. 模拟与桌面报告写明修正；嵌入式 `status` / 通知给出修正计数；
6. 配置档预算不变：容错不需要额外缓冲。

## 5. 范围外

- RF64 / BW64（超过 4 GB 的录音与广播文件）：涉及 64 位长度与 ds64 chunk，另列；
- 浮点 WAV：见 FORMATS 的 F3；
- 修复文件（写回磁盘）：只读播放，不改文件。
