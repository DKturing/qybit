# QyBit F2：AIFF / AIFF-C（未压缩 PCM）

遵循根目录 AGENTS.md。顺序见 [tasks/FORMATS.md](FORMATS.md)：W1 之后。

状态：**已完成**，记录见 [docs/f2-aiff.md](../docs/f2-aiff.md)。审定于 2026-10-14。用户决定：Core 最严格，不符合规范的拒绝，但保留以后扩展的能力；嵌入式配置档启用 AIFF；长度不一致先严格，再逐条加。

**目标**：自行实现 AIFF 与 AIFF-C（未压缩）解码，按现有 `Decoder` 契约（交错右对齐 `i32` + 有效位 N）接入，桌面、模拟与嵌入式宿主共用，严格路径不改变样本。

## 0. 规范出处（已核对原文）

| 文档 | 来源与校验 |
| --- | --- |
| Apple《Audio Interchange File Format: "AIFF" — A Standard for Sampled Sound Files》Version 1.3，1989-01-04 | 用户提供的 PDF，31 页，SHA-256 `56902eb9a5410adcde5f928830b26234442070e0ab1f047f564b23af84067e0a` |
| Apple《Audio Interchange File Format AIFF-C — A revision to include compressed audio data》草案，正文日期 1991-08-26（文件名与 PDF 标题为 9/26/91） | 用户提供的 PDF，45 页，SHA-256 `04417236851b4e5a9c792d144ed6aa73e9154553c60369de3d9919dcf20845bd` |

两份是 Apple 的版权文档，只记录出处与校验值，不放入仓库。下文“AIFF §x”指 AIFF 1.3 正文的相应小节，实现时逐条在代码注释中引用。

## 1. 原则

- 与 WAV、FLAC 相同：`no_std`、无 alloc、调用级可暂停、任意分块；不可信输入不 panic；
- **只接受规范定义的内容**。拒绝分三类，报告里写清是哪一类：
  - **不合规**（`Malformed` / `Truncated`）：违反规范的“必须”，例如缺少 COMM、长度越界；
  - **合规但本程序尚不支持**（`Unsupported` + 明细）：规范允许，但现在没有实现，例如 SSND 在 COMM 之前；
  - **规范之外的扩展**（`Unsupported` + 明细）：后来的写入程序加的类型，例如 `sowt`。
- **保留扩展能力**：
  - 每类拒绝都有独立的明细枚举项，以后加支持时只把对应项改为可播放，不改其他情形；
  - 规范之外的扩展要单独列出出处，再逐项加入（同 W1“先严格，再逐条加”）。

## 2. 容器（AIFF 与 AIFF-C 共同）

- **识别**：`FORM` + 4 字节长度 + 形式类型 `AIFF` 或 `AIFC`。`qy-codec-auto` 现在只看前 4 字节；`FORM` 也被其他 IFF 格式使用，因此改为读到 12 字节再按形式类型分派。其他形式类型照旧按“无法识别”拒绝并写明。
- **chunk**：大端长度，奇数长度后有 1 字节 0 填充（不计入长度）。chunk 越出 FORM 声明的范围即不合规。
- **必需的 chunk**：
  - COMM：有且只有一个；
  - SSND：最多一个；`numSampleFrames` > 0 时必需；
  - AIFF-C 另需 FVER：有且只有一个，`timestamp` 为 `0xA2805140`（AIFCVersion1），其他值按“尚不支持的版本”拒绝；
  - 重复的 COMM / SSND / FVER 不合规。
- **其余 chunk**：规范定义的可选 chunk（MARK、INST、MIDI、AESD、APPL、COMT、NAME、AUTH、`(c) `、ANNO，AIFF-C 另有 SAXL）以及未知 chunk 都跳过，不影响样本。
- **chunk 顺序**：规范规定 FORM 内 chunk 的顺序没有限制（AIFF §Chunks）。
  - SSND 在 COMM 之前是**合规**的。按顺序读取时，读到 SSND 还不知道格式；
  - 第一阶段按“合规但尚不支持”拒绝，明细写明原因；
  - 扩展方案记录在案：引擎新增“从头重开曲目”的动作（新增接口，不破坏冻结接口），先跳过 SSND 找到 COMM，再从头读取。实测真实文件中这种情况常见时再实施。

## 3. COMM 与 SSND

- **COMM**：`numChannels`（i16）、`numSampleFrames`（u32）、`sampleSize`（i16）、`sampleRate`（80 位 IEEE 754 扩展精度）。
  - AIFF-C 另有 `compressionType`（4 字节）与 `compressionName`（Pascal 字符串，总长为偶数，按需加 1 字节填充）。
  - `numChannels` ≥ 1、`sampleSize` 为 1–32，否则不合规。
- **采样率**：80 位扩展精度精确换算为整数，必须为正、是整数、能放入 `u32`，否则按“尚不支持的采样率”拒绝并给出原值。不四舍五入。
- **帧数以 COMM 为准**：规范规定样本帧数应从 COMM 的 `numSampleFrames` 取得，而不是 SSND 的长度（AIFF-C §Number of Sample Frames）。
  - SSND 数据 = `offset` 字节（跳过，不是样本）+ `numSampleFrames` × 每帧字节；
  - SSND 声明长度不足以容纳这些数据：不合规；
  - 文件在数据结束前截断：`Truncated`；已解码的完整帧照常输出；
  - SSND 中帧数据之后剩余的字节（块对齐填充）：按规范不属于样本，跳过；
  - `blockSize` 只是对齐提示，不影响解码。
- **长度不一致**：先严格，再逐条加（同 W1）。COMM 与 SSND 矛盾、FORM 长度与文件不符等情形，第一阶段都按上面的规则拒绝；以后找到真实写入程序的样例、意图没有歧义时，再逐条加入容错规则，每条报告修正。

## 4. 样本

- **位数**（AIFF §Sample Points）：
  - 每个样本点是线性补码，宽 1–32 位，N = `sampleSize`；
  - 1–8 位占 1 字节，9–16 位占 2 字节，17–24 位占 3 字节，25–32 位占 4 字节，大端；
  - 不是 8 的整数倍时有效位左对齐，剩余低位“置零”。解码时算术右移取出 N 位并保留符号。低位填充不属于样本值，与 WAV 的处理相同：丢弃，不影响 N 位样本；
  - 8 位同样是补码，与 WAV 的无符号 8 位不同，不做偏移。
- **AIFF-C 的 `compressionType`**（AIFF-C 原文只定义了以下五种）：

| 类型 | 规范含义 | 处理 |
| --- | --- | --- |
| `NONE` | 未压缩，与 AIFF 相同 | 支持 |
| `ACE2` / `ACE8` | Apple IIGS ACE 压缩 | 拒绝：压缩类型 |
| `MAC3` / `MAC6` | Macintosh MACE 压缩 | 拒绝：压缩类型 |

- **规范之外的类型**：后来由 QuickTime / Core Audio 引入，不在 AIFF-C 原文中。第一阶段按“规范之外的扩展”拒绝，明细写明类型码：
  - 小端 `sowt`；
  - 大端 `twos`；
  - 无符号 8 位 `raw `；
  - 浮点 `fl32` / `fl64` / `FL32` / `FL64`；
  - `ulaw` / `alaw` / `ima4` 等。

  其中 `sowt`、`twos` 实际很常见。用户 2026-10-15 决定不进 Core，以后作为插件考虑（浮点属于 F3）。**2026-10-18 用户改为纳入基础格式**：`twos`、`sowt`、`fl32`/`fl64` 由 [F5](F5.md) 实现。
- **声道布局**（AIFF §Sound Data Chunk 的多声道约定）：

| 声道数 | 规范约定 | 处理 |
| --- | --- | --- |
| 1 | 单声道 | `[FC]` |
| 2 | 左、右 | `[FL FR]` |
| 3 | 左、右、中 | `[FL FR FC]` |
| 4 | 规范给出两种互相冲突的约定：quad 为前左、前右、后左、后右；“4 channel”为左、中、右、环绕 | 拒绝：布局有歧义 |
| 6 | 左、左中、中、右、右中、环绕；单个“环绕”声道对应哪个扬声器位置，规范没有说明 | 拒绝：布局有歧义 |
| 5、7 及以上 | 规范没有约定 | 拒绝：未定义布局 |

  这些约定在规范中用的是“应遵守”。接受的布局按扬声器位置送到设备（F1 的纯置换）。被拒的布局以后若有可靠依据（如 APPL chunk 中的声道布局），作为扩展另行加入。

## 5. 接入

- **新 crate `qy-codec-aiff`**：`no_std`、无 alloc，工作区与 WAV 解码器相同（`PCM_WORK_SAMPLES`）。
- **`qy-codec-auto` 新增特性 `aiff`**，默认开启。只开 `wav` 或 `flac` 的构建不链接它。
- **配置档**：Desktop、Embedded Full、Embedded Lite 都启用 AIFF（用户决定）。AIFF 与 WAV 的缓冲需求相同，不增加 RAM；`.text` 增量以实测记录。
- **报告**：拒绝明细（`AiffDetail`，区分不合规、尚不支持、规范之外的扩展）进入实时输出、播放报告与 `qybit decode`，写法与 WAV 一致。

## 6. 夹具与参考

- **生成器**（`tools/qy-gen-fixtures`，纯 Rust）：
  - 构造 AIFF / AIFF-C 夹具，并独立给出期望样本；
  - ffmpeg 作为第二参考，对它能读取的情形逐样本比较；
  - 不放第三方音频。
- **覆盖**：
  - 1、8、12、16、20、24、32 位；单声道、双声道、3 声道；
  - 44.1k、48k、96k、192k 与非常见整数采样率；
  - AIFF 与 AIFF-C `NONE`；
  - 极值样本，低位填充非零；
  - SSND `offset` ≠ 0，帧数据之后有剩余字节；
  - 可选 chunk 与未知 chunk，奇数长度 chunk 的填充，`compressionName` 的奇偶长度；
  - 拒绝情形：
    - 不合规：缺 COMM、重复 COMM / SSND / FVER、FVER 版本不符、chunk 越界、SSND 长度不足；
    - 截断；
    - 尚不支持：SSND 在 COMM 之前、非整数或超范围采样率；
    - 规范之外的扩展：`sowt`、`twos`、`raw `、`fl32` 等；
    - 压缩类型：`MAC3` 等；
    - 布局：4、6 声道（歧义）与 5 声道（未定义）。

## 7. 验收

1. 全部夹具与独立参考逐样本一致；ffmpeg 能读的与第二参考一致；拒绝情形的类别与明细与期望相同；
2. 任意分块（1 字节、随机、整块）结果相同；
3. fuzz：新目标 `aiff_decode` 10 分钟，并加入 `auto_decode` 语料，记录种子与次数；
4. 模拟宿主：AIFF 曲目与 WAV、FLAC 混排，种子 × 两种设备模型，设备字节逐字节等于独立参考；
5. A 层回环（ALSA file 插件）逐字节比对；
6. no_std 构建（thumbv7em）与 Clippy；三个配置档的预算不变，`.text` 增量记录；QEMU 演示照常通过；
7. 文档记录规范出处、各类型与布局的处理和已知限制。
