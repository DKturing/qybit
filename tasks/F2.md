# QyBit F2：AIFF / AIFF-C（未压缩 PCM）

遵循根目录 AGENTS.md。顺序见 [tasks/FORMATS.md](FORMATS.md)：W1 之后。

状态：**草案，待用户审定后实施**。

**目标**：自行实现 AIFF 与 AIFF-C（未压缩）解码，按现有 `Decoder` 契约（交错右对齐 `i32` + 有效位 N）接入，桌面、模拟与嵌入式宿主共用，严格路径不改变样本。

**原则**：

- 与 WAV、FLAC 相同：`no_std`、无 alloc、调用级可暂停、任意分块；不可信输入不 panic；
- 规范出处实现前逐条核对原文：Apple《Audio Interchange File Format: "AIFF"》1.3（1989）与《AIFF-C》草案（1991）。无法取得原文时，以 ffmpeg（`libavformat/aiffdec.c`）与 libsndfile 源码交叉核对，并在记录中写明依据来自哪里；
- 有歧义就拒绝并写明原因；不为个别写入程序写特例。

## 1. 容器

- **识别**：`FORM` + 4 字节长度 + 形式类型 `AIFF` 或 `AIFC`。`qy-codec-auto` 现在只看前 4 字节；`FORM` 也被其他 IFF 格式使用，因此改为读到 12 字节再按形式类型分派。其他形式类型照旧按“无法识别”拒绝并写明。
- **chunk**：大端长度，奇数长度后有 1 字节填充。需要 `COMM` 与 `SSND`，AIFF-C 还要求 `FVER`。其余 chunk（`NAME`、`AUTH`、`ANNO`、`(c) `、`ID3 `、`MARK`、`INST`、`COMT`、`APPL` 等）跳过，不影响样本。
- **COMM**：
  - `numChannels`（i16）、`numSampleFrames`（u32）、`sampleSize`（i16）、`sampleRate`（80 位 IEEE 扩展精度）；
  - AIFF-C 另有 `compressionType`（4 字节）与 `compressionName`（Pascal 字符串，按偶数长度填充）。
- **采样率**：80 位扩展精度精确换算为整数，必须为正、是整数、能放入 `u32`，否则拒绝并给出原值。不四舍五入。
- **SSND**：`offset`（u32）、`blockSize`（u32），之后是样本数据。`offset` 跳过的字节不是样本；`blockSize` 只是对齐提示，不影响解码。
- **COMM 在 SSND 之后**：规范允许 chunk 任意顺序。实现必须支持 SSND 在 COMM 之前，但不能缓存整个 SSND。方案（实现前定）：
  - 甲：遇到 SSND 在前时按“需要格式”拒绝；
  - 乙：宿主重新定位读取。宿主接口目前没有 seek，这会改变冻结接口，因此先选甲，并核对真实文件中这种情况是否常见。
- **长度一致性**：`numSampleFrames × 每帧字节` 与 SSND 实际数据长度不符时的处理，按 W1 的思路逐条定义，实现前核对真实样例。没有真实来源的情形不容错，按 `Malformed` / `Truncated` 拒绝。

## 2. 样本

- **位数**：`sampleSize` 为 1–32 时，N = `sampleSize`，每样本占 `ceil(N/8)` 字节。规范规定有效位左对齐、低位填 0，解码时算术右移取出 N 位并保留符号。
- **AIFF 的 8 位是有符号的**，与 WAV 不同，不做偏移。
- **AIFF-C 的 `compressionType`**：

| 类型 | 含义 | 处理 |
| --- | --- | --- |
| `NONE` | 大端有符号 PCM，同 AIFF | 支持 |
| `twos` | 大端有符号 PCM（QuickTime） | 支持（核对与 `NONE` 等价） |
| `sowt` | 小端有符号 PCM | 支持（核对位数范围，常见为 16 位） |
| `raw ` | 8 位无符号，偏移 128 | 支持：与 WAV 8 位相同的精确转换 |
| `fl32` / `FL32` / `fl64` / `FL64` | 浮点 | F3 范围，现在按“不支持”拒绝并写明 |
| `ulaw` / `alaw` / `ima4` 等 | 压缩或有损编码 | 拒绝并写明类型 |

- **声道布局**：
  - 1 声道为单声道 `[FC]`，2 声道为 `[FL FR]`；
  - 多于 2 声道时，AIFF 1.3 给出了部分声道数的扬声器顺序（实现前逐项核对原文）。能映射到 WAVE 扬声器位置的才接受，映射后按 F1 的规则送到设备；
  - 无法确定位置的（例如规范未定义的声道数，或顺序与位置无法一一对应）按“未定义布局”拒绝。

## 3. 接入

- **新 crate `qy-codec-aiff`**：`no_std`、无 alloc，工作区与 WAV 解码器相同（`PCM_WORK_SAMPLES`）。
- **`qy-codec-auto` 新增特性 `aiff`**，默认开启。只开 `wav` 或 `flac` 的构建不链接它。
- **配置档**：Desktop 启用 AIFF。Embedded 是否启用由预算决定：AIFF 与 WAV 的缓冲需求相同，预计不增加 RAM，以实测的 `.bss` 与栈为准。
- **报告**：拒绝明细（`AiffDetail`）进入实时输出、播放报告与 `qybit decode`，写法与 WAV 一致。

## 4. 夹具与参考

- **生成器**（`tools/qy-gen-fixtures`，纯 Rust）：
  - 构造 AIFF / AIFF-C 夹具，并独立给出期望样本；
  - ffmpeg 作为第二参考，对它能读取的情形逐样本比较；
  - 不放第三方音频。
- **覆盖**：
  - 8/12/16/20/24/32 位，单声道、双声道、多声道；
  - 44.1k、48k、96k、192k 及非常见整数采样率；
  - `NONE`/`twos`/`sowt`/`raw ` 各一组；
  - 极值样本，低位填充非 0 的情形；
  - SSND `offset` ≠ 0；
  - chunk 任意顺序（COMM 在 SSND 之前或之后）；
  - 奇数长度 chunk 的填充；
  - 未知 chunk、`ID3 ` chunk；
  - 非整数或超范围的采样率、浮点类型、压缩类型、未定义的多声道布局。

## 5. 验收

1. 全部夹具与独立参考逐样本一致；ffmpeg 能读的与第二参考一致；拒绝情形的分类与明细与期望相同；
2. 任意分块（1 字节、随机、整块）结果相同；

4. 模拟宿主：AIFF 曲目与 WAV、FLAC 混排，种子 × 两种设备模型，设备字节逐字节等于独立参考；
5. A 层回环（ALSA file 插件）逐字节比对；
6. no_std 构建（thumbv7em）与 Clippy；MCU 配置档的预算与明确拒绝；QEMU 演示照常通过；
7. 文档记录规范出处、各类型的处理与已知限制。
