# QyBit X1：外部扩展示例与接口契约测试

遵循根目录 AGENTS.md。来源：2026-10-16 外部架构评估（“现在最缺的不是 PluginManager，而是证明第三方真的能接入”）。顺序：B1（[B1.md](B1.md)）与 L1（[L1.md](L1.md)）之后。

状态：**草案，待用户审定**。

**目标**：用一个仓库外部视角的示例证明，扩展只需实现接口并在组装层接入，不修改核心状态机。同时把各接口的契约写成文档和可复用的测试。短期只做编译期扩展；运行时动态插件以后在桌面宿主外层另行设计，不让 MCU 核心承担加载与版本协商的成本。

## 1. 扩展点（现有接口，本卡不改它们）

| 接口 | 所在 | 扩展什么 |
| --- | --- | --- |
| `Decoder`（M0 起冻结）+ `Resources` | `qy-core` | 新的音频格式 |
| `FrameSink` / `FrameSource` | `qy-pcm-format` | 帧队列（例如另一种无锁队列或 DMA 双缓冲） |
| `Backend`、`TrackSource` | `qy-player` | 桌面输出后端、音源（文件之外，如内存、网络缓存） |
| `Storage`、`AudioOutput` | `qy-host-embedded` | MCU 的存储介质与输出外设 |

## 2. 示例 crate：`examples/qy-ext-demo`

示例 crate 不发布，不进入 Embedded 配置档。它只依赖公开接口，不改任何 `qy-*` crate 的源码；需要改动时，说明扩展点不完整，记入 §5 再单独处理。示例包含三部分：

- **示例格式解码器**：一个只为示例定义的极简格式“QYT1”：
  - 头部为魔数、采样率、声道数、位数与帧数，之后是小端整数 PCM；
  - 实现 `Decoder` + `Resources`；
  - 定位：支持（按字节计算）与不支持两种构造，用来验证核心的定位降级；
  - 它不是要支持的生产格式，不进入 `qy-codec-auto`（新的生产格式仍按 FORMATS 路线单独立卡）。
- **组装**：在组装层把示例解码器与 `AutoDecoder` 组合成一个解码器。按文件头选择：魔数为 QYT1 时用示例解码器，否则交给 `AutoDecoder`。用它构建桌面 `Engine` 与嵌入式 `Player`。
  - B1 之后 `HostResources` 能否接收自定义解码器，在本卡中核对；不能时，改为泛型或增加接收已组装引擎的构造，这一改动属于组装层。
- **内存音源与无硬件输出**：
  - `TrackSource` 的内存实现；
  - 一个按真实时间或虚拟时间消费的 `Backend`，不访问硬件，记录收到的字节。
- **场景**：通过现有核心完成以下各项，输出与独立参考逐字节一致：
  - 播放、暂停与恢复、切歌、停止；
  - 定位，以及解码器不支持定位时的顺序解码降级；
  - 解码错误按出错策略跳过；
  - 示例格式与 WAV / FLAC 混排。

## 3. 接口契约（文档 + 可复用测试）

在 [docs/arch-core-mcu.md](../docs/arch-core-mcu.md) 增加“扩展契约”一节，并提供可复用的契约测试（`qy-testkit`，只作 dev-dependency；或 `qy-core` 的 `testkit` 特性），对任意解码器检查：

- **缓冲所有权**：
  - 工作区由宿主提供，`reset` 后复用，不重新分配；
  - `pcm()` 返回的切片在 `release` 或下一次 `decode` 之前有效。
- **状态语义**：
  - `NeedInput` 与 `End` 不混用；
  - `eof` 为真之后不得再返回 `NeedInput`；
  - 零产出不能同时表示缺输入与结束。
- **分块无关**：一次性、逐字节与随机分块输入的样本、格式、错误明细都相同（现有 WAV / FLAC / AIFF 的同类测试改用这个工具）。
- **格式**：头部解析完成前 `format()` 为 `None`，不伪造。
- **错误后**：出错后在 `reset` 之前不得再产出样本；`reset` 后可以解码下一个源。
- **定位**：默认不支持时核心顺序降级；支持时只输出目标帧及之后的样本。
- **停止后的迟到事件**：由核心按代次拒绝，扩展不需要处理。这一条写进文档，测试中用假宿主注入迟到回报来验证。

`FrameSink` / `FrameSource`、`Backend`、`Storage` 与 `AudioOutput` 同样各列一张契约表：谁拥有缓冲、短写或整包的语义、返回 0 的含义、错误后能否继续。

## 4. 验收

1. 示例 crate 只用公开接口构建，在 CI 中构建与测试；`qy-*` 源码没有为示例而改（如有，逐项列出原因）。
2. §2 的全部场景在桌面假后端与嵌入式虚拟时间仿真中通过，逐字节核对。
3. 契约测试对现有 WAV、FLAC、AIFF 与示例解码器全部通过；故意违反契约的解码器（测试内构造，例如 EOF 后返回 `NeedInput`）被契约测试发现。
4. 文档写明各扩展点的契约与组装方法。

## 5. 待决定

1. **示例格式**：**建议**用测试专用的 QYT1，避免把一个真实格式的半成品放进仓库。另一种做法是用已有格式的子集（例如只读 16 位 PCM 的 WAV），但那样无法证明“新格式不改核心”。
2. **契约测试的位置**：**建议**单独的 `qy-testkit` crate（只作 dev-dependency），避免给 `qy-core` 增加测试用特性。
