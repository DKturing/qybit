# QyBit M2：Linux ALSA 严格输出与数字回环

遵循根目录 AGENTS.md。前置：M0、M1 自动验收完成。目标：抽出与平台无关的播放器层，实现 ALSA 直连 `hw` 设备的严格输出，用 alsa-lib `file` 插件与 snd-aloop 两层数字回环自动验证软件路径逐字节一致；同时用模型检查、变异测试与场景 fuzz 加强已有核心验证。

范围：Linux ALSA 播放、顺序多文件、CLI；WAV/FLAC 沿用 M1 自动识别。不做 PipeWire/PulseAudio 后端、GUI、seek、随机播放、配置保存、交互设备选择；macOS 与 MCU 实机另列任务。

依赖：ALSA 绑定使用 `alsa` crate（封装系统 alsa-lib），是平台 API 绑定，与 WASAPI 使用 `windows` crate 同类；版本在实现时核对并锁定，`unsafe`/FFI 边界单独审计。构建需要 libasound 开发包，CI 与 README 写明。不使用 cpal 等通用音频库（不保证独占、不保证不转换格式）。

## T1：平台无关播放器层

- 新建 `qy-player`（std 库）：把 `qy-host-wasapi` 中与平台无关的部分迁入，包括播放驱动、`Backend`/`PendingStream`/`RunningStream` trait、宿主资源、渲染循环、报告与摘要、假后端测试设施。
- 后端 trait 要能表达两类提交语义：要求整包的后端（WASAPI 事件周期）和支持短写的后端（ALSA `writei`）。实际消费、欠载/xrun、尾部填充与排空分开计数，不重复提交有效帧。
- 协商记录统一区分四项：请求格式、协商结果、可查询的已应用参数、回录证据（M2 T4 填写）。WASAPI 的 `GetMixFormat` 仍不得冒充独占流格式。
- `qy-host-wasapi` 只保留 Windows 绑定与 WASAPI 特有逻辑，依赖 `qy-player`。CLI 按目标平台选择后端，命令语法不变。
- 核心 `Action`/`Event`/`Decoder` 保持冻结；本卡只移动和泛化宿主层代码，不改变播放行为。

验收：
- M0/M1 全部 WASAPI 假后端测试迁移后逐字节通过，未删除、未弱化；Windows 目标测试通过（CI 与本地 wine）。
- 新增一个“短写后端”假实现，在 `qy-player` 测试中覆盖：部分提交、零提交、xrun 恢复、EOF 排空；有效字节由独立公式计算。

## T2：ALSA 格式映射与参数确认（纯逻辑）

- 在 `qy-pcm-format` 中加入 ALSA 格式映射（no_std、不依赖 alsa-lib）。本阶段支持以下小端整数格式：

  | ALSA 格式 | 容器 C | 有效位 V | 放置方式 |
  | --- | --- | --- | --- |
  | `S16_LE` | 16 | 16 | — |
  | `S24_3LE` | 24 | 24 | — |
  | `S24_LE` | 32 | 24 | 低 24 位、符号扩展（`Placement::LsbAligned`） |
  | `S32_LE` | 32 | 32 | — |

  大端格式与浮点格式明确不支持。
- 候选顺序：选择满足 N ≤ V 的最小 V；V 相同时按设备偏好排序。不选会改变样本的格式。
- 参数设置规则：
  - access 为 `RW_INTERLEAVED`；
  - 用 `set_rate_resample(false)` 禁用 alsa-lib 重采样；
  - 采样率与声道精确设置，不使用 `*_near` 接受近似值；
  - 设置后用 `hw_params_current` 读回已应用参数，格式、采样率、声道、period 与 buffer 必须与请求一致，否则明确报错。
- 设备名只接受 `hw:`。`plughw:`、`default`、`dmix`、`pipewire`、`pulse` 等会转换或混音的 PCM 一律拒绝，并说明原因。
- 设备忙（`EBUSY`，常见于 PipeWire/PulseAudio 占用）时明确报错并提示占用者，不回退到共享路径。

验收：
- 映射与候选选择的单元测试覆盖符号、极值与 N > V 拒绝；`S24_LE` 与 WASAPI 32/24 的打包结果互不相同，各自对照独立参考字节。
- 参数确认逻辑用假的“已应用参数”覆盖：近似采样率、被改写的格式、period 不一致，均须报错。
- `qy-pcm-format` 仍能编译到 thumbv7em。

## T3：ALSA 渲染后端与 CLI

- 新建 `qy-host-alsa`：Linux 目标编译 alsa 绑定，其余逻辑跨平台可测。
- 渲染线程规则不变：不解码、不 pack、不分配、不阻塞于生产端。每次唤醒按 `poll` 与 `avail` 搬运队列中的完整帧。
- `writei` 短写时保留未提交部分，下次继续提交。
- 返回 `EPIPE`（xrun）时：记录欠载（位置、缺失帧），用 `prepare` 恢复，并把该段标记为非完整保真。
- 返回 `ESTRPIPE`/`ENODEV` 等错误时：记录设备错误并停止。
- EOF 时用 `drain` 播完设备中剩余音频；只有已确认无后续数据，才允许补齐尾部静音周期并单独计数。
- 设置 `SCHED_FIFO` 等实时优先级只作尝试：结果写入报告，失败不阻止播放（同 WASAPI 的 MMCSS 处理）。
- CLI（Linux）：
  - `qybit list-devices` 列出 `hw:CARD=…,DEV=…`；
  - `qybit --device hw:… a.flac b.wav` 顺序播放；
  - `qybit matrix --device hw:…` 输出格式矩阵 JSON/CSV；
  - 退出码约定同 M0。

验收：
- 假 ALSA 后端（模拟 `avail`/短写/xrun/设备消失）的自动测试通过；渲染循环无分配（计数分配器验证）。
- 真机播放测试默认 `#[ignore]`，需要 `QYBIT_ALSA_DEVICE`；未运行须明确标记。

## T4：两层数字回环

同步与比对：
- 回环比对用已知同步序列对齐：测试先播放一段同格式的伪随机同步曲目，再无缝衔接待测曲目。
- 在回录中按同步序列定位起点，其后字节须与待测曲目的期望设备字节逐字节一致，包括曲目真实的前导静音与满幅尾帧；不得删除前导静音来凑对齐。

A 层：alsa-lib `file` 插件（不需要内核模块，任何 Linux CI 可跑）
- 测试生成临时 `asoundrc`：`type file` 写入文件，slave 为 `null`。
- 用它验证 pack 后提交给 alsa-lib 的字节流。
- 这一层不经过真实驱动，只证明软件路径提交正确。

B 层：snd-aloop（内核虚拟声卡）
- 由 `hw:Loopback,0,N` 播放，`hw:Loopback,1,N` 用同一格式回录。
- 覆盖 44.1/48/96/192 kHz × `S16_LE`/`S24_3LE`/`S24_LE`/`S32_LE` × 单/双声道。
- 格式与源格式各组合逐字节比对：N < V 时验证 pack 的左移或扩展；N > V 时设备选择阶段即须拒绝。
- 另测同格式多曲无缝衔接，以及不同格式换曲后重新打开。

记录与 CI：
- 每项记录请求格式、已应用参数、回录结果和比对结论。
- 报告中写明这是虚拟回环，不宣称真实 DAC 已验证。
- CI 尝试在 GitHub 托管 Ubuntu runner 上 `modprobe snd-aloop`：
  - 能加载则作为 CI 作业运行；
  - 不能加载则该作业明确标记为“未运行（runner 不支持内核模块）”，同时提供本地运行脚本与步骤，不得以 A 层结果冒充 B 层。

验收：A 层在 CI 运行通过；B 层按上述两种情况之一运行并记录（在 CI 或本地，附完整矩阵报告），未运行项明确列出。

## T5：验证加强（已完成）

> 2026-10-13 经用户同意延后，先进行 M3 T1；2026-10-15 完成，记录见 [docs/m2-t5-verification.md](../docs/m2-t5-verification.md)（Miri 下一个播放器测试因本环境内存不足未完成，见该文档 §5）。

- **Kani 模型检查**（版本锁定，单独作业）：对 no_std 纯函数做有界证明，至少覆盖：
  - `pack`：对所有 N ≤ V、所有放置方式与字节序，任意样本不 panic、无溢出，且解包后与原样本一致；
  - CRC-8/CRC-16 实现与按位参考定义等价（有界长度）；
  - WAV/FLAC 头部关键整数计算无溢出。

  记录证明边界与耗时；无法证明的项说明原因，不得删除断言来凑通过。
- **cargo-mutants**：对 `qy-pcm-format`、`qy-core`、`qy-codec-wav`、`qy-codec-flac`、`qy-codec-auto` 运行，记录总数、被杀数和存活数。逐个分析存活变异：补测试，或说明为等价变异。CI 定期运行（如每周），不阻塞每次提交。
- **场景 fuzz**：新增 fuzz 目标，由 libFuzzer 直接生成模拟宿主场景，包括曲目组合、读取模型、停顿、断开与重启时刻，用来补充固定种子。检查不变式：不 panic、不超时、不协议错误；正常场景逐字节一致，故障场景输出为期望前缀。运行至少 10 分钟并记录；CI 加冒烟。
- **Miri**：对 `qy-player` 中涉及的 `unsafe` 边界（如有）及纯 Rust 部分运行测试；FFI 部分不适用的明确标记。

验收：各项结果写入 docs/m2-t5-verification.md，附命令、版本、时长与存活/失败项处理结论。
