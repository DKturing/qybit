# QyBit A1：ALSA 内核直连与多架构静态程序

遵循根目录 AGENTS.md。来源：2026-10-17 用户要求 Linux 版“和系统无关”，并支持 x86_64 之外的架构（ARM、LoongArch 等）。排在 Linux 阶段最前：先让命令行版在任意发行版、任意支持的架构上直接运行，再做 Linux 图形界面（另立任务卡）。

状态：**软件部分已完成**（2026-10-17，记录见 [docs/a1-kernel-alsa.md](../docs/a1-kernel-alsa.md)）：验收 1（CI 构建、静态核对与构件上传，run 39058369531 通过）、4、5 已满足；验收 3 的 B 层逐字节回环已在 QEMU 虚拟机（Ubuntu 内核 + snd-aloop）中通过，用户机器上未运行；验收 2（用户机器真实声卡）未运行。审定（2026-10-17）：§6.1 用 musl；§6.2 x86_64、aarch64、armv7、loongarch64、riscv64 都做（用户写“armv7/8”：32 位 ARMv8 运行 armv7 程序，64 位 ARMv8 即 aarch64）；§6.3 选甲；§6.4 发布版不保留 alsa-lib 后端。

## 1. 现状与问题

- `qy-host-alsa` 经 `alsa` crate 调用 alsa-lib（`libasound.so.2`），并动态链接 glibc。精简系统上常没有 alsa-lib，程序无法启动；不同发行版、不同架构的库版本各不相同。
- 但 alsa-lib 只在一处：`pcm::Pcm` trait（打开、读写参数、读回、启动、停止、排空、等待、可写量、写入、声道映射）的真实实现 `linux::real::RealPcm`，以及 B 层回环的回录 `linux::capture`。协商、候选格式、读回核对、短写渲染循环、报告都在 trait 之上，与 alsa-lib 无关。
- QyBit 只用 `hw:` 设备，本来就不用 alsa-lib 的插件、混音与格式转换。

## 2. 做法：直接使用内核 ALSA 接口

依据：Linux 内核 `include/uapi/sound/asound.h`（用户空间接口，内核承诺向后兼容）与内核文档 *ALSA PCM interface*。实现时逐项记录出处与内核接口版本（`SNDRV_PCM_IOCTL_PVERSION`）。

- **新的 `Pcm` 实现 `KernelPcm`**：打开 `/dev/snd/pcmC{卡}D{设备}p`，用 ioctl 完成：
  - `HW_REFINE`：查询设备支持的格式、采样率、声道、周期与缓冲范围（替代 alsa-lib 的能力查询）；
  - `HW_PARAMS` / `SW_PARAMS` / `HW_FREE`：设置与释放参数；设置后读回内核返回的实际值（格式、采样率的分子分母、声道、周期、缓冲、`msbits` 有效位），替代 `snd_pcm_dump_hw_setup` 的文本解析；
  - `PREPARE` / `START` / `DROP` / `DRAIN`、`WRITEI_FRAMES`、状态查询（可写量、xrun）；等待用 `poll`。
  - 错误仍报告为调用名与正 errno，`api.rs` 的错误映射（`EPIPE` xrun、`EAGAIN`、`ESTRPIPE`、`ENODEV`）不变。
- **设备枚举**：`/dev/snd/controlC*` 的 `CARD_INFO` 与 `PCM_INFO`（声卡 id、名称、PCM 名、方向），替代 alsa-lib 的设备列表。`qybit list-devices` 的输出格式不变（`hw:CARD=<id>,DEV=<n>`）。
- **声道映射**：控制接口的 “Playback Channel Map” 元素（TLV 读能力、值读写），替代 alsa-lib 的 chmap 接口；布局无法确认时照旧拒绝（F1）。
- **B 层回环的回录**：同一套 ioctl 打开 `pcmC{卡}D{设备}c`，`READI_FRAMES`。
- 占用进程查找（`/proc`）与实时调度（`sched_setscheduler`）本来就不经过 alsa-lib，保持不变。
- `unsafe`（ioctl、`poll`、结构体按内核 ABI 布局）集中在一个模块，逐处写明前提，按 AGENTS §2 单独审计。结构体布局对每个目标架构做编译期大小与偏移检查（`size_of` / `offset_of` 对照 uapi 头文件）。
- **32 位架构的时间结构**：armv7 等 32 位系统上，状态结构中的时间戳在内核 5.6 起有 64 位时间版本。按内核接口版本选择对应的 ioctl 编号，单独核对与测试。

## 3. 静态程序与架构

- 每个目标架构编译一个**完全静态链接**的 `qybit`（不依赖任何系统库，放到该架构的任意 Linux 发行版上直接运行），作为 CI 产物发布。
- C 库用 **musl**，不用静态链接的 glibc（理由见 §6.1）。
- 目标（以开始实施时 rustup 实际提供的为准，届时核对各目标的支持级别并记录）：
  - `x86_64-unknown-linux-musl`
  - `aarch64-unknown-linux-musl`（64 位 ARM，如树莓派 4/5 的 64 位系统）
  - `armv7-unknown-linux-musleabihf`（32 位 ARM）
  - `loongarch64-unknown-linux-musl`（龙芯）
  - `riscv64gc-unknown-linux-musl`（可选，见 §6.2）
- 内核最低版本：按所用 ioctl 与接口版本定，写入文档；运行时内核过旧时明确报错。

## 4. 测试

- **不变的部分**：`Pcm` trait 之上的全部测试（假 PCM、协商、读回核对、渲染循环、矩阵）照常运行。
- **ioctl 层**：
  - 参数位掩码与区间的编码、解码，以及读回值转换，用纯函数实现并单元测试，对照 uapi 定义的独立参考值；
  - 结构体大小与偏移的编译期检查，在每个目标架构上交叉编译时执行。
- **其他架构**：用 `qemu-user` 运行各架构静态程序的单元测试与 `qybit --version`（不涉及声卡）。
- **真实内核路径**：
  - B 层 snd-aloop 回环改用 `KernelPcm`，在能加载 `snd-aloop` 的机器上运行（GitHub runner 不能加载内核模块；用户的 Debian 机器可以，用 root 执行 `modprobe snd-aloop`）；
  - 用户机器上的真实声卡跑 `qybit list-devices`、格式矩阵与顺序播放。
- **A 层回环**：现在依赖 alsa-lib 的 `file` 插件，内核直连后不再适用，处理方式见 §6.3。

## 5. 验收

1. 各目标架构的静态 `qybit` 在 CI 中构建并作为产物发布；用 `file` 或 ELF 头核对为静态链接、不依赖任何动态库。
2. x86_64 静态程序在没有安装 alsa-lib 的 Linux 上运行 `list-devices`、格式矩阵与顺序播放（用户机器）；结果与报告格式和现有后端一致。
3. B 层 snd-aloop 回环在用户机器上逐字节通过（虚拟回环，不证明真实 DAC）。
4. 其他架构：qemu-user 下单元测试通过；真机未运行的架构在文档中逐个标明“未运行”。
5. alsa-lib 不再是发布版的依赖（§6.3 选择保留可选后端时，只在测试中使用）。

## 6. 待决定

1. **C 库：musl 还是静态 glibc**。**建议 musl**：
   - glibc 官方不推荐完全静态链接：名称解析（NSS）、`dlopen`、`iconv` 等在静态程序中依赖运行时再加载同版本的 glibc 模块，会出警告或失效；
   - glibc 是 LGPL，静态链接时须向用户提供可重新链接的目标文件；musl 是 MIT，没有这项义务；
   - musl 本来就为静态链接设计，程序更小。musl 的内存分配较慢，但 QyBit 只在启动时分配，播放中不分配，不受影响。
2. **架构列表**：x86_64、aarch64、armv7、loongarch64 必做；riscv64 是否一起做。
3. **A 层回环**（软件路径提交的字节核对，CI 中运行）：
   - 甲：保留现有 alsa-lib 后端作为默认关闭的可选特性，只在 CI 中跑 A 层（核对 pack 与渲染路径），发布版不含；
   - 乙：去掉 A 层，改为在 CI 中用一个假的内核接口（模拟 ioctl 的回应）核对提交的字节，snd-aloop 与真实设备在用户机器上运行。
   - **建议甲**：A 层已经稳定地核对了软件路径，保留它的代价只是 CI 中多编译一个可选特性。
4. **现有 alsa-lib 后端在发布版中是否保留为可选**：建议不保留（§6.3 选甲时只在测试中使用），避免两套真实后端长期并存。
