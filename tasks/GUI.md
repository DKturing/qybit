# QyBit GUI：极简 Rust 图形界面

遵循根目录 AGENTS.md。前置：M0（Windows WAV）、M1（FLAC）、M2（ALSA/snd-aloop）与 M3（QyBit Embedded Reference，播放调度已下沉到 Core）完成后才开始；在此之前不创建 GUI crate，也不为 GUI 修改核心接口。

目标：为现有命令行播放器提供一个极简图形前端。GUI 只是控制与显示层，播放仍走与 CLI 相同的核心、自有解码、pack 与独占输出后端，不另建音频路径。

范围：
- 选择音频文件（WAV/FLAC）组成顺序播放列表；播放、停止、下一首。
- 列出输出设备并选择一个（AGENTS M0 禁止的交互设备选择在本卡放开，仅限 GUI）。
- 显示当前曲目的源格式、请求的设备格式、独占协商结果、欠载与错误计数。
- 不做：音量/均衡/任何 DSP、seek、随机播放、歌词、封面、媒体库、皮肤、配置保存以外的设置项。

## T1：技术选型

- 纯 Rust，不嵌入 WebView、不依赖 Node/Python；候选 egui/eframe、iced、slint，按以下标准比较后选定一个并记录理由：
  Windows/Linux/macOS 支持、二进制大小、依赖数量与许可证、是否需要 unsafe 或系统运行库、空闲 CPU 占用。
- 文件选择框若需系统对话框，评估 rfd 等成熟 crate；不能则用 GUI 框架内置的文件列表。
- 依赖锁定版本，新增依赖说明用途。

验收：选型记录写入 docs，附各候选的最小样例构建结果（大小、编译时间、空闲 CPU）。

## T2：GUI crate 与线程模型

- 新建 `qy-gui`（库）与二进制 `qybit-gui`；复用 `qy-host-wasapi` / ALSA 宿主的播放驱动，不复制播放逻辑。
- 播放驱动在独立生产线程运行；渲染线程规则不变（不解码、不 pack、不分配、不阻塞）。
- GUI 线程只发送控制命令（开始、停止、下一首、选设备）并读取原子计数与报告快照；不得持有或阻塞音频队列，不得在 UI 帧回调中做 I/O 或解码。
- 停止/换曲沿用核心的代次规则，旧代次结果不得显示为当前状态。

验收：模拟后端下自动测试控制命令序列（开始、停止、连续切换、设备失效）与状态显示一致；UI 线程卡顿注入（如人为延迟 1 s）不导致欠载。

## T3：显示与报告

- 文字区分：源格式、请求格式、协商结果（含描述类型与 HRESULT/ALSA 返回值）、可查询参数。不显示未经证实的“bit-perfect”。
- 欠载、丢帧、输出错误实时显示，且该次播放不再标示为完整保真。
- 设备不支持格式或独占打开失败时给出明确错误，不提供“改用共享模式/重采样”的选项。

验收：各状态的界面截图与对应报告字段一致；Windows 真机与 Linux snd-aloop 各运行一次并记录，未运行的平台明确标记。
