# QyBit GUI：极简 Rust 图形界面（Windows 优先）

遵循根目录 AGENTS.md。

**顺序**（2026-10-15 用户调整）：先在 Windows 上完成本卡（WASAPI 独占），再在 Linux 上运行（ALSA），单片机放在最后。前置条件是播放调度已在 Core（M3 T1，已完成）；GUI 只依赖桌面宿主与播放器层，不等待 M3 的实物验收。

**目标**：为现有播放器提供一个极简图形前端。GUI 只是控制与显示层，播放仍走与 CLI 相同的核心、自有解码、pack 与独占输出后端，不另建音频路径，不复制播放逻辑。

## 界面（参考 foobar2000 默认界面的布局与交互）

只借鉴布局与操作习惯，不使用其名称、图标或外观资源。

- **工具栏**：播放、暂停、停止、上一首、下一首；输出设备下拉框（列出可用端点，选定后用于下一次打开设备）。
- **播放列表**（表格）：正在播放标记、序号、文件名、时长、格式（如 `FLAC 44.1 kHz 16 位 2 声道`）。双击播放该曲；添加文件 / 添加文件夹；拖放文件或文件夹到列表；Delete 移除选中项；按列表顺序播放。
- **状态栏**：当前曲目源格式 → 设备格式与独占协商结果；已播放 / 总时长（只显示，不可拖动定位）；欠载、丢帧与错误计数；保真状态（严格路径完整 / 已改变 / 有欠载或错误）。
- **选项**：单声道复制到左右两路（tasks/O1.md），默认关闭；开启后状态栏与报告标为“已改变”。
- **设备硬件音量**（T5，用户 2026-10-15 决定）：只调节输出设备自身实现的硬件音量，送到设备的数据不变；设备没有硬件音量时滑块不可用并写明原因。
- **不做**：软件音量（软件增益恒为 1）、均衡与任何 DSP、重采样、共享模式退回、媒体库、标签编辑、封面、歌词、皮肤、随机播放；播放列表与设置的保存本卡不做。

AGENTS 中 M0 不做的交互设备选择与拖放，在本卡只对 GUI 放开；CLI 不变。

**定位（seek）**：属于核心能力，另立任务卡 [tasks/S1.md](S1.md)，已完成软件部分（[docs/s1-seek.md](../docs/s1-seek.md)）：工具栏下方的进度条（拖动预览、松开定位，总时长未知时不可用），列表中 ←/→ 定位 ±5 秒。状态栏的“只显示，不可拖动定位”由此改为可定位。

- 依赖锁定版本，新增依赖说明用途。

验收：选型记录写入 docs，附各候选最小样例（含一个列表与一个按钮）在 Windows 上的构建结果：release 大小、全新编译时间、空闲 CPU（窗口打开不操作 30 秒的进程 CPU 时间）。

## T2：播放控制与线程模型（已完成；用户已在真机上运行，见 docs/gui-t2-windows.md）

- 播放器层（`qy-player`）的控制扩展为：停止、暂停/恢复、上一首、下一首、跳到第 k 首（引擎已有对应操作）；CLI 与 GUI 共用，不另写播放逻辑。
- 新建 `qy-ui`（与平台无关的界面模型：播放列表、状态快照、控制命令、显示文字、后台文件头读取；纯安全 Rust，可在任何平台测试）与二进制 `qybit-gui`（Windows 原生控件前端，GUI 子系统，不弹控制台；Win32 调用的 `unsafe` 集中在一个模块并单独审计）。播放驱动在独立生产线程运行，渲染线程规则不变（不解码、不 pack、不分配、不阻塞）。
- GUI 线程只发送控制命令并读取原子计数与报告快照；不得持有或阻塞音频队列，不得在界面帧回调中做文件 I/O 或解码（读取时长与格式的文件头解析也在后台线程）。
- 停止/换曲沿用核心的代次规则，旧代次结果不得显示为当前状态。

验收：模拟后端下自动测试控制命令序列（开始、暂停、恢复、停止、连续切换、跳曲、设备失效）与状态一致；界面线程卡顿注入（人为延迟 1 秒）不导致欠载。

## T5：设备硬件音量（用户 2026-10-15 决定；软件部分已完成，真机未运行，见 docs/gui-t5-volume.md）

依据：Microsoft Learn《Endpoint Volume Controls》：`IAudioEndpointVolume` 在设备实现了硬件音量时使用硬件控制，这时音量变化在共享与独占模式下都有效；设备没有硬件音量时，它退化为软件音量，只作用于共享模式，对独占流不起作用（独占模式下应用与硬件直接交换数据，绕过软件控制）。`QueryHardwareSupport` 的 `ENDPOINT_HARDWARE_SUPPORT_VOLUME` 位表示设备在硬件上实现了音量。

- 工具栏下方（格式行右侧）加“设备音量”滑块与标签，作用于当前选定的输出设备（默认设备时取系统默认渲染端点）。
- 只在 `ENDPOINT_HARDWARE_SUPPORT_VOLUME` 置位时可用：拖动即调用 `SetMasterVolumeLevelScalar`，标签显示 `GetMasterVolumeLevel` 读回的 dB 值；设备在硬件上实现静音且处于静音时标明“已静音”。
- 设备没有硬件音量时滑块不可用，标签写明“设备没有硬件音量，请在 DAC 或功放上调节”；读取失败时写明原因。QyBit 不调用该端点的软件音量（它对独占流无效，只会改变其他程序的共享模式音量）。
- 送到设备的数据不变：播放报告、保真状态与 bit-perfect 说明都不受影响。设备内部的硬件音量是模拟还是数字实现，QyBit 无法得知，文档写明这一点。
- 其他程序（如系统音量键）改变了硬件音量时，界面在下次刷新时读回。
- CLI 不变。

验收：CI 中启动与截图（runner 没有音频设备，应显示读取失败的原因）；硬件音量的实际调节需要用户在有硬件音量的设备上运行。

## T6：使用体验（用户 2026-10-17 决定；已完成，见 docs/gui-t6-windows.md；用户 2026-10-17 在 Windows 真机上测试，反馈基本没有问题）

用户在 Windows 阶段收尾时确认以下各项都做；“记住播放列表与设置”由用户选择是否开启。都只改界面层，不改播放路径与保真规则。

- **采样率指示灯**：状态栏右下角一栏（用户 2026-10-17 调整：原定在格式行左侧），彩色圆点与采样率文字，按设备流的协商结果显示：
  - 灰：未播放；琥珀：正在打开设备；
  - 绿：设备流已按源采样率独占打开（“44.1 kHz 原生”，即没有重采样）；
  - 红：设备未能按该格式打开（“48 kHz 未打开”，具体原因在状态栏与日志，不断言是采样率本身的问题），或设备流采样率与源不一致（严格路径不应出现，出现即报告）。
  - 只依据协商结果，不宣称 DAC 实际运行在该采样率；颜色之外文字写明状态（不只靠颜色区分）。
- **输出设备列表自动更新**：注册端点变化通知（`IMMNotificationClient`：设备增加、移除、状态变化、默认设备变化），收到后重新枚举。已选设备消失时保留该项并标明“未连接”，不自动换到别的设备（下次播放按选定设备打开并如实报错）。注册失败时在日志写明原因，打开下拉框时重新枚举作为退路。
- **键盘媒体键**：播放/暂停、停止、上一首、下一首。窗口在前台时经 `WM_APPCOMMAND`；另注册全局热键，使窗口不在前台时也响应（播放菜单可关闭）。热键被其他程序占用时只在窗口激活时响应，并在日志写明。
- **记住播放列表与设置**（可选，默认关闭）：文件菜单“记住播放列表与设置”。开启后退出时保存到 `%APPDATA%\QyBit\qybit-gui.cfg`（文本，先写临时文件再替换），下次启动恢复播放列表顺序、选定的输出设备、窗口位置与大小、日志区显示与高度、列表排序、全局媒体键开关；关闭时删除该文件。**不保存**单声道复制与浮点转整数：这两项是明确开启的非严格选项，每次启动默认关闭（AGENTS §3）。文件损坏或不可读时忽略并在日志写明，不影响启动；找不到的文件照常列出并显示无法播放的原因。
- **列表排序**：点击列标题按序号（添加顺序）、文件名、时长、格式排序，再点一次反向，列标题显示箭头；“列表”菜单有同样的命令。
- **拖动调整顺序**：拖动选中的行到新位置（插入标记指示落点），Ctrl+↑ / Ctrl+↓ 移动选中的行。手动调整后排序箭头清除。
- **排序与移动在播放中**：正在播放的会话按开始时的顺序继续（与增删条目相同），新顺序从下一次开始播放起生效；第一次在播放中改变顺序时日志写明。
- **窗口不可见时不重绘**：在 L1 最小化的基础上，窗口在另一个虚拟桌面（DWM 隐藏，`DWMWA_CLOAKED`）时同样暂存重绘。被其他窗口完全遮挡的情况在 DWM 合成下没有可靠的判断方法，不做。

验收：
- `qy-ui` 单元测试：排序（各键、稳定、反向、未知时长排后）、移动（单行、多行不连续、到首尾、越界）、指示灯各状态、设置的保存与解析（往返、损坏行、未知键、非 UTF-8 路径跳过、不保存两个非严格选项）。
- CI（模拟设备）：各状态下指示灯文字；`WM_APPCOMMAND` 媒体键开始播放与暂停；列表命令排序后读回列表文字核对顺序；真实鼠标拖动一行后读回顺序；开启记住设置、关闭、再启动后恢复列表；设备变化通知的注册结果写入日志。
- 需要用户在真机上确认：插拔 USB 音频设备时列表更新、窗口不在前台时媒体键、另一个虚拟桌面时不重绘。
