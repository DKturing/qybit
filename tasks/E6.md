# QyBit E6：解码所需的读取跳转

遵循根目录 AGENTS.md。顺序见 [tasks/FORMATS.md](FORMATS.md)“公共接口”：E3、E5 之后，首个版本 tag 之前。

状态：**已完成软件部分**（2026-10-19），记录见 [docs/e6-jumps.md](../docs/e6-jumps.md)；真实设备与 M4A 文件未运行（M4A 解析在插件仓库）。

## 0. 问题与决定

Lite 插件的 M4A 解码器要处理索引（`moov`）在音频数据（`mdat`）之后的文件：先沿顶层 box 的长度跳过 `mdat` 找到 `moov`，再按索引回到音频包；多轨交错的文件在数据阶段也要在块之间跳转。现有接口里，解码器只能顺序接收输入：`seek_request` 只用于用户定位过程中（FLAC 二分查找），失败时核心改为“重新打开、顺序解码”，用在解析阶段会反复重开。

2026-10-19 用户在两个方案中选定 **B**：由格式解码器决定需要哪些文件字节，核心调度读取与跳转，宿主只执行 I/O（AGENTS §1、§2）。同一套能力桌面与 MCU 共用，也适用于其他需要随机读取的容器。主仓库不加入任何 M4A 专用逻辑；插件把尾置 `moov` 的解析接到本卡的协议上（插件仓库的工作，不在本卡内）。

**版本与接口决定（2026-10-19）**：

- 用户同意按建议把本卡纳入首个正式版本 0.1.0。已核实远端没有发布任何 tag（`git ls-remote --tags origin` 为空），本地的 `v0.1.0` 在本卡完成后重新打在完成后的提交上；
- 用户就本卡授权的公共接口调整（“尚未推 tag”不作为授权的理由，授权以本条记录为准）：
  - `qy_core::Decoder` 新增带默认实现的 `take_jump`（已有实现不变）；
  - `qy_core::Fault` 新增变体 `Jump(JumpFault)`（`Action::Failed` 的内容，属于 M0 T4 冻结的 `Action` / `Event` 接口：本条即对这次修改的同意）；`Action` / `Event` 本身不新增变体，跳转沿用 `Action::Seek` 与 `Event::SeekDone` / `SeekFailed`；
  - `qy_core::engine::HostAction` 新增变体 `ParseJumped`；
  - `qy-host-embedded` 的 `budget::Load` 新增字段，`Margins` 新增字段；`Storage::seek` 越过文件末尾时改为成功（§2.2）。
- 按 E4 规则这些都属破坏性修改；因为首个版本尚未发布，直接计入 0.1.0（CHANGELOG 写明），不升到 0.2.0。

## 1. 接口

```rust
// qy-core
pub trait Decoder {
    // ……
    /// 解码需要的读取跳转（E6）：下一批需要的字节不在当前读取位置之后时，返回新的字节位置
    /// （距音源开头）。取走即清空；`reset` 清除。默认没有。
    fn take_jump(&mut self) -> Option<u64> { None }
}

pub enum JumpFault {
    /// 解码需要跳转，但音源不可定位（如管道）。
    Unseekable,
    /// 自上一次跳转完成（或打开音源）以来没有读到任何字节就再次请求跳转。
    NoProgress,
    /// 违反约定：同一次 `decode` 同时给出 `take_jump` 与 `seek_request`，或返回 `End` 时给出跳转。
    Protocol,
}
pub enum Fault { /* …… */ Jump(JumpFault) }

/// 跳转的协议检查。核心与各同步驱动（`read_header`、`qybit decode`、`qy-testkit`）共用这一份。
pub struct JumpGuard { /* 自上次跳转完成以来读到的字节数 */ }
pub enum Jump { None, Parse(u64), Seek(u64) }

// qy_core::engine
HostAction::ParseJumped { track: u32, offset: u64, header: bool }   // 每次解析跳转，在对应的 Seek 之后给出
```

两种跳转分开处理：

| | 解析跳转（本卡） | 用户定位的跳转（S1） |
| --- | --- | --- |
| 来源 | `take_jump`：解码器自己需要的字节在别处 | `Decoder::seek` 的返回值与其后的 `seek_request` |
| 何时 | 任何一次 `decode` 之后（文件头阶段与数据阶段） | 只在用户定位过程中 |
| 宿主 | `Action::Seek` | `Action::Seek` |
| 失败 | 明确报错 `Fault::Jump(Unseekable)`，不重新打开 | 保持现有回退：重新打开、顺序解码到目标 |

## 2. 规则

### 2.1 请求的生命周期与顺序

- `take_jump` 取走即清空；`reset` 清除未取走的跳转（契约测试核对 `reset` 后为 `None`）。
- 核心在每次成功的 `decode` 之后、按以下顺序处理（`decode` 出错时直接失败，不再取跳转；解码器出错后冻结，规则不变）：
  1. 处理 `consumed`，取 `take_preroll`（E5）；
  2. 取 `take_jump` 与 `seek_request`：两者都给出、或状态为 `End` 时给出跳转，为 `Fault::Jump(Protocol)`；
  3. 有解析跳转时，先做无推进检查（§2.4）；
  4. 有 `seek_request` 时执行它（S1，位置与原来相同，用户定位的行为不变）；
  5. **用户定位优先**：有尚未交给解码器的定位目标，且本次状态为 `Frames` / `NeedOutput`（文件头已解析、首次产出样本）时，调用 `Decoder::seek`。返回位置时，`seek` 已让解码器丢弃未取走的样本并从目标处重新定位，本次给出的解析跳转随之作废——解码器从 `seek` 返回的位置继续，它需要的其他位置在之后的 `decode` 中再给出；返回 `Unsupported` 时解码器状态未变，照常执行本次的解析跳转（顺序丢弃到目标）。定位请求不会丢失，也不会被解析跳转覆盖；
  6. 否则执行解析跳转；本次状态为 `NeedInput` 时定位目标保持待交，等解析跳转之后首次产出样本时再交给解码器；
  7. 否则按状态继续（输出、读取、结束）。
- 解析跳转不影响已产出、尚未取走的样本：跳转完成后先照常输出这些样本，再继续解码。

### 2.2 跳转与 EOF

- 跳转成功（`SeekDone`）后，输入窗口中旧位置的字节全部废弃，旧位置的 EOF 状态清除；下一次 `Read` 从新位置读取，解码器下一次看到的输入从该位置开始（解码器据此知道输入对应的文件位置）。
- 文件头解析状态由解码器自己保存，跳转前后连续：核心不重置解码器，只换输入。
- 跳到文件末尾或之后是合法的：宿主定位成功，之后的读取得到 EOF，核心把 EOF 交给解码器（`eof = true`、输入为空），解码器按自己的规则结束或报错（截断）。为此 `qy-host-embedded` 的 `Storage::seek` 越过文件末尾时改为成功、之后读取返回 0；“不支持定位”仍返回 `false`。桌面 `std::fs::File` 本来如此。

### 2.3 跳转失败

- 解析跳转的 `SeekFailed`：`Fault::Jump(Unseekable)`，曲目失败（按出错跳过策略继续下一首），**不重新打开**，所以不会反复重开。
- 用户定位的 `SeekFailed`：保持现有回退（重新打开并顺序解码）。重新打开后的解析跳转若再失败，同样是 `Unseekable`，不会再次回退。

### 2.4 防止循环（两层）

1. **核心检测**（`JumpGuard`，生产环境生效）：自上一次跳转完成（或打开音源）以来没有读到任何字节，解码器就请求解析跳转，为 `Fault::Jump(NoProgress)`。这覆盖“反复请求同一位置”“跳到文件末尾之后再跳”“空输入上连续跳转”。
2. **契约测试检测**（`qy-testkit`，只是测试保护）：读到了字节、但在几个位置之间来回跳的循环，核心不靠记录位置发现，属于解码器的错误。契约测试给每个源设步数上限（与文件大小相关），超出即报违约。**这一层不在生产环境运行，不宣称生产环境能检测所有循环。**

### 2.5 E3 路由

- `Identify::NeedMore { container: true }` 表示已认领这个容器，路由层可以提前转交给它的解码器；**不表示子格式已经支持**——容器里是哪种编码（如 M4A 内的 ALAC、AAC 或不支持的编码）仍由容器解码器解析后决定，不支持时由它返回 `Unsupported` 与明细。
- `total` 可能大于输入窗口（索引在文件末尾时）：路由层不得为攒够 `total` 字节而等待，见到 `container: true` 即转交。
- `identify` 只看文件开头的前缀，不跳转；索引不在前缀里时回答 `NeedMore { container: true }`，前缀包含索引时（例如整个文件）可以给出 `Supported`，与完整解码（含跳转）一致。

### 2.6 辅助入口一致

播放（桌面、模拟宿主、嵌入式宿主，经核心）、`qybit decode`、`qy_player::read_header` 与 `qy-testkit` 都执行 §2.1–§2.4 的同一套语义；核心以外的同步驱动用同一个 `JumpGuard`。示例中的路由解码器（`ExtDecoder`）把内层解码器的跳转原样转出，并加上它跳过的 ID3v2 标签长度。

### 2.7 资源统计与 MCU 预算

- 跳转不算播放帧数，不计入预填量与播放位置。
- `read_header` 按实际读取的字节累计预算（16 MiB），跳转后重复读取的字节也计入；输入窗口上限不变。
- 宿主计数：`HostAction::ParseJumped` 给出每次解析跳转（`header`：该曲目首次产出样本之前）。桌面报告写明每首的文件头跳转与数据跳转次数；嵌入式宿主计入 `stats` 的 `parse_jumps`（不逐次输出事件：数据阶段的跳转可能很多，通知队列只有 8 项），超出预算时输出 `EVENT jump-budget-exceeded`。
- **MCU 预算**（`qy-host-embedded::budget`）：`Load` 增加 `J`（`header_jumps`：首次输出之前的最多解析跳转次数）、`k`（`unit_jumps`：数据阶段每个输入单元之前的最多跳转次数）与 `S`（`jump_us`：板级实测的最长定位耗时，含 FAT 簇链查找）。由插件按格式声明 `J`、`k`，板级实测 `S`；官方格式均为 0。
  - 持续负载：`R · (U + k·S) / W / 10⁶ + D · fs / F / 10⁶ ≤ 1`；
  - 预填（启动与换曲）：`P ≥ O + J·(S + U) + U + k·S + D + T`；
  - 定位响应（报告，不作启动条件）：`O + J·(S + U) + S + U + D`，写入 `Margins`；
  - 运行时核对：一首曲目首次输出之前的解析跳转超过声明的 `J`（各格式的最大值）时，嵌入式宿主给出 `Notice::JumpBudgetExceeded` 并输出串口事件；`k` 只按声明计入公式，运行时不核对。超出预算的文件仍可能欠载，欠载照常计数与报告。

## 3. 示例：尾部索引格式 QYI1

`examples/qy-ext-demo` 增加 QYI1（只为说明本卡接口而定义，代表 M4A 这类索引在后的容器，不是要支持的生产格式）：

- 文件头 12 字节：魔数 `QYI1` + 索引位置（u64）；
- 数据区：若干个 16 位整数 PCM 包，包之间可以有填充（数据阶段需要跳过）；
- 索引（文件末尾）：`IDX1`、采样率、声道数、包数，每包的位置与帧数；索引表存放在宿主提供的静态切片中，超出容量明确报错。

解码过程：读文件头 → 跳到索引（文件头跳转）→ 读索引、确定格式 → 跳到第一个包（文件头跳转）→ 顺序解码，下一包不紧接在当前包之后时跳过去（数据跳转）。定位按包直接定位。
