# QyBit L1：低功耗宿主——按事件等待、通知合并与测量

遵循根目录 AGENTS.md。来源：2026-10-16 外部架构评估。核心已有等待原因（`Wait::Io`、`Wait::QueueFull`、`Wait::Device`）与 `Poll::Yield`，本卡不新增核心接口，只让宿主真正利用它们。顺序：B1（[B1.md](B1.md)）之后，X1（[X1.md](X1.md)）之前。

状态：**草案，待用户审定**。

**目标**：
- 播放、暂停、空闲时宿主只在有事可做时醒来，同时满足：
  - 命令不丢失、响应及时；
  - 不新增欠载；
  - 暂停后恢复的行为不变。
- 用前后对比的数据说明效果，不以“改成事件驱动”本身作为结论。

## 1. 现状（2026-10-17 核对 `afe44ad`）

- **桌面生产端**（`qy-player/src/player.rs`）：
  - 队列满时（`wait_for_space`）与排空期间（`poll_drain`）固定 `sleep(2 ms)` 轮询；
  - 暂停时队列是满的，也按 2 ms 醒来，约每秒 500 次；
  - 控制命令经 `mpsc` 通道送达，生产端在每轮循环中查看。
- **渲染线程**：
  - WASAPI 用事件回调（`AUDCLNT_STREAMFLAGS_EVENTCALLBACK` + `WaitForSingleObject`），按设备周期醒来；
  - ALSA 为阻塞写入。
  - 两者本来就由设备节拍驱动，本卡不改实时路径。
- **界面**：
  - `qy-ui` 的后台线程每个事件都经 `PostMessageW` 通知窗口；
  - 播放中的状态快照至多每 100 ms 一次（`STATUS_INTERVAL`），窗口最小化时照常更新。
- **MCU 板级示例**（`qy-board`）：
  - 主循环空闲时也不进入 `WFI`，因为串口接收没有用中断或 DMA，`WFI` 期间到达的多个字符会丢失；
  - `qy-host-embedded` 的 `Player::step` 已能返回 `Step::Idle`；
  - QEMU 演示不测功耗。

## 2. 桌面生产端：按事件等待

- **唤醒源**：
  - 渲染线程取走数据，使队列降到阈值以下（建议半满，带滞回，避免每个设备周期都唤醒）；
  - 渲染线程结束（排空完成或出错）；
  - 控制命令到达；
  - 状态快照到期（只在播放且有回调时）。
- **机制**：
  - 用 `std::thread::park_timeout` / `unpark`。`unpark` 先于 `park` 发生时下一次 `park` 立即返回，不会丢失唤醒；
  - 命令发送方经 `PlayControl` 新增的唤醒句柄唤醒生产端（`qy-ui` 与 CLI 都改用它）；
  - 超时只作安全网（建议 = 状态间隔或 1 s），正常路径不靠超时。
- **暂停**：不取队列、不轮询，只等命令。设备在暂停期间是否继续输出静音时钟，由后端现有行为决定（WASAPI 照常送静音，不能为了省电停掉设备，否则恢复行为改变）。
- **空闲**（无会话）：生产端线程阻塞在命令通道上，不运行。
- **不做**：不改渲染线程的实时搬运；不引入异步运行时。

## 3. 界面：通知合并

- 后台线程向窗口投递消息前检查“已有未处理的通知”标志（原子量），已有时不再投递；窗口处理时清除标志并一次取完全部事件。
- 窗口最小化或被遮挡时，状态快照只记录不重绘；恢复显示时重绘一次。
- 日志与结束报告不受影响（不丢事件，只合并通知）。

## 4. MCU：空闲时休眠

- **板级示例改为中断接收串口**：字节进环形缓冲（有界、中断里只写入）。
- **主循环**：`Step::Idle` 时进入 `WFI`，由 DMA 半传输或完成中断、串口接收中断唤醒。
- **测量手段**：用 DWT 周期计数器（Cortex-M3/M4/M7）统计活跃与休眠时间，经串口命令 `stats` 报告：
  - 活跃比例；
  - 单次 `step` 的最长耗时；
  - DMA 截止余量（中断时队列中剩余帧数的最小值，复用 R1 水位）。
- **平均电流**：需要用户在实物板上用电流表或电源分析仪测量，本卡只给出步骤与记录表。

## 5. 测量与验收

**桌面**（开发机 Linux 与 CI Windows；数值只对该机器成立）：

| 指标 | 方法 | 要求 |
| --- | --- | --- |
| 生产端每秒唤醒次数 | 生产端计数器（测试特性下导出） | 播放、暂停、空闲三种状态分别记录前后数值；暂停与空闲时显著下降，空闲应为 0 |
| 进程 CPU 时间 | Linux `getrusage` / Windows `GetProcessTimes`，各 60 s | 记录前后数值 |
| 命令响应延迟 | 发送命令到状态快照反映的时间，假设备上测 | 不超过 50 ms（暂停、恢复、切歌、停止） |
| 欠载与水位 | 现有计数 | 按真实时间消费的假设备上无新增欠载，最低水位记录在案 |

**正确性**：
- 现有播放器与界面测试全部通过；
- 新增“命令在生产端等待时到达”“渲染线程在生产端等待前结束”“暂停中停止”的确定性测试，证明无丢失唤醒、无死锁；
- 用 Miri 运行不涉及 FFI 的部分（同 M2 T5）。

**MCU**：
- 虚拟时间仿真中，空闲期间不调用 `step`，靠中断唤醒，仍无欠载；
- QEMU 演示照常通过；
- 实物上的活跃比例与平均电流由用户在任一板上测量后填入记录（未运行时明确标记）。

## 6. 待决定

1. **桌面唤醒阈值**：建议队列降到半满时唤醒生产端，填满后再等。阈值更低醒得更少，但留给读盘与解码的余量更小。实测后定。
2. **MCU 示例的串口中断改动**：涉及板级 `unsafe` 中断注册（同现有 DMA 中断），按现有审计方式记录。

## 7. 范围外

- 降低 CPU 频率、电源管理策略（属于平台或板级）；
- 有界或分层 FLAC 解码（P1，实测证明需要时再做）；
- GUI 框架更换。
