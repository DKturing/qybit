# QyBit F3：浮点 PCM（WAV 32/64 位 IEEE 浮点）

遵循根目录 AGENTS.md。顺序见 [tasks/FORMATS.md](FORMATS.md)：F2 之后。

状态：**已审定**（2026-10-15）。设备不接受浮点格式时，另外提供一个明确开启、报告标为“样本已改变”的转换选项（用户决定）；§8 四项均按建议（用户 2026-10-15 确认）：只做 WAV 浮点；转换时遇到 NaN / ±∞ 拒绝该曲目并报告位置；binary32 → binary64 与整数 → 浮点本卡不做；同意 `SourceFormat` / `DeviceFormat` 新增样本编码。**软件部分已完成**（2026-10-15），记录见 [docs/f3-float.md](../docs/f3-float.md)；WASAPI / ALSA 真机与 MCU 实物未运行；IEEE 754-2019 与 RIFF 1991 原文待用户提供后补核。

**目标**：自行实现浮点 WAV 的解码；设备接受相同浮点格式时原样输出（严格路径，逐位不变）；设备不接受时默认明确拒绝，只有用户明确开启转换选项时才转为整数 PCM，并在报告中标为“样本已改变”。桌面、模拟与嵌入式宿主共用。

## 0. 规范出处（实施前核对原文，记入 docs/specs.md）

| 内容 | 出处 |
| --- | --- |
| 格式码 `WAVE_FORMAT_IEEE_FLOAT`（3）、`wBitsPerSample` 为 32 或 64 | Microsoft Learn / Windows SDK `mmreg.h`；Microsoft《Multiple Channel Audio Data and WAVE Files》 |
| EXTENSIBLE 子格式 `KSDATAFORMAT_SUBTYPE_IEEE_FLOAT` | Microsoft Learn `WAVEFORMATEXTENSIBLE`、`ksmedia.h` |
| `fact` chunk（样本帧数；原文只要求压缩格式与 `wavl` LIST 有，见 §10） | IBM/Microsoft《Multimedia Programming Interface and Data Specifications 1.0》（1991）RIFF WAVE 部分 |
| binary32 / binary64 的编码、NaN、无穷、次正规数 | IEEE 754-2019 |
| 设备端浮点格式 | WASAPI：独占模式的 `KSDATAFORMAT_SUBTYPE_IEEE_FLOAT`；ALSA：`SND_PCM_FORMAT_FLOAT_LE` / `FLOAT64_LE` |

Microsoft 文档以 GitHub `MicrosoftDocs` 仓库中的文档源核对；RIFF 1991 规范与 IEEE 754 需要原文，取不到时请用户提供（同 F2）。

## 1. 原则

- **Core 最严格**：只接受规范定义的内容，拒绝分为不合规、合规但尚不支持、规范之外的扩展三类（同 F2），各有独立的明细项，以后扩展只改对应一项。
- **严格路径逐位不变**：浮点样本按位原样送到接受同一浮点格式的设备，不经任何数值运算。
- **转换只在明确开启时发生**：默认关闭；开启后每首被转换的曲目都在报告中标为“样本已改变”，结论不再是严格路径，也不再说“软件路径无损”。
- **不加抖动、不改增益**：转换是确定的逐样本映射，同一输入总得到同一输出。乘以 2^(V−1) 是浮点满幅 ±1.0 与整数满幅之间的表示换算，不是增益调整。
- **AGENTS 的同步**：AGENTS §3 已加入第二项“浮点 PCM 转整数 PCM（见 tasks/F3.md）”（2026-10-15）。

## 2. 解码（`qy-codec-wav` 扩展）

- **识别**：格式码 3，或 EXTENSIBLE 且子格式为 `KSDATAFORMAT_SUBTYPE_IEEE_FLOAT`；`wBitsPerSample`（EXTENSIBLE 时为容器，`wValidBitsPerSample` 必须等于容器）为 32 或 64，其余拒绝。
- **`fact` chunk**（2026-10-16 按用户决定修改，见 §10）：
  - 没有 `fact`：照常，帧数按 data 长度计算；
  - data 之前有 `fact` 且帧数与 data 长度一致：正常；
  - `fact` 重复、帧数与 data 长度不一致，或 data 长度为占位值而无法核对：按不合规拒绝，以后按真实样例逐条加容错（同 W1“先严格，再逐条加”），每条修正写入报告。
- **样本**：小端 binary32 / binary64，按位读取，不做数值运算。
- **输出契约**（不改 `Decoder` trait）：
  - `SourceFormat` 新增样本编码 `SampleEncoding { Int, Float32, Float64 }`，现有构造函数仍为 `Int`；
  - `Float32`：`pcm()` 中每个样本占 1 个 `i32`，存放 binary32 的位模式（`f32::to_bits` 的按位重解释，不是数值）；
  - `Float64`：每个样本占 2 个 `i32`（低 32 位、高 32 位），`release(frames)` 仍按帧计；
  - 位模式重解释用 `from_bits` / `to_bits`，不用 `unsafe`。
- **非有限值**：NaN 与 ±∞ 在严格路径中原样保留并计数，报告给出个数；转换时的处理见 §4。
- **最大连续输入**：一帧（64 位 × 声道数），远小于核心最小窗口。

## 3. 严格路径：原样输出到浮点设备

- `DeviceFormat` 新增样本编码，与 `SourceFormat` 对应；WASAPI 用 EXTENSIBLE + `IEEE_FLOAT` 子格式协商，ALSA 用 `FLOAT_LE` / `FLOAT64_LE`。
- **pack**：编码相同时按位复制（小端），声道仍按 F1 的位置纯置换。
- **binary32 → binary64**：每个 binary32 值都能被 binary64 精确表示，数值不变。第一阶段**不做**（见 §8 决定 3），设备只接受 64 位时按“设备不支持”拒绝。
- **协商顺序**：先请求与源相同的浮点格式；设备不接受时：
  - 转换选项关闭：明确拒绝，报告写明“设备不接受 32 位浮点；可用 `--float-to-int` 明确开启转换（样本已改变）”；
  - 转换选项开启：改为请求整数格式，见 §4。

## 4. 转换选项：浮点转整数 PCM（明确开启，样本已改变）

- **开启方式**：CLI `--float-to-int`；嵌入式由板级配置或串口命令 `float-to-int on|off` 开启。默认关闭。
- **目标格式**：同采样率、同声道；整数位深从设备支持的格式中选有效位 V 最大者（V ≤ 32）。
- **映射**（与 ffmpeg / libsndfile 的常用约定一致，整数来源的浮点文件可往返精确还原）：
  - `s = round_half_even(x × 2^(V−1))`，再限制到 `[−2^(V−1), 2^(V−1) − 1]`；
  - 即 −1.0 → 最小值，+1.0 及以上 → 最大值（被限幅），−1.0 以下 → 最小值；
  - 用整数运算直接按 IEEE 754 的符号、指数、尾数完成缩放与舍入，不依赖硬件浮点，桌面与 MCU（含无双精度 FPU 的 Cortex-M4F）结果逐位相同。
- **非有限值**：NaN 与 ±∞ 不做猜测——该曲目按“含非有限样本，无法转换”拒绝（转换前不知道时，在遇到的位置停止该曲目，已输出部分照常排空），报告给出位置。
- **报告**（每首被转换的曲目）：
  - “曲目 N 样本已改变：32 位浮点转为 24 位整数（明确开启；不加抖动）”；
  - 限幅样本数；
  - **不精确的样本数**：转换后再按同一公式换回浮点不等于原值的样本个数。为 0 时写明“本曲每个样本都能被 V 位整数精确表示（例如由整数 PCM 生成的浮点文件），转换未损失数值”，但仍标为“样本已改变”（表示与类型已改变）。
- **实现位置**：
  - 转换在非实时生产端完成，结果为 `Pcm<Altered>`（`Pcm<Altered>` 的第一个产生者），再由 pack 按设备格式放置；
  - 转换分块进行，工作区由宿主启动时提供（`&'static mut [i32]`，容量写入配置档），不在 codec 或 core 内嵌大数组。

## 5. 接入

- **`qy-codec-auto`**：WAV 浮点随 `wav` 特性一起提供，不新增特性。
- **配置档**：
  - 浮点样本复用流式工作区（64 位样本每个占两个字，同样容量能容纳的帧数减半），不增加 RAM；
  - 转换工作区：Desktop 与 Embedded Full 提供，Embedded Lite 不提供（开启转换时按“资源不足”明确拒绝）。具体容量与 `.text` 增量以实测记录。
- **宿主**：模拟宿主、桌面播放器（WASAPI、ALSA）、`qybit decode`（写出原样浮点 WAV；或开启转换后写出整数 WAV）、嵌入式宿主与 QEMU 演示。MCU 的 I²S 输出是整数格式，浮点文件只能在开启转换时播放。

## 6. 夹具与参考

- **生成器**（`tools/qy-gen-fixtures`，纯 Rust）：构造浮点 WAV 并独立给出期望位模式；ffmpeg 作第二参考（`-f f32le` / `-f f64le` 按位比较；转换用 `-c:a pcm_s16le` / `pcm_s24le` / `pcm_s32le`，不开抖动）。
- **覆盖**：
  - 32 / 64 位；单声道、双声道、多声道掩码；
  - 0、±0、±1.0、略大于 1.0、次正规数、最小/最大有限值、NaN（静默/信号）、±∞；
  - 由 16 / 24 位整数生成的浮点（转换应精确）与任意值（转换不精确）；
  - 格式码 3 与 EXTENSIBLE 两种描述；有 / 无 `fact`、`fact` 帧数不一致；
  - 拒绝情形：位宽不是 32/64、EXTENSIBLE 有效位不等于容器、截断等。
- **转换参考**：独立公式（用 `f64` 与 `i128` 在测试代码里按 §4 计算，不调用被测实现），覆盖每个舍入边界（正好半个 LSB、半个 LSB ± 1 ulp）。

## 7. 验收

1. 全部夹具解码结果与独立期望按位一致；ffmpeg 能读的与第二参考一致；拒绝情形的类别与明细与期望相同；
2. 任意分块（1 字节、随机、整块）结果相同；
3. 转换：与独立公式逐样本一致，ffmpeg 转换参考一致（舍入约定相同的部分）；限幅与不精确计数正确；
4. fuzz：`wav_decode` 加入浮点语料，新增转换目标（任意位模式不 panic，结果在 V 位范围内，与参考公式一致），各 10 分钟并记录；
5. 模拟宿主：浮点曲目在浮点设备上逐位一致；在整数设备上关闭转换时拒绝、开启时与参考一致并报告；与整数曲目混排；种子 × 两种设备模型；
6. A 层回环（ALSA file 插件，`FLOAT_LE`）逐字节比对；
7. no_std（thumbv7em）构建与 Clippy；QEMU 演示播放一首浮点文件（开启转换），三个配置档的预算与 `.text` 增量记录；
8. 文档记录规范出处、各情形的处理与限制。

## 8. 决定（2026-10-15 用户确认，均按建议）

1. **AIFF-C 的 `fl32` / `fl64`**：AIFF-C 原文（1991 草案）没有定义浮点类型，和 `sowt` / `twos` 一样属于“规范之外的扩展”。**建议**：F3 只做 WAV 浮点，AIFF-C 浮点照旧拒绝，以后与 `sowt` / `twos` 一起作为插件考虑。（2026-10-18 用户改为纳入基础格式，由 [F5](F5.md) 实现。）
2. **非有限值（NaN / ±∞）在转换时的处理**：**建议**按 §4 拒绝该曲目（不猜测）；另一种做法是置 0 并计数，但这会把无意义的数据当成静音播放。
3. **binary32 → binary64 及“整数 → 浮点”**：两者在数值上都是精确的（整数 N ≤ 24 位可被 binary32 精确表示），理论上可算作不改值的表示转换。**建议**本卡不做，以后确有只接受 64 位浮点或只接受浮点的设备时再单独评估。
4. **冻结接口的改动**：`SourceFormat`、`DeviceFormat` 新增样本编码（只增加，现有构造函数与行为不变）；`Pcm` 中浮点样本按位存放。这触及 M0 起冻结的格式类型，**需要你同意**。

## 9. 范围外

- 压缩或有损浮点格式；
- 浮点的增益、抖动、重采样；
- 写浮点文件（`qybit decode` 输出原样浮点 WAV 除外）。

## 10. 实施记录（与原卡不同之处）

- **浮点源本身超出本机能力**：原卡只规定“设备不接受时”按整数回退。实施中发现，浮点按自身宽度估计的队列放不下（如 Embedded Full 上的 f64 双声道 96 kHz），而转换后的整数放得下时，原逻辑会直接拒绝。现在开启转换时同样从第一档整数起协商；严格路径仍按能力不足拒绝。
- **嵌入式协商顺序**：I²S 只输出整数，开启转换后仍先按源格式请求浮点，被拒后回退，因此会先出现一条“设备不接受浮点”的通知。
- **`fact` 规则的出处**（用户 2026-10-16 提供 RIFF 1991 原文后核对）：§0 写的“非 PCM 格式需要 `fact` chunk”在 1991 原文中没有依据。原文只要求压缩格式和 `wavl` LIST 有 `fact`，而且原文没有定义格式码 3。用户 2026-10-16 决定：`fact` 可有可无，没有时帧数按 data 长度计算（§2 已改）。
- **ffmpeg 转换参考的范围**：ffmpeg 的 SIMD 转换在 |x| ≥ 1 时溢出，转换参考只用于 [−1, 1) 内的值；限幅按独立公式核对。
