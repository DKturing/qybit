# QyBit 格式路线（规划卡）

遵循根目录 AGENTS.md：软件不设人为上限；严格路径不改变样本；每种格式自行实现解码器（参考实现只用于测试）；格式按“产出交错右对齐 `i32` + 有效位 N”的 `Decoder` 契约接入。

## 分工（2026-10-18 用户决定，取代此前的路线）

| 层 | 格式 | 维护 |
| --- | --- | --- |
| **基础** | WAV（整数、浮点、8 位、EXTENSIBLE、RF64/BW64）、FLAC、AIFF / AIFF-C 未压缩（`NONE`、`twos`、`sowt`、`fl32`/`fl64`） | 本仓库，官方解码器（`qy-codec-wav` / `-flac` / `-aiff`），默认发行版包含 |
| **Lite** | ALAC（含 M4A 必要容器解析）、AAC-LC（M4A / ADTS）、MP3 | 用户另建的插件仓库，不合并进本仓库 |
| **Full** | Lite 全部，再加 HE-AAC v1/v2、WavPack 整数无损、APE、Ogg Vorbis、Ogg Opus、DSF/DFF（初期不含 DST） | 同上 |

- Lite 与 Full 共用同一份格式实现，只是选择的格式不同；“Lite”指格式少，不代表资源占用少（2026-10-18 对 Lite 插件包的评估：AAC/MP3 工作区约 110–180 KB）。
- 此前路线上的 F4 ALAC、F5 WavPack、F6 APE、F7 DSD 不再作为官方解码器，移到插件仓库（Lite / Full）；2026-10-15 决定“`sowt`/`twos`/AIFF-C 浮点不进 Core”改为进入基础格式（2026-10-18）。
- 插件仓库依赖本仓库的公开接口；本仓库负责下面“公共接口”一节的工作，插件按 [docs/x1-extensions.md](../docs/x1-extensions.md) 的契约编写，用 `qy-testkit` 证明遵守接口约定。

本卡只定顺序与范围；每一项开始前写详细任务卡（规范出处、夹具与参考工具、验收标准）。

## 基础格式

| 顺序 | 项目 | 要点 | 对音质 |
| --- | --- | --- | --- |
| F1 | 多声道（[任务卡](F1.md)；软件部分已完成、真实多声道设备未运行，见 [docs/f1-multichannel.md](../docs/f1-multichannel.md)） | FLAC 1–8 声道（RFC 9639 声道分配）、WAV EXTENSIBLE 声道掩码；声道顺序精确映射到 WASAPI 声道掩码、ALSA 声道映射（chmap）；设备不支持该布局时明确拒绝 | 不改变样本 |
| W1 | 真实世界 WAV 的容错与 8 位 PCM（[任务卡](W1.md)；已完成，见 [docs/w1-wav-tolerance.md](../docs/w1-wav-tolerance.md)） | 流式占位长度、RIFF 长度写错、不完整尾帧等意图明确的情形可播放并报告修正；有歧义的照旧拒绝；8 位无符号 PCM 精确转为有符号 | 不改变样本 |
| F2 | AIFF / AIFF-C（未压缩 `NONE`）（[任务卡](F2.md)；已完成，见 [docs/f2-aiff.md](../docs/f2-aiff.md)；规范出处见 [docs/specs.md](../docs/specs.md)） | 大端 PCM，1–32 位左对齐补码 | 不改变样本 |
| F3 | 浮点 PCM（[任务卡](F3.md)；软件部分已完成，[记录](../docs/f3-float.md)） | 设备接受相同浮点格式时原样输出；不接受时严格路径拒绝；明确开启、报告标为“样本已改变”的转为整数选项 | 原样输出时不改变；转换时改变 |
| F4 | WAV RF64 / BW64（[任务卡](F4.md)；软件部分已完成，见 [docs/f4-rf64.md](../docs/f4-rf64.md)；规范原文待核对） | `ds64` 块给出 64 位长度，支持超过 4 GiB 的 WAV；块大小表；流式写入程序的占位值按 W1 规则处理 | 不改变样本 |
| F5 | AIFF-C 未压缩变体 `twos`、`sowt`、`fl32`/`fl64`（[任务卡](F5.md)；软件部分已完成，见 [docs/f5-aifc-variants.md](../docs/f5-aifc-variants.md)） | 大端与小端整数（1–32 位）、32/64 位 IEEE 浮点（大端，按位输出，接入 F3 的浮点路径） | 不改变样本 |

可选，以后按需要另立卡：Sony Wave64（`.w64`）、CAF 中的 PCM（CAF 也可能装 ALAC，若做则整体放进 Lite）。不做无文件头的裸 PCM（格式只能靠用户输入，违反“格式解析完成前不得伪造格式”）。

## 公共接口（本仓库为插件做的工作）

| 顺序 | 项目 | 要点 |
| --- | --- | --- |
| E1 | 有损标记（[任务卡](E1.md)；用户 2026-10-18 同意扩展接口） | 格式信息中的结构化“有损”字段；报告、CLI、GUI 明确显示；有损格式的输出位数是解码精度，不是音源位深 |
| E2 | 应用组装入口（[任务卡](E2.md)） | `qybit` / `qybit-gui` 的主体可作为库调用，由调用方传入解码器与文件信息读取；文件筛选的扩展名与 `--help` 的格式列表由解码器集合提供 |
| E3 | 格式识别（[任务卡](E3.md)） | 官方解码器能回答“文件头不是我的格式”与“是我的格式但子类型不支持”，插件的路由层据此转交，不必自己缓存文件头 |
| E4 | 接口版本（[任务卡](E4.md)） | X1 契约的版本号与兼容规则、版本 tag；`qy-testkit` 作为公开的测试工具 |
| E5 | 帧格式的定位预滚（[任务卡](E5.md)） | 解码器可定位到目标之前的某一帧，再由核心解码并丢弃到目标，避免有损格式从头顺序解码 |
| D1 | DSD 输出通道（以后，Full 需要；开始前另写详细任务卡） | DoP 封装与原生 DSD 格式（如 ALSA `DSD_U32_*`），设备不支持时拒绝，不转 PCM；WASAPI 只有 DoP |

每项基础格式的验收都包括：独立参考逐样本（或逐比特）一致、任意分块与 fuzz、模拟宿主场景、A 层回环逐字节比对，以及在 MCU 配置档下的资源预算与明确拒绝。
