# QyBit S1：曲目内定位（seek）

遵循根目录 AGENTS.md。来源：tasks/GUI.md“待用户决定”一节；用户 2026-10-15 决定在 GUI T3、T4 之后做。

状态：**已完成软件部分**（2026-10-15 用户确认 §7 三项：同意 §2 的冻结接口变更；样本级精确；FLAC 无 SEEKTABLE 时二分上限 1 秒、32 次跳转）。记录见 [docs/s1-seek.md](../docs/s1-seek.md)；实施中与本卡不同之处见 §8。真实设备上的定位未运行。

**目标**：在正在播放的曲目内跳到任意位置。定位后送到设备的第一帧就是目标帧（样本级精确），之后的数据与从头播放到该处逐字节相同；不改变样本，不做淡入淡出。桌面、模拟与嵌入式宿主共用核心层的实现。

## 0. 规范出处（实施前核对原文，记入 docs/specs.md）

| 内容 | 出处 |
| --- | --- |
| FLAC SEEKTABLE（定位点：样本号、相对第一帧的字节偏移、帧内样本数；占位点 0xFFFFFFFFFFFFFFFF） | RFC 9639 §8.5 |
| FLAC 帧头同步码、阻塞策略、帧号/样本号（类 UTF-8 编码）、CRC-8 | RFC 9639 §9.1 |
| FLAC 帧尾 CRC-16（同步命中后用整帧校验排除误同步） | RFC 9639 §9.3 |
| STREAMINFO 总样本数为 0 表示未知 | RFC 9639 §8.2 |
| WAV data 块：帧对齐的字节偏移 | RIFF WAVE（同 M0 T2 出处） |
| AIFF SSND：`offset` 字段与样本帧起点 | AIFF 1.3 / AIFF-C（同 F2 出处） |

## 1. 行为

- **定位目标**：曲目内的帧号 `frame`（从 0 起）。界面按时间换算：`frame = 秒 × 采样率`，取整到帧。
- **等于或超过曲目长度**：按播完该曲处理，进入下一首（与自动换曲相同的规则）；总帧数未知的 FLAC 读到 EOF 时同样处理。
- **实现方式**：定位是“从目标帧重新开始这首曲目”：停止设备、丢弃队列（与跳曲相同，沿用代次规则，旧代次的回报与 PCM 一律拒绝），重新打开音源并解析文件头，再按解码器给出的字节位置让宿主移动读取位置，解码器丢弃目标帧之前的样本。之后预填、启动设备。设备格式相同，按现有规则续用或重新打开。
- **暂停中定位**：保持暂停，恢复后从目标帧播放。
- **不可定位的音源**（宿主回报 `SeekFailed`，如管道）：按顺序读取并解码、丢弃到目标帧。结果同样精确，只是更慢；报告写明“该音源不支持定位，已按顺序解码到目标位置”。
- **报告**：“按操作定位 N 次（定位过的曲目没有完整播放）”，与切歌同样不计为完整播放；欠载、错误照常统计。

## 2. 接口变更（需用户同意）

冻结接口（M0 T4）：
- `Action` 新增 `Seek { generation, request, offset: u64 }`：宿主把音源读取位置移到距文件开头 `offset` 字节处，之后的 `Read` 从该处读取。
- `Event` 新增 `SeekDone { generation, request }` 与 `SeekFailed { generation, request }`。

`Decoder` trait 只新增带默认实现的方法，已有实现不需要改动：
- `fn seek(&mut self, frame: u64) -> Result<u64, SeekError>`：在文件头解析完成后调用，返回宿主应移动到的字节位置，解码器进入“定位中”状态。默认实现返回 `Unsupported`，此时核心按顺序解码并丢弃。
- `fn seek_request(&self) -> Option<u64>`：FLAC 无 SEEKTABLE 时可能需要再跳一次（§3），核心据此再发 `Seek`。默认实现返回 `None`。
- 丢弃目标帧之前的样本由解码器完成：`pcm()` 只给出目标帧及之后的样本。

播放引擎（M3 T1 起，未正式冻结，各宿主都在用）：
- `Engine::seek(frame)`；`HostAction::Seek { generation, request, offset }`；`HostEvent::SeekDone` / `SeekFailed`。
- `qy-player` 新增 `Command::Seek(frame)`；嵌入式串口命令 `seek <毫秒>`。

## 3. 各格式

- **WAV / AIFF**：字节位置 = data（SSND 数据起点）偏移 + `frame × block_align`，一次精确定位，不需要丢弃。W1 修正过的结构（如占位长度）按修正后的边界计算。
- **FLAC**：
  1. **有 SEEKTABLE**：取样本号 ≤ 目标的最后一个有效定位点（跳过占位点），跳到“第一帧起点 + 该点偏移”，从该帧解码，丢弃目标之前的样本。
  2. **没有 SEEKTABLE**（或表中没有可用的点）：按比例估计位置（第一帧起点 + 目标 / 总样本数 × 音频字节数），跳过去后寻找帧同步码。候选帧头须通过 CRC-8，并与 STREAMINFO 的采样率、声道、位深一致；整帧解码后再用 CRC-16 确认。读出该帧的起始样本号：超过目标时向前二分、远早于目标时向后二分，直到落在目标之前且距离不超过一个上限（建议 1 秒的样本），然后解码并丢弃。跳转次数有上限（建议 32 次），超过时退回从第一帧顺序解码，并在报告中写明。
  3. **总样本数未知**（STREAMINFO 为 0）：不能按比例估计，只用 SEEKTABLE；没有 SEEKTABLE 时从第一帧顺序解码到目标。
  4. 误同步（音频数据里出现同步码样式）由 CRC-8 和 CRC-16 两次校验排除；校验不过就继续向后找，不报错。

## 4. 界面

- **GUI**：工具栏下方加进度条（Win32 trackbar）。拖动时只预览时间，松开时定位；←/→ 键定位 ±5 秒。总时长未知（FLAC 总样本数为 0）时进度条不可用。
- **CLI**：不提供交互定位（M0 规则不变）。
- **嵌入式**：串口命令 `seek <毫秒>`，回应 `OK seek frame=<N>`；通知 `EVENT seek track=N frame=M`。

## 5. 验证

- **样本级精确**：每个格式各选若干夹具（WAV 8/16/24/32 位与 EXTENSIBLE、AIFF/AIFF-C、FLAC 定长与变长块、有与无 SEEKTABLE、总样本数为 0），定位目标取 0、1、帧边界前后各 1、中点、最后一帧、等于与超过长度，外加按种子随机的 64 个目标。定位后的输出须等于独立参考（ffmpeg / libFLAC 的 `.expect` / `.s32le`）从目标帧起的切片，且之后逐字节相同。
- **任意分块与短读**：定位后的读取同样用零长度读、短读、慢读注入（同 M0 T4 的模拟宿主规则）。
- **FLAC 误同步**：构造音频数据中含同步码样式的文件（或用 fuzz 生成的帧），确认不会被当成帧头。
- **不可定位的音源**：模拟宿主回报 `SeekFailed`，结果同样精确，报告写明。
- **代次**：定位过程中旧代次的读取回报与 PCM 被拒绝；连续快速定位（每 10 ms 一次、100 次）后只播放最后一次的目标。
- **暂停中定位**、定位到末尾进入下一首、定位后换格式。
- **fuzz**：在场景 fuzz 目标（M2 T5）中加入随机定位命令。
- **no_std**：核心与三个解码器照常 thumbv7em 编译；嵌入式宿主在虚拟时间仿真与 QEMU 中执行 `seek` 命令，按独立参考核对。
- **GUI**：qy-ui 测试定位命令与状态；CI 截图核对进度条。真机定位需要用户运行。

## 7. 用户决定（2026-10-15 确认，均按建议）

1. **同意 §2 的冻结接口变更**（`Action::Seek`、`Event::SeekDone` / `SeekFailed`）。建议同意：现在核心只能顺序读取，定位必须让宿主移动读取位置；`Decoder` 只加带默认实现的方法，已有解码器不受影响。
2. **样本级精确**（定位后第一帧就是目标帧）。建议采用：WAV/AIFF 不增加成本，FLAC 只是多解码、丢弃不超过一个定位间隔的样本。
3. **FLAC 无 SEEKTABLE 时的二分上限**（1 秒、32 次跳转）。建议按此实施，实测后可再调整。

## 8. 实施记录（与上文不同之处）

1. `seek_request` 为 `&mut self`：取出请求的同时清除它。
2. FLAC 跳转满 32 次（或离目标 1 秒以内、范围已窄）时，从已确认的、目标之前最近的帧顺序解码，而不是退回第一帧；结果相同、更快。实测单次定位最多 14 次跳转。
3. FLAC 固定块策略但最小块 ≠ 最大块的码流不能从帧号换算样本号（RFC 9639 §9.1.5），不试探，核心顺序解码。
4. 嵌入式串口回应为 `OK seek track=N frame=M`；刚开始播放、格式未定时回应 `OK seek track=N pending ms=M`，格式确定后定位。音源不可定位时通知 `EVENT seek-sequential track=N decoded-to-target`；正常定位不另发通知。
