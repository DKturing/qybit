# QyBit M3：QyBit Embedded Reference（草案，待审定）

遵循根目录 AGENTS.md。前置：M0、M1 完成；M2 T1–T4 完成（M2 T5 延后）。

**目标**：证明 QyBit Core 不只能在 MCU 上编译，还能在 MCU 上稳定播放音乐。具体分两步：

1. 先把播放调度下沉到 `no_std` 核心层，让桌面、模拟与 MCU 宿主共用同一套播放逻辑；
2. 再做与开发板无关的通用嵌入式宿主：从板载存储读取 WAV/FLAC，经 I²S DMA 连续播放；任一满足最低要求的板只需写一层很薄的板级适配，并在实物上留下可验证的证据。

**范围**：播放、暂停、停止、上一首/下一首、出错跳过；串口命令控制。不做屏幕、按键 UI、音量、seek、随机播放。

缺口分析与冻结接口的检查见 `docs/arch-core-mcu.md`。结论：冻结的 `Action`/`Event`/`Decoder` 不需要破坏性变更，本里程碑只新增接口。

## 硬件策略：通用，不指定开发板

Core 与嵌入式宿主都不绑定具体芯片、开发板或存储介质（2026-10-13 用户确认）。板子之间的差别只体现在两处：

- **板级适配层**：时钟、引脚、存储外设（SD 卡、eMMC、U 盘、闪存等）、I²S/SAI 外设与 DMA 的初始化，以及把它们接到通用宿主的 trait 上。每块板一个很薄的适配，不含播放逻辑；
- **配置档**：宿主声明的能力与资源（RAM、采样率、位深、FLAC 块大小、预填时长）。不同 RAM 的板用不同配置档常量，代码相同。

**最低要求**（满足即可，不限型号）：有 CAS 原子的 Cortex-M（M3/M4/M7/M33，`thumbv7m`/`thumbv7em`/`thumbv8m.main`），RAM 不少于所选配置档的预算加栈（Embedded Lite 约 90 KiB，Embedded Full 约 360 KiB），有 I²S/SAI 与 DMA，有能存放曲目的存储（任何介质，接法见 T2“存储”）。没有 CAS 原子的芯片（如 Cortex-M0+）需要静态队列的临界区版本，另列。

**实物验证**：实时可靠性只能在实物上证明（AGENTS §1 第三层）。T2/T3 中需要硬件的验收，由用户在手头任一满足最低要求的板上运行并提供记录，记录里写明芯片型号、RAM/Flash、时钟、DAC 型号与采集设备；结论只对记录中的那块板成立，不推广为“所有 MCU 已验证”。开发者环境没有实物硬件，没有记录的项明确标记为未运行。

## T1：核心下沉（不需要硬件）

状态：已完成，记录见 [docs/m3-t1-engine.md](../docs/m3-t1-engine.md)。MCU 演示只在 QEMU 中运行（指令集仿真）；实机属于 T2/T3。

- **no_std 播放调度**：新增 `no_std`、无 `alloc` 的播放调度状态机，可放在 `qy-core` 新模块或独立 crate，在 T1 内决定并记录理由。
  - 把 `qy-player` 中的以下规则迁入：预填、同格式续用、换格式先排空、EOF 与失败排空、背压、设备错误停止核心。
  - 新增：暂停/恢复、上一首/下一首、出错后按策略跳过坏文件。
  - 暂停期间的静音单独计数，不算欠载。
  - 调度层只通过“宿主操作/宿主回报”与外界交互，不访问文件、线程或时钟。
- **静态 SPSC 帧队列**：选用成熟库（候选 `bbqueue`、`heapless::spsc`），核对当前版本、`no_std` 支持、中断安全与 `unsafe` 边界，锁定版本并说明用途。
  - 与 `rtrb` 实现放在同一个“按完整帧入队/出队”的接口之后。
  - 继续满足 AGENTS 的规则：DMA/中断里只做有界搬运和计数。
- **资源预算按公式计算（整条播放链路，不只 FLAC）**：新增编译期可求值的函数，给定目标能力（最大采样率、声道、容器位宽、FLAC 最大块与位深、缓冲时长），计算各缓冲的大小与合计 RAM：
  - FLAC 输入窗口：取不压缩帧上界（帧头 + 各声道子帧头 + 块大小 × 位深，side 声道多 1 位 + CRC）；FLAC 工作区 `i64` 与 PCM `i32` 按块大小 × 声道计算；
  - WAV 输入窗口与 PCM 工作区：流式解码，大小固定，但也计入合计；
  - **设备帧队列**：采样率 × 缓冲时长 × 声道 × 容器字节数。这是 RAM 的最大头，WAV 与 FLAC 共用；现行 192 kHz / 2 ch / C32 / 500 ms 为 750 KiB；
  - pack 暂存区。
  - `Capacity::DESKTOP` / `Capacity::MCU` 与队列容量改为由该函数得出，不再手写常量。现有 `Capacity::MCU`（32 KiB 窗口）只覆盖 24 位双声道 4608 块，32 位需要约 36.6 KiB；配置档必须写明覆盖到的位深与采样率。
  - MCU 的缓冲时长不沿用桌面的 500 ms，由 T2 实测的存储最坏读取延迟加余量推出，再回写到配置档。
  - 测试：用独立公式核对计算结果；用最大块的不压缩夹具验证“窗口正好够时成功，少 1 字节时返回容量错误”。
  - 容量仍在启动时一次性固定，不依据文件头动态分配；单个文件的需求继续由文件头与逐帧检查在运行时判定。
- **去掉软件人为上限**（AGENTS §3）：`MAX_SAMPLE_RATE`（192 kHz）与 `MAX_CHANNELS`（2）等常量不再作为软件上限。采样率与声道只受格式规范、设备能力和宿主声明的资源限制；超出时在设备打开前报告具体原因（例如“本机配置的队列不足以承载 384 kHz / 8 声道 / C32”）。
  - 本卡只去掉上限并让资源预算随之计算；多声道的声道映射（WAV EXTENSIBLE 声道掩码、WASAPI 声道掩码、ALSA 声道映射）另见 tasks/FORMATS.md，在映射实现前，多于 2 声道的源明确报“声道映射尚未实现”，不得静默截取或重排声道（F1 已实现映射，见 [docs/f1-multichannel.md](../docs/f1-multichannel.md)；Embedded 配置档仍为双声道，多声道按能力不足拒绝）。
  - 回归：现有 192 kHz / 2 声道以内的全部测试不变；新增 384 kHz 及高采样率源在桌面配置档下播放，以及超出 MCU 配置档时被明确拒绝的模拟场景。
- **资源能力声明**：新增 `Capabilities`（最大采样率、声道、位深、FLAC 容量、输入窗口、队列字节数），由宿主启动时声明；其中各缓冲容量与 RAM 总量由上面的函数得出。
  - 核心据此在 `Configure` 之前拒绝超出能力的源，并给出明确错误。
  - 定义 Desktop / Embedded Lite / Embedded Full 三个配置档的常量，它们共用同一套代码。
- **codec 按需链接**：`qy-codec-auto` 增加 `wav`、`flac` feature，默认都开。只开 WAV 时不链接 FLAC，并检查链接产物确实不含 FLAC 符号。
- **宿主改造**：`qy-host-sim` 与 `qy-player` 改用新调度层，删除重复逻辑。

验收：
- **回归不变**：WAV 1000 个种子、FLAC 1200 个种子的模拟场景，M2 的整包/短写假设备测试，以及 A 层回环，结果逐字节不变。
- **新增模拟场景**（记录种子与时长）：暂停/恢复、下一首、上一首、出错跳过、能力超限拒绝。
- **no_std 编译**：调度层与静态队列能编译到 thumbv7em，并加入 CI。
- **MCU 资源演示**：一个 thumbv7em 的最小 no_std 演示程序（模拟“读卡”和“DMA”的纯软件宿主）链接成功，记录 `.bss` / `.data` / 栈的静态估计值。

## T2：通用嵌入式宿主（不绑定开发板）

前置：F1 多声道（[tasks/F1.md](F1.md)）。音频输出 trait 携带声道布局，嵌入式配置档仍声明双声道。

状态：不需要硬件的部分已完成，记录见 [docs/m3-t2-embedded-host.md](../docs/m3-t2-embedded-host.md)；实物验收未运行（需要用户在任一满足最低要求的板上运行并提供记录）。

**预填与队列的推导公式**（2026-10-13 定，实现在 `qy_host_embedded::budget`，`Player::new` 启动时核对，不满足即报错）。按启用的每种格式分别核对：
- 记号：`W` 最大输入单元字节数（FLAC 为最大块的不压缩帧上界；WAV 为板级选定的统计窗口），`F` 其中至少的帧数，`U` 读取任意连续 `W` 字节的最长耗时（含停顿与文件系统查找，按该板的存储介质实测），`D` 解码并 pack 一个单元的最长耗时（板级实测），`O` 打开一首曲目的最长耗时（目录查找与读取目录项，板级实测；2026-10-16 加入），`T` 最长 DMA 缓冲周期，`R` 源的最大字节率，`fs` 最高采样率，`P` 预填；
- 持续负载：`R · U / W + D · fs / F ≤ 10⁶`（µs）；
- 预填：`P ≥ O + U + D + T`（换曲时先打开下一首；E6 起含解码需要的读取跳转：`P ≥ O + J·(S + U) + U + k·S + D + T`，见 tasks/E6.md §2.7）；队列容量 = 预填量（配置档按公式分配）。

- 新建 `crates/qy-host-embedded`（`no_std`、无 alloc）：与板无关的嵌入式宿主，把引擎的宿主操作接到几个小 trait 上：
  - **存储**：读取曲目，读取非阻塞或分段完成。存储介质由板级决定，宿主只依赖 `Storage` 接口，不假定 SD 卡（2026-10-13 用户确认要通用）：
    - 块设备上的 FAT（SD 卡、eMMC、U 盘、放了 FAT 镜像的闪存）：通用实现 `FatStorage`（成熟库 `embedded-sdmmc`，版本锁定），板级只实现按块读取；
    - 不需要文件系统的介质（内存映射闪存、SPI NOR、EEPROM 等）：通用实现 `FlatStorage`，曲目表 + 标准接口 `embedded_storage::ReadStorage`（按偏移读取），板级给出曲目表；
    - 其他文件系统（如 littlefs）：板级用成熟库直接实现 `Storage`；
  - **音频输出**：启动/停止 I²S DMA、查询设备格式能力；DMA 半满/全满中断回调只做有界搬运与计数（静态队列 `FrameSource`）；
  - **控制**：串口命令（播放、暂停、停止、上一首、下一首、列出文件、状态）解析为引擎调用，与具体串口外设无关；
  - `embedded-hal` 1.0 没有 I²S/DMA 的通用接口，因此音频输出 trait 由本项目定义，保持最小。
- 所有大缓冲用 `ConstStaticCell` 与静态队列分配，链接 map 中核对它们位于 `.bss`，并记录 RAM 占用。
- **不需要硬件的验收**：
  - 模拟宿主与 QEMU 中用假的存储（内存中的 FAT 镜像，以及无文件系统的闪存）与假的 I²S DMA 运行同一个 `qy-host-embedded`，按独立参考核对设备字节；
  - 读取延迟与 DMA 周期可注入，覆盖慢读、读错误、拔卡；
  - 预填量与队列容量的推导公式写入本卡：由存储的最坏读取延迟推出，不足时明确报错，不靠“通常够用”。
- **板级适配示例**：给出至少一个板级适配作为示例并能编译（板子由实现时手头可编译的成熟 HAL 决定，不代表推荐型号）；适配层只做外设初始化与 trait 实现。
- 实物上的存储读取延迟、DMA 周期回写到对应配置档。

验收（需用户在任一满足最低要求的实物板上运行并提供记录）：
- 能从板载存储（该板实际使用的介质，记录中写明）播放 16/24 位 WAV 与支持范围内的 FLAC；
- 串口命令都有效；
- 欠载、读取错误、解码错误都有计数并通过串口报告。

## T3：实时可靠性与数字输出验证（需要硬件）

前置：R1 资源计划与可靠性验证（[tasks/R1.md](R1.md)）。T3 的实测数据（读取耗时 `U`、解码耗时 `D`、解码余量、中断占用、RAM 余量）是 P1 性能优化（[tasks/P1.md](P1.md)）的启动依据。

- **长时播放**：连续播放至少 2 小时，覆盖 WAV/FLAC 混排、换格式和反复暂停切歌。记录：
  - 欠载次数（必须为 0，或每次都报告）；
  - 解码余量，即每帧解码耗时与周期之比的最大值和分布；
  - 栈高水位与内存占用。
- **数字输出采集**：用逻辑分析仪或 I²S 采集设备录下 I²S 数据，按 M2 T4 的同步序列方法对齐，与独立公式算出的期望字节逐字节比对。
  - 覆盖该板支持的采样率、位深与声道组合；
  - 报告写明这是在 I²S 线上采集的，**不证明 DAC 模拟输出**。
- **故障注入**：拔卡、坏文件、截断文件、超出能力的文件。要求不 panic、状态可恢复、错误能报告。

验收：
- 以上记录写入 `docs/m3-*.md`；
- 实测得到的 FLAC 最大块、最低 RAM、可支持的采样率上限回写到配置档常量；
- 未运行的项明确列出。

## 不在本里程碑内

GUI、屏幕/按键 UI、macOS、蓝牙/USB 音频、音量与任何 DSP。
