# QyBit M3：QyBit Embedded Reference（草案，待审定）

遵循根目录 AGENTS.md。前置：M0、M1 完成；M2 T1–T4 完成（M2 T5 延后）。

**目标**：证明 QyBit Core 不只能在 MCU 上编译，还能在 MCU 上稳定播放音乐。具体分两步：

1. 先把播放调度下沉到 `no_std` 核心层，让桌面、模拟与 MCU 宿主共用同一套播放逻辑；
2. 再在一块具体的参考开发板上，从 SD 卡读取 WAV/FLAC，经 I²S DMA 连续播放，并留下可验证的证据。

**范围**：播放、暂停、停止、上一首/下一首、出错跳过；串口命令控制。不做屏幕、按键 UI、音量、seek、随机播放。

缺口分析与冻结接口的检查见 `docs/arch-core-mcu.md`。结论：冻结的 `Action`/`Event`/`Decoder` 不需要破坏性变更，本里程碑只新增接口。

## 参考硬件（待用户确定）

T2 开始前由用户确定以下几项，并写入本卡：

- **开发板**：建议候选为 STM32H7 系列（RAM 充裕，有 SAI/I²S 与 SDMMC），或 RP2040/RP2350（PIO 实现 I²S、SPI 读 SD 卡）。
- **外设**：SD 卡座、I²S DAC 模块。
- **采集设备**：逻辑分析仪或 I²S 采集设备。
- **记录内容**：芯片型号、RAM/Flash、时钟、DAC 型号，以及采集设备的型号与采样能力。

开发者环境没有实物硬件。凡是需要硬件的验收，都要由用户在本地运行并提供记录；没有记录的明确标记为未运行。

## T1：核心下沉（不需要硬件）

- **no_std 播放调度**：新增 `no_std`、无 `alloc` 的播放调度状态机，可放在 `qy-core` 新模块或独立 crate，在 T1 内决定并记录理由。
  - 把 `qy-player` 中的以下规则迁入：预填、同格式续用、换格式先排空、EOF 与失败排空、背压、设备错误停止核心。
  - 新增：暂停/恢复、上一首/下一首、出错后按策略跳过坏文件。
  - 暂停期间的静音单独计数，不算欠载。
  - 调度层只通过“宿主操作/宿主回报”与外界交互，不访问文件、线程或时钟。
- **静态 SPSC 帧队列**：选用成熟库（候选 `bbqueue`、`heapless::spsc`），核对当前版本、`no_std` 支持、中断安全与 `unsafe` 边界，锁定版本并说明用途。
  - 与 `rtrb` 实现放在同一个“按完整帧入队/出队”的接口之后。
  - 继续满足 AGENTS 的规则：DMA/中断里只做有界搬运和计数。
- **资源预算按公式计算（整条播放链路，不只 FLAC）**：新增编译期可求值的函数，给定目标能力（最大采样率、声道、容器位宽、FLAC 最大块与位深、缓冲时长），计算各缓冲的大小与合计 RAM：
  - FLAC 输入窗口：取不压缩帧上界（帧头 + 各声道子帧头 + 块大小 × 位深，side 声道多 1 位 + CRC）；FLAC 工作区 `i64` 与 PCM `i32` 按块大小 × 声道计算；
  - WAV 输入窗口与 PCM 工作区：流式解码，大小固定，但也计入合计；
  - **设备帧队列**：采样率 × 缓冲时长 × 声道 × 容器字节数。这是 RAM 的最大头，WAV 与 FLAC 共用；现行 192 kHz / 2 ch / C32 / 500 ms 为 750 KiB；
  - pack 暂存区。
  - `Capacity::DESKTOP` / `Capacity::MCU` 与队列容量改为由该函数得出，不再手写常量。现有 `Capacity::MCU`（32 KiB 窗口）只覆盖 24 位双声道 4608 块，32 位需要约 36.6 KiB；配置档必须写明覆盖到的位深与采样率。
  - MCU 的缓冲时长不沿用桌面的 500 ms，由 T2 实测的 SD 卡最坏读取延迟加余量推出，再回写到配置档。
  - 测试：用独立公式核对计算结果；用最大块的不压缩夹具验证“窗口正好够时成功，少 1 字节时返回容量错误”。
  - 容量仍在启动时一次性固定，不依据文件头动态分配；单个文件的需求继续由文件头与逐帧检查在运行时判定。
- **去掉软件人为上限**（AGENTS §3）：`MAX_SAMPLE_RATE`（192 kHz）与 `MAX_CHANNELS`（2）等常量不再作为软件上限。采样率与声道只受格式规范、设备能力和宿主声明的资源限制；超出时在设备打开前报告具体原因（例如“本机配置的队列不足以承载 384 kHz / 8 声道 / C32”）。
  - 本卡只去掉上限并让资源预算随之计算；多声道的声道映射（WAV EXTENSIBLE 声道掩码、WASAPI 声道掩码、ALSA 声道映射）另见 tasks/FORMATS.md，在映射实现前，多于 2 声道的源明确报“声道映射尚未实现”，不得静默截取或重排声道。
  - 回归：现有 192 kHz / 2 声道以内的全部测试不变；新增 384 kHz 及高采样率源在桌面配置档下播放，以及超出 MCU 配置档时被明确拒绝的模拟场景。
- **资源能力声明**：新增 `Capabilities`（最大采样率、声道、位深、FLAC 容量、输入窗口、队列字节数），由宿主启动时声明；其中各缓冲容量与 RAM 总量由上面的函数得出。
  - 核心据此在 `Configure` 之前拒绝超出能力的源，并给出明确错误。
  - 定义 Desktop / Embedded Lite / Embedded Full 三个配置档的常量，它们共用同一套代码。
- **codec 按需链接**：`qy-codec-auto` 增加 `wav`、`flac` feature，默认都开。只开 WAV 时不链接 FLAC，并检查链接产物确实不含 FLAC 符号。
- **宿主改造**：`qy-host-sim` 与 `qy-player` 改用新调度层，删除重复逻辑。

验收：
- **回归不变**：WAV 1000 个种子、FLAC 1200 个种子的模拟场景，M2 的整包/短写假设备测试，以及 A 层回环，结果逐字节不变。
- **新增模拟场景**（记录种子与时长）：暂停/恢复、下一首、上一首、出错跳过、能力超限拒绝。
- **no_std 编译**：调度层与静态队列能编译到 thumbv7em，并加入 CI。
- **MCU 资源演示**：一个 thumbv7em 的最小 no_std 演示程序（模拟“读卡”和“DMA”的纯软件宿主）链接成功，记录 `.bss` / `.data` / 栈的静态估计值。

## T2：参考板上板（需要硬件）

- 新建 `apps/qybit-embedded`，或 `crates/qy-host-<板>` 加应用，在 T2 内决定并记录理由。内容包括：
  - 时钟与外设初始化；
  - SD 卡读取（成熟的 FAT 库，选型并锁定版本）；
  - I²S/SAI DMA 输出，DMA 半满/全满中断只做有界搬运；
  - 串口命令（播放、暂停、停止、上一首、下一首、列出文件、状态）。
- 所有大缓冲用 `ConstStaticCell` 静态分配，链接 map 中核对它们位于 `.bss`，并记录 RAM 占用。
- 读卡延迟、DMA 周期与队列容量写入本卡：
  - 预填量与队列容量由测得的最坏读卡延迟推出；
  - 不足时明确报错，不靠“通常够用”。

验收（需用户在实物上运行并提供记录）：
- 能从 SD 卡播放 16/24 位 WAV 与支持范围内的 FLAC；
- 串口命令都有效；
- 欠载、读取错误、解码错误都有计数并通过串口报告。

## T3：实时可靠性与数字输出验证（需要硬件）

- **长时播放**：连续播放至少 2 小时，覆盖 WAV/FLAC 混排、换格式和反复暂停切歌。记录：
  - 欠载次数（必须为 0，或每次都报告）；
  - 解码余量，即每帧解码耗时与周期之比的最大值和分布；
  - 栈高水位与内存占用。
- **数字输出采集**：用逻辑分析仪或 I²S 采集设备录下 I²S 数据，按 M2 T4 的同步序列方法对齐，与独立公式算出的期望字节逐字节比对。
  - 覆盖本板支持的采样率、位深与声道组合；
  - 报告写明这是在 I²S 线上采集的，**不证明 DAC 模拟输出**。
- **故障注入**：拔卡、坏文件、截断文件、超出能力的文件。要求不 panic、状态可恢复、错误能报告。

验收：
- 以上记录写入 `docs/m3-*.md`；
- 实测得到的 FLAC 最大块、最低 RAM、可支持的采样率上限回写到配置档常量；
- 未运行的项明确列出。

## 不在本里程碑内

GUI、屏幕/按键 UI、macOS、蓝牙/USB 音频、音量与任何 DSP。
