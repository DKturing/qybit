# QyBit O1：单声道复制到左右两路（明确开启）与端点扬声器提示

遵循根目录 AGENTS.md。来源：Windows 真机测试中，端点拒绝单声道 `[FC]`、只能播放立体声，单声道文件无法出声。用户 2026-10-14 同意按以下建议实施；顺序在 F2 之后（可按用户要求提前）。

状态：已审定，待实施。

## 1. 单声道复制到左右两路（非严格选项，默认关闭）

- **开启方式**：
  - CLI 用 `--mono-to-stereo`；
  - 嵌入式由配置或串口命令开启；
  - 默认关闭，严格路径不受影响。
- **做什么**：源为单声道 `[FC]` 时，设备格式请求立体声 `[FL FR]`，每个样本原样复制到左右两路。
  - 只复制，不混音、不改增益、不改样本值；采样率与位深不变。
  - 开启后对所有单声道源生效，行为确定，不依赖设备是否先拒绝单声道。
- **在哪里做**：
  - 引擎配置新增声道策略（如 `ChannelPolicy::DuplicateMono`），由 Core 决定设备格式，桌面、模拟、嵌入式共用；
  - 表示转换仍只在 pack：复制属于改变表示的操作，用 `Pcm<Altered>` 的受控入口，不经过 `Pcm<Exact>`。
- **报告**：
  - 实时输出、播放报告与 `status` 写明“声道已改变：单声道 [FC] 复制为 [FL FR]（明确开启；样本值未改变）”；
  - 结论不再写“软件路径无损”，改写“样本值未改变，声道布局已按选项改变”。
- **不做**：多声道下混、上混、任意声道重映射；以后若有需求，另立任务卡。
- **验收**：
  - 单声道夹具在开启时设备字节等于独立参考，即每帧两份相同样本；关闭时行为与现在逐字节相同；
  - 报告字段与结论文字正确；
  - 模拟种子 × 两种设备模型；嵌入式仿真与 QEMU 演示照常通过；
  - Windows 真机由用户试听，标为人工试听。

## 2. 端点扬声器提示（只警告，不拒绝）

- **WASAPI**：
  - 读取端点属性 `PKEY_AudioEndpoint_PhysicalSpeakers`（物理扬声器掩码）。实现前核对 Microsoft Learn 原文，确认属性定义与取值；
  - 源布局中有端点不具备的扬声器位置时，在打开设备后给出警告，例如“端点报告的物理扬声器为 [FL FR]，源的 [FC] 不在其中，可能听不到”。
- **驱动未提供或读取失败**：报告“端点未报告物理扬声器配置”，不警告、不拒绝。
- **性质**：
  - 这是驱动填写的信息，可能缺失或不准，因此只作提示；
  - 协商与播放照常进行，严格规则不变。
- **ALSA**：没有对应的物理扬声器属性。报告写“不可查询”，不推测。
- **验收**：
  - 假后端覆盖三种情况：掩码包含源布局、掩码缺少源位置、属性缺失；
  - Windows 真机由用户运行，记录报告中的掩码与警告。
